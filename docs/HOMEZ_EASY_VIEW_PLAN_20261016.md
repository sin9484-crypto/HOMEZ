## 2. 문제점·위험

1. **console.js 비대화**: 새 화면을 계속 같은 파일에 넣으면 25,000줄이 더 늘어 유지·검증이 어렵다.
2. **데이터 없는 약속 금지**: 시안의 예시 값(횟수, HZ-1042 같은 예시 주문)은 실제 화면에 나오면 안 된다. 없는 값은 비워 두거나 숨긴다.
3. **승인 우회 위험**: "허용" 버튼이 기존 게이트(모드·비상정지·재인증·값 일치)를 건너뛰면 안 된다. 쉬운 보기는 **보기와 순서만 단순화**하고 서버 규칙은 그대로 둔다.
4. **권한·가이드 회귀**: 메뉴 숨김·가이드가 `.nav-item`에 묶여 있어, 새 메뉴가 그것을 따르지 않으면 권한 없는 메뉴가 보인다.
5. **기존 사용자 혼란**: 한 번에 기본 화면을 바꾸면 되돌릴 방법이 필요하다.
6. **외부 호출**: 새 화면을 열기만 해도 쿠팡·온채널 호출이 나가면 안 된다(지금 송장 패널처럼 **버튼을 눌러야만** 조회).

## 3. 구현 계획 — 단계

원칙: 서버 쓰기 규칙·Model·Migration은 건드리지 않는다. 쉬운 보기는 **사용자별 켜고 끄는 설정**으로 시작한다. 각 단계 끝에 실제 브라우저로 확인하고 사용자 확인 뒤 다음 단계로 간다.

| 단계 | 내용 | 서버 변경 | 크기 |
|---|---|---|---|
| **E0 기반** | ① 새 파일 `app/web/easy/easy_view.js`·`easy_view.css`(초록 시안 색은 `body.easy-view` 아래로 한정해 기존 teal 화면은 그대로) ② `console.js` 끝에 작은 연결부(`window.HomezEasyBridge`: apiFetch·toast·askConfirm·promptRecentAuthToken·navigateTo·escapeHtml·i18n) ③ 사이드바 4개+승인 센터+더보기(기존 `SECTION_NAV`와 `.nav-item` 숨김 상태를 그대로 따름) ④ 더보기에 "전체 메뉴(고급 보기)"와 "쉬운 보기 켜기/끄기"(`user_settings.ui_preferences`에 저장 — 이미 허용된 키) | 없음 | S |
| **E1 오늘 할 일** | 기존 `work-queue`를 시안 1번 모양으로: 탭, 요약 띠, 표(사진·상태 칩·다음 작업), 오른쪽 상세 패널. 데이터는 기존 `wqBuildItems` 재사용 + "출고일 확인" 카드(저장된 위저드 값 `outboundShippingTimeDay`가 없거나 1인 등록 상품만, 쿠팡을 읽지 않음) | 없음 | M |

### 새 집계 API(2개, 모두 읽기 전용)
- 위치: 새 도메인 폴더 `app/domains/easy_view/`(router·service·schema). 회사 범위 필터, `AdminGuard` 이상, DB 쓰기 없음, **외부 호출 없음**.
- 이유: 진행 막대·승인 모음을 화면에서 5~6개 API를 따로 불러 조립하면 느리고 테스트가 어렵다. 한 곳에서 계산하고 서버 테스트로 고정한다.

**신규 파일**

- `tests/test_easy_view_ui.py`, `tests/test_easy_view_orders.py`, `tests/test_easy_view_approvals.py`
- `docs/HOMEZ_EASY_VIEW_PLAN_20261016.md`(이 문서)

**수정 파일**
- `app/web/console.html`(새 JS·CSS 연결, 사이드바 자리), `app/web/console.js`(연결부·뷰 등록만), `app/web/console.css`(쉬운 보기 토글 표시 최소)
- `app/web/i18n/ko-KR.js`, `en-US.js`(쉬운 보기 문구 `easy.*` 키 추가만)
- `app/main.py` 또는 라우터 등록 파일(새 라우터 연결 1줄)

- 기존 UI 테스트 중 메뉴 개수·순서를 고정한 것(`test_section_nav_ui.py` 등)은 **의미를 유지한 채** 새 구조에 맞게만 조정(약화 금지)

**건드리지 않는 것**: Model·Migration, 기존 서버의 승인·전송 규칙, 쿠팡·온채널 어댑터, `.env`·자격증명, 기존 미추적 WIP 파일.

## 5. 검증 계획

- **서버**: 집계 API는 격리 SQLite로 회사 간 격리, 단계 계산(성공/실패/결과불명), 빈 데이터, **쓰기·외부 호출이 없음**을 테스트. 규칙을 일부러 깨뜨리는 변이 검사 포함.
- **UI 정적·Node**: 화면 열기만으로 쿠팡·온채널 호출이 나가지 않음, 버튼 순서(확인→재인증→전송), 서버 문구 이스케이프, ko/en 키 짝, 권한 숨김 따라감, 쉬운 보기 끄면 기존 화면 그대로.
- **실제 브라우저**(로컬 앱, 외부 호출 0 확인 — 가드 로그 대조): 시안과 나란히 비교한 스크린샷, 좁은 폭, 키보드 이동.
- **회귀**: 영향 범위 전체(약 1,200건)를 단계마다 실행.
- **되돌리기**: 쉬운 보기 끄기(설정) → 즉시 기존 화면. 코드는 단계별 커밋이라 `git revert`로 한 단계씩 취소 가능.

## 7. 진행 방식

1. 사용자가 이 계획·Whitelist·D1~D6을 확인한다.
2. E0부터 한 단계씩 구현 → 검증 → 보고 → 사용자 확인 → 커밋 → 다음 단계(커밋·푸시·앱 재시작·쿠팡/온채널 호출은 각각 사용자 승인 후).
3. 각 단계 완료 보고에 변경 파일, 테스트 결과, 외부 호출 0건 근거, 남은 위험을 적는다.
