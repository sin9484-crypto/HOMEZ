# 사용자 구매 자동화 안전 가이드(Gate RP-2, 2026-08-22)

HOMEZ의 "구매 실행 연결" 화면(콘솔 좌측 메뉴)을 운영하는 담당자를
위한 안내다. 기술 문서가 아니라 **실제로 무엇을 설정하고, 무엇을
조심해야 하는지**를 다룬다.

## 1. 지금 이 기능이 할 수 있는 것 / 할 수 없는 것

**할 수 있는 것**
- 테스트 전용(FAKE) Provider로 상품 검색→동일상품 비교→매입비 미리
  보기→정책 검사→예산 예약→견적→구매까지 전 과정을 실제로 실행하고
  검증할 수 있다(시연·회귀 검증 목적).
- 자동구매 정책(허용 구매처, 최소 이익·마진, 가격 상승 허용률, 상품별
  최대 수량, 동시 구매 한도, 자동 실행 여부 등)을 회사별로 설정할
  수 있다.

**할 수 없는 것(중요)**
- **실제 네이버·11번가·G마켓·옥션 등에서 실제 구매가 실행되지
  않는다.** 이 플랫폼들과의 서면 계약·공식 API 연동이 아직 없기
  때문이다 — "구매처 연결 상태" 화면에서 FAKE 이외 모든 항목이
  "계약 필요"로 표시되는 이유다.
- 소비자 계정(아이디·비밀번호)을 저장하거나 자동 로그인하지
  않는다 — 이 기능은 설계에 아예 존재하지 않는다.

## 2. 정책 설정 — 각 항목이 실제로 무엇을 막는지

| 항목 | 이 값을 낮추면(완화하면) 벌어지는 일 |
|---|---|
| 허용 구매처 | 비워두면(기본값) 전부 차단 — 반드시 최소 1개 이상 명시적으로 체크해야 그 Provider로 구매를 진행할 수 있다. |
| 상품 매칭 신뢰도 하한 | 낮추면 실제로는 다른 상품인데도 "동일상품"으로 판정될 위험이 커진다. 0.90 미만으로는 내릴 수 없다(시스템이 강제). |
| 최소 순이익·최소 마진율 | 낮추면 손해에 가까운 구매도 자동 통과된다. |
| 최대 매입가격·1회 최대 구매금액 | 제한을 없애면(빈칸) 고가 상품도 자동 승인 대상이 된다. |
| 가격 상승 허용률 | 높이면 최초 제안 시점보다 훨씬 비싸진 상품도 그대로 구매가 진행된다. |
| 상품별 최대 구매수량 | 없애면 한 번에 대량 구매가 자동 승인될 수 있다. |
| 반품 가능 필수 여부 | 끄면 반품 불가 상품도 자동구매 대상이 된다. |
| 판매자 신뢰점수 하한 | 낮추면 신뢰도 낮은 판매자에게서도 자동구매가 진행된다. |
| 일별·월별 구매한도, 동시 구매 건수 | 없애면 예산 소진 속도를 정책이 더 이상 제어하지 못한다. |
| **자동 실행 여부** | 끄면 정책 범위 안이라도 매 건 사람이 직접 다음 단계를 눌러야 진행된다(전사 차원의 안전판). |
| **승인 필요 금액 기준** | 이 금액을 넘는 건은 자동 실행이 켜져 있어도 사람 확인 단계로 낮춰진다. |
| **결과 불명확(UNCERTAIN) 처리정책** | "사람이 확인할 때까지 보류"(기본값, 권장)와 "지정 시간 후 예산만 자동 반환"(구매 자체는 절대 재시도하지 않음) 중 선택. |

정책 수정 화면은 위험한 방향으로 값이 바뀌면(완화) 자동으로
경고 문구를 보여준다 — 경고가 뜬다고 저장이 막히지는 않으니,
실제로 의도한 변경인지 반드시 다시 한 번 확인한 뒤 저장하라.

## 3. "결과 불명확(UNCERTAIN)"이 뜨면 무엇을 해야 하는가

이 상태는 "구매처 서버가 응답하지 않아 실제로 결제됐는지 실패했는지
시스템이 확신할 수 없다"는 뜻이다. **시스템은 이 상태에서 어떤 경우에도
자동으로 다시 결제를 시도하지 않는다**(이중 결제 방지가 최우선
원칙이기 때문). 담당자가 할 일:

1. 실제 구매처(쇼핑몰) 사이트의 주문내역에서 그 주문이 실제로
   존재하는지 직접 확인한다.
2. 존재하면 — 시스템의 예산 예약 상태를 그대로 두고, 정산·재고 처리를
   수동으로 진행한다.
3. 존재하지 않으면 — 안전하게 예산을 반환할 수 있다(현재 UI는 이
   반환을 자동으로 하지 않는다 — 정책에서 "지정 시간 후 자동 반환"을
   켜지 않은 이상 담당자가 직접 처리 경로를 통해 정리해야 한다).

## 4. Emergency Stop이 켜져 있을 때

화면 상단에 빨간 배너로 표시된다. 이 상태에서는 정책 검사 자체가
막힌다("EMERGENCY_STOP_ACTIVE") — 이미 견적까지 나온 주문도 구매
실행 단계에서 다시 차단된다. 다른 화면(안전 설정)에서 EStop을 해제한
뒤에만 구매 실행이 재개된다.

## 5. 알림 패널을 읽는 법

"구매 실행 연결" 화면 상단 "알림"은 별도로 저장되는 알림이 아니라,
현재 Provider 연결 상태·주문 목록에서 매번 새로 계산해 보여주는
목록이다. 정책 위반·예산 부족·가격 변동·재고 품절·결과 불명확·
승인 필요·구매 성공/실패·배송 상태 변경·Provider 장애·재인증 필요
항목이 여기 모인다. 각 줄을 클릭하면 해당 주문 상세 화면으로 이동한다.

## 6. 자주 나오는 화면 문구

- **"실구매 불가·시연용"** — 지금 고른 구매처가 FAKE(테스트 전용)
  라는 뜻. 실제 돈이 나가지 않는다.
- **"아직 서면 계약·공식 API 연동이 완료되지 않았습니다"** — 이
  구매처는 계약이 없어 최종 발주 단계에서 항상 막힌다는 뜻. 정책
  검사·견적까지는 볼 수 있어도 실제 구매는 진행되지 않는다.
- **"정책 검사 이후 자동구매 정책이 변경되어 이전 판정을 더 진행할
  수 없습니다"** — 다른 관리자가 그 사이 정책을 바꿨다는 뜻. 정책
  검사를 다시 실행하면 된다.

## 7. 이번 라운드에 아직 없는 것(정직하게 공개)

- 11번가/G마켓/옥션 등 채널별 전용 연동(전부 공통 인터페이스와
  미계약 상태로만 존재).
- Webhook을 받아 주문 상태를 자동 갱신하는 기능(서명 검증 계약만
  구현, 실제 처리 로직 없음).
- 운영자용 알림의 이메일·문자 발송(현재는 콘솔 화면 안에서만 표시).
