# HOMEZ 연동 독립 회계 프로그램 개발 시나리오 및 종합 보고서

작성 기준일: 2026-08-17  
상태: V10 완료 후 착수할 제품 기준안(미구현)  
적용 대상: 대한민국 온라인 판매업의 개인사업자·법인·간편장부 대상자

## 1. 목적

회계 기능을 HOMEZ 내부에 종속시키지 않고 별도의 회계 프로그램으로
개발한다. HOMEZ와 회계 프로그램은 표준 연동 계약으로 병렬 연결하며,
사용자가 다른 회계·세무 프로그램도 선택할 수 있게 한다.

이 문서는 다음 질문에 답한다.

- 무엇을 먼저 만들어야 하는가?
- HOMEZ와 회계 프로그램은 어떤 데이터를 주고받는가?
- 간편장부·복식부기·법인은 어떻게 나누는가?
- 직접 신고와 세무대리 서비스의 경계는 어디인가?
- 자체 회계 프로그램 외 다른 프로그램을 어떻게 연결하는가?
- 오류·법령 변경·중복 전송·데이터 불일치를 어떻게 처리하는가?

## 2. 고정 제품 원칙

1. 회계 프로그램은 HOMEZ와 별도의 실행 파일·서비스·DB·버전을 가진다.
2. HOMEZ 판매 업무는 회계 프로그램 장애 때문에 중단되지 않는다.
3. HOMEZ는 검증된 원천자료를 제공하고 회계 프로그램은 장부·신고자료를
   생성한다.
4. 전송은 비동기 Queue로 처리하며 중복 전송을 멱등성 키로 차단한다.
5. 회사별 데이터는 `company_id`로 완전히 격리한다.
6. 비밀번호·인증서·Credential 원문은 업무 DB에 저장하지 않는다.
7. 세금 계산 규칙은 생성형 AI의 추측으로 결정하지 않는다.
8. 법령·국세청 서식·공식 안내의 기준일과 버전을 함께 기록한다.
9. 신고 전 사용자 또는 세무전문가의 최종 확인을 요구한다.
10. 다른 회계 프로그램도 Adapter로 연결할 수 있게 한다.

## 3. 쉬운 구조 설명

```text
HOMEZ
  주문·환불·정산·원가·수수료
            |
            | 표준 회계 이벤트
            v
연동 허브(Queue·검증·중복 방지·대사)
      |                 |
      v                 v
HOMEZ 회계 프로그램   외부 회계/세무 프로그램
      |
      v
장부·세금 계산·신고자료·세무대리 협업
```

HOMEZ가 회계 장부를 직접 수정하지 않고 `판매가 발생했다`, `환불됐다`,
`채널 수수료가 확정됐다`와 같은 원천 이벤트를 보낸다. 회계 프로그램은
그 이벤트를 검증한 뒤 분개와 장부로 변환한다.

## 4. 개발 시나리오 A — 내보내기 우선형

### 내용

- HOMEZ 자료를 CSV/XLSX로 내보낸다.
- 사용자가 세무사 또는 기존 회계 프로그램에 직접 전달한다.
- 연도·월·채널·거래유형별 파일을 제공한다.
- 누락·중복·미확정 정산을 경고한다.

### 장점

- 가장 빨리 사용할 수 있다.
- 세무신고 책임 경계가 명확하다.
- 법령·신고 API가 바뀌어도 영향이 작다.

### 한계

- 수동 업로드가 필요하다.
- 실시간 대사가 어렵다.
- 자체 장부와 신고 자동화 목표에는 부족하다.

### 적합 시점

V10 완료 직후 첫 번째 안전 버전으로 적합하다.

## 5. 개발 시나리오 B — 독립 장부형

### 내용

- 별도 회계 프로그램이 HOMEZ 이벤트를 받아 장부를 작성한다.
- 개인사업자 간편장부와 복식부기 장부를 구분한다.
- 법인에는 계정과목·분개·재무제표 작성 기반을 제공한다.
- 증빙과 거래를 연결하고 미확정 항목을 보류함으로 분리한다.

### 장점

- HOMEZ와 독립적으로 장부를 관리할 수 있다.
- 다른 판매 시스템의 자료도 받을 수 있다.
- 세무사에게 검토 가능한 표준 자료를 제공할 수 있다.

### 한계

- 계정과목·결산·수정분개 설계가 필요하다.
- 잘못된 자동 분개가 누적되지 않도록 검토 흐름이 필요하다.

### 적합 시점

내보내기형이 안정된 다음 두 번째 단계로 적합하다.

## 6. 개발 시나리오 C — 신고·세무대리 협업형

### 내용

- 부가가치세·종합소득세·법인세 신고자료를 생성한다.
- 사용자와 세무대리인이 같은 장부의 검토 상태를 공유한다.
- 제출 전 오류·누락·증빙 부족·미확정 거래를 차단한다.
- 공식 전자신고 연결은 지원 자격·인증·등록 요건을 확인한 뒤 별도
  Live Gate로 구현한다.

### 장점

- 사용자가 HOMEZ 자료를 다시 입력할 필요가 줄어든다.
- 세무대리 업무와 수정 이력이 투명해진다.

### 한계

- 법률·서식·기한 변경 대응이 필수다.
- 전자신고와 전자세금계산서 발급 대행은 등록·인증 요건 검토가 필요하다.
- 잘못된 신고의 영향이 크므로 전문가 검증 없이는 출시할 수 없다.

### 적합 시점

장부형의 실제 운영 데이터와 전문가 검증이 확보된 뒤 진행한다.

## 7. 개발 시나리오 D — 회계 연동 허브형

### 내용

- HOMEZ 회계 프로그램뿐 아니라 다른 회계·세무 제품도 연결한다.
- 각 제품별 Adapter가 HOMEZ 표준 이벤트를 해당 제품 규격으로 변환한다.
- 연결 상태·전송 이력·실패·재시도·대사 결과를 한 화면에서 관리한다.

### 장점

- 사용자가 기존 회계 프로그램을 유지할 수 있다.
- 특정 업체의 장애·가격·정책에 종속되지 않는다.
- 향후 은행·카드·전자세금계산서 Provider도 확장할 수 있다.

### 한계

- Provider별 인증과 데이터 규격 관리 비용이 든다.
- 동일 거래가 여러 프로그램에 중복 반영되지 않도록 통제가 필요하다.

### 적합 시점

자체 장부형의 표준 이벤트 계약이 안정된 뒤 확장한다.

## 8. 권장 혼합 시나리오

네 시나리오 중 하나만 선택하지 않고 위험이 낮은 순서로 쌓는다.

```text
1단계 내보내기
→ 2단계 독립 장부
→ 3단계 외부 회계 Adapter
→ 4단계 신고자료
→ 5단계 세무대리 협업
→ 6단계 승인된 전자신고 연동
```

이 순서는 초기부터 전자신고를 시도해 법적·기술적 위험을 크게 만드는
것보다 효율적이다. 각 단계가 독립적으로 사용자 가치를 제공한다.

## 9. 표준 회계 이벤트

HOMEZ에서 다음 이벤트를 제공한다.

- `SALE_RECOGNIZED`: 매출 인식
- `SALE_CANCELLED`: 매출 취소
- `REFUND_CONFIRMED`: 환불 확정
- `MARKETPLACE_FEE_CONFIRMED`: 판매채널 수수료 확정
- `SETTLEMENT_EXPECTED`: 정산 예정
- `SETTLEMENT_RECEIVED`: 정산 입금
- `COST_CONFIRMED`: 상품 원가 확정
- `SHIPPING_COST_CONFIRMED`: 배송비 확정
- `AD_COST_CONFIRMED`: 광고비 확정
- `PURCHASE_CONFIRMED`: 매입 확정
- `INVENTORY_ADJUSTED`: 재고 조정
- `EVIDENCE_ATTACHED`: 증빙 연결

각 이벤트에는 다음 공통 필드가 필요하다.

- 이벤트 ID와 스키마 버전
- 회사 ID
- 거래 발생일·회계 기준일·전송일
- 원본 도메인과 원본 ID
- 공급가액·세액·총액·통화
- 채널·거래처·증빙 reference
- 취소·정정 대상 이벤트 ID
- idempotency key
- 생성 주체·감사 추적 정보

## 10. 핵심 데이터 경계

### HOMEZ 소유

- 주문과 주문항목
- 상품·원가·재고
- 판매채널 수수료와 정산 원본
- 배송·반품·환불
- 광고·채널 비용 원천자료

### 회계 프로그램 소유

- 계정과목
- 분개와 전표
- 장부
- 결산 조정
- 세금 계산 snapshot
- 신고서 작성 상태
- 세무대리 검토·승인

### 공유하지만 복사본으로 관리

- 사업자 기본정보
- 거래처
- 증빙 metadata
- 신고 기간
- 제출 결과 reference

한 프로그램이 다른 프로그램의 DB를 직접 수정하지 않는다.

## 11. 사용자 유형별 흐름

### 간편장부 대상 개인사업자

```text
HOMEZ 자료 수신
→ 수입·비용 자동 분류 제안
→ 증빙 확인
→ 간편장부
→ 월·분기 점검
→ 종합소득세·부가세 자료
```

지원하지 못하는 신고·서식은 숨기지 않고 Excel 내보내기와 알림을
제공한다.

### 복식부기 개인사업자

```text
원천 이벤트
→ 복식 분개
→ 보조부
→ 결산 조정
→ 재무제표·신고자료
```

### 법인

```text
원천 이벤트
→ 복식 분개
→ 증빙·승인
→ 월마감
→ 결산
→ 재무제표·법인세 신고자료
```

법인 신고에는 다수 서식과 부속자료가 필요할 수 있으므로 초기에는
완전 자동 제출을 약속하지 않고 작성·검증·내보내기 범위를 명시한다.

## 12. 세무대리 협업

역할을 분리한다.

- 사업자: 거래 확인, 증빙 제공, 최종 승인
- 직원: 자료 정리, 미확정 항목 처리
- 세무대리인: 분개·결산·신고자료 검토
- 시스템: 계산·검증·누락 경고

세무대리인은 명시적으로 위임된 회사와 기간만 접근한다. 위임 만료,
철회, 다운로드, 수정, 승인 이력을 모두 감사로그에 남긴다.

## 13. AI 사용 경계

AI가 할 수 있는 일:

- 계정과목 후보 추천
- 증빙과 거래 연결 후보
- 이상 거래 설명
- 누락 자료 안내
- 자연어 보고서 초안

AI가 확정하면 안 되는 일:

- 세액 최종 확정
- 신고서 무검토 제출
- 법령 적용 여부 최종 판단
- 임의 수정분개
- 사용자 승인 없는 세무대리 권한 부여

추천 결과에는 모델·규칙 버전, 근거, 신뢰도, 사용자 수정 이력을 남긴다.

## 14. 개발 Gate

### Accounting Gate 0 — 법·제품 범위 확정

- 지원 세목·사업자·업종 정의
- 공식 자료 목록과 기준일
- 세무사·회계사 검토 체계
- 지원/미지원 기능 표시 정책

### Gate 1 — 연동 계약

- 이벤트 스키마
- 회사 격리
- 멱등성·정정·취소
- Queue·재시도·대사
- Provider Adapter 계약

### Gate 2 — 내보내기 MVP

- CSV/XLSX
- 연도·월·채널 필터
- 누락·미확정 경고
- Formula Injection 방어
- 한글·영문 헤더

### Gate 3 — 독립 장부

- 계정과목·분개·전표
- 간편장부·복식부기
- 증빙 연결
- 월마감·재개방
- 수정·역분개

### Gate 4 — 세금 계산 자료

- 부가세 자료
- 종합소득세 자료
- 법인세 자료
- 규칙 버전·기준일
- 과거 연도 재현

### Gate 4A — 세액공제·감면 탐색과 자료요청

구현 시점은 Gate 4의 세액 계산 엔진과 공식 사례 대조 검증이 끝난 뒤,
Gate 5 외부 Provider 전송과 Gate 7 신고 연동을 시작하기 전으로 고정한다.

- 사업자 유형, 업종, 사업장 지역, 창업일, 대표자·고용 현황 등 확인된
  데이터만 사용해 적용 가능한 공제·감면 후보를 탐색한다.
- 후보별로 적용 가능성, 예상 절감 범위, 중복 적용 제한, 최저한세,
  사후관리 조건, 신청·신고 기한, 적용 법령과 기준일을 표시한다.
- 감면 전 예상 세액과 감면 후 예상 세액을 함께 표시하되, 증빙과 요건이
  부족하면 금액을 확정하지 않고 `추가 확인 필요` 또는 `계산 불가`로
  표시한다.
- 예상 세액이나 감면 검토에 필요한 누락 자료를 식별해 사용자·담당자·
  세무대리인에게 자료요청을 생성한다.
- 자료요청에는 요청 항목, 요청 사유, 대상 기간, 제출기한, 담당자와
  연결된 세목·감면 후보를 기록한다.
- 제출 전, 제출됨, 검토 중, 보완 요청, 승인, 반려 상태와 알림·재요청,
  첨부자료 접근권한, 보존기간, 열람·수정·승인 감사로그를 관리한다.
- 지원 파일은 PDF, 이미지, CSV/XLSX와 구조화 전자증빙을 대상으로 하며,
  악성 파일 검사와 회사 격리를 통과한 자료만 검토에 사용한다.
- AI는 후보 탐색, 누락 탐지와 설명만 보조한다. 공제·감면의 적용 확정과
  신고 반영은 규칙 엔진 검증 후 사용자 또는 자격 있는 세무전문가의
  명시적 승인을 요구한다.
- 공식 근거가 없거나 적용 연도가 불명확한 제도는 추천하지 않는다.

완료 조건:

- 공식 사례와 전문가 검증 사례에서 감면 전·후 산식이 일치한다.
- 필수 자료 누락 시 추측 계산이나 자동 반영이 차단된다.
- 동일 자료의 중복 제출·중복 적용이 차단된다.
- 요청부터 제출·보완·승인·신고 반영까지 전체 이력이 재현 가능하다.
- 과거 연도 조회 시 해당 연도의 규칙과 근거를 사용한다.

진행 알림 규칙:

- Gate 4의 계산 엔진, 공식 사례 대조와 전문가 검증이 모두 완료되는
  시점에 사용자에게 Gate 4A의 착수 시점이 도래했음을 반드시 알린다.
- 이후 Gate 5 또는 신고자료 생성으로 넘어가기 전에 Gate 4A의 구현·검증
  여부와 보류 사유를 확인한다.
- 이 알림은 일정 기반 자동 알림이 아니라 개발 Gate 충족 여부에 따른
  진행 규칙이다. 사용자 확인과 실제 구현 증거 없이 완료로 표시하지 않는다.

## 15. 테스트 시나리오

- 같은 주문을 두 번 전송해도 전표는 1개
- 취소·환불은 원본을 삭제하지 않고 정정 연결
- 회사 A 이벤트를 회사 B가 볼 수 없음
- 정산 예정과 실제 입금 차이 표시

- 연말을 넘는 주문·환불
- 과거 연도 규칙으로 과거 신고 재현
- Adapter timeout 후 안전한 재시도
- 회계 프로그램 중단 중 HOMEZ 판매 업무 지속
- 손상 백업 복원 거부
- 세무대리 권한 철회 즉시 차단

### 장부·증빙 보존 경계

국세기본법 관련 공식 해석례는 거래 장부와 증빙서류를 해당 국세의
법정신고기한이 지난 날부터 5년간 보존하는 원칙을 설명한다. 따라서
회계 프로그램의 일반적인 `계정 삭제`가 법정 보존 대상까지 즉시 물리
삭제하는 구조가 되어서는 안 된다.

- 거래 장부·증빙과 일반 프로필 데이터를 구분한다.
- 보존 근거·기산일·종료일·법적 보류를 항목별로 기록한다.
- 보존기간 중에는 수정 대신 정정·역분개·새 버전을 사용한다.
- 보존 목적이 끝난 개인정보는 파기하거나 법정 보존 데이터와 분리한다.
- 실제 보존기간은 세목·자료 유형·예외를 전문가가 다시 확인한다.

### 세무대리 자격 경계

세무사법과 관련 판례는 타인의 조세 신고·신청 등을 대신하거나 사실상
신고를 주도하는 세무대리에 자격·등록 제한이 있음을 보여준다. 따라서
HOMEZ 운영사나 회계 프로그램이 자격 확인 없이 `세무대리 서비스`를
직접 제공한다고 표시하거나 수행해서는 안 된다.

- 프로그램은 장부 작성 지원·검증·신고자료 생성 범위를 명시한다.
- 세무대리는 등록된 세무사·세무법인 등 적법한 주체와 계약해 제공한다.
- 위임 주체, 자격·등록 상태, 업무 범위, 기간을 검증한다.
- 자격 만료·위임 철회 시 즉시 접근과 제출 권한을 차단한다.
- 신고 제출 버튼은 자격·위임·사용자 최종 승인을 모두 확인한다.

추가 근거:

법적·기술적 자격과 전문가 검증을 마친 마지막 단계로 둔다.

이 구조는 HOMEZ 판매 업무의 안정성을 지키면서 사용자가 자체 회계
프로그램 또는 기존 회계·세무 서비스를 선택할 수 있게 한다.

## 22. 팀 규모별 제작 시나리오

아래 기간은 법·세무 전문가 검토와 실연동 승인 시간을 제외한 계획용
추정치이며 확정 일정이 아니다.

### 1인 또는 AI 보조 중심

```text
1단계 이벤트·내보내기
→ 2단계 장부
→ 3단계 외부 Adapter
→ 4단계 신고자료
```

- 한 번에 한 세로 흐름만 완료한다.
- 전체 회계 자동화를 동시에 개발하지 않는다.
- 장점: 의사결정이 빠르고 비용이 낮다.
- 위험: 세무 검증·보안·UX가 한 사람에게 집중된다.

### 소규모 3트랙

- Core: 회계 엔진·DB·규칙
- Experience: 장부·대사·신고 UI
- Compliance/Release: 법령·테스트·패키징·연동

HOMEZ V7에서 채택한 3트랙 방식과 동일하게 기능별로 세 트랙을 닫는다.

### 외부 전문가 협업

- 개발팀은 데이터·계산·UI를 구현한다.
- 세무사/회계사는 테스트 케이스와 신고 결과를 검증한다.
- 보안 담당은 인증·권한·Credential·감사로그를 검증한다.
- 전자신고·전자세금계산서 대행은 자격·등록 요건을 별도로 판단한다.

## 24. API 초안

HOMEZ가 제공할 최소 API:

- `GET /accounting/events`: 승인된 원천 이벤트 조회
- `POST /accounting/export-jobs`: 기간별 내보내기 생성
- `GET /accounting/export-jobs/{id}`: 생성 상태·파일 reference
- `POST /accounting/connections`: 회계 Provider 연결 요청
- `POST /accounting/connections/{id}/verify`: 연결 확인
- `POST /accounting/deliveries/preview`: 전송 대상 preview
- `POST /accounting/deliveries`: 사용자 승인 후 전송
- `GET /accounting/deliveries/{id}`: 결과·부분 실패
- `POST /accounting/deliveries/{id}/retry`: 실패 항목만 재시도
- `POST /accounting/reconciliation`: 상태 대사

회계 프로그램이 제공할 최소 API:

- `POST /source-events`: 이벤트 수신
- `GET /source-events/{id}`: 수신·처리 상태
- `GET /books/periods`: 연도·기간 목록
- `GET /books/entries`: 장부 조회
- `POST /classifications/preview`: 분류 제안
- `POST /periods/{id}/close`: 기간 마감
- `POST /tax-preparations`: 신고자료 생성
- `GET /tax-preparations/{id}/validation`: 검증 결과

모든 쓰기 API는 회사 범위 멱등성 키, 사용자 승인 reference, 감사 추적
ID를 요구한다.

사용자 지표:

- 수동 입력 감소 시간
- 미분류 거래 처리 시간
- 월마감 소요시간
- 세무사 질문 왕복 횟수
- 신고자료 내보내기 성공률
- 누락 증빙 사전 발견률

안전 지표:

- 무승인 전송 0건
- Credential 원문 노출 0건
- AI 무검토 세액 확정 0건
- 법령 기준일 없는 계산 규칙 0건

## 26. 축소·중단 시나리오

### 법적 전자신고 연동이 불가능한 경우

장부·검증·신고자료 내보내기까지만 제공하고 홈택스 직접 제출 안내와
세무사 전달 패키지를 제공한다.

### 외부 회계 API가 없는 경우

표준 CSV/XLSX와 검증 보고서를 제공하고, 파일 내보내기도 Provider로
취급해 같은 전송·대사 이력을 남긴다.

### 학습 데이터가 부족한 경우

AI 자동 분류를 출시하지 않고 규칙 기반 후보와 사용자 확인을 유지한다.

### 법령 변경을 제때 반영하지 못한 경우

해당 신고기간의 자동 계산·제출을 Restricted Mode로 차단하고 원천자료
조회·내보내기·백업은 계속 제공한다.

### 대사 불일치가 발생한 경우

자동 신고·기간 마감을 차단하고 불일치 원본·전송·장부 항목을 사용자가
비교할 수 있는 진단 패키지를 생성한다.

## 27. 착수 전 최종 결정 목록

1. 회계 프로그램 제품명·법적 운영 주체
2. 세무대리 업무를 직접 제공할지 제휴할지
3. 첫 지원 세목과 신고 범위
4. 간편장부와 복식부기의 첫 출시 순서
5. 증빙 원문 저장 위치와 보존기간
6. 다른 회계 프로그램 1차 연결 대상
7. 전자세금계산서 발급 대행 여부
8. 사용자 동의·위임·철회 정책
9. 과거 연도 데이터 이관 범위
10. 전문가 검증과 책임 경계
11. 장부·증빙별 법정 보존기간과 파기 정책
12. 세무대리 직접 운영 또는 등록 전문가 제휴 방식
