# HOMEZ V7 — 신규 매입처(공급처) 후보 조사 (Track B, 2026-09-09)

- **작성일**: 2026-09-09
- **성격**: 신규 파일 생성. 코드·DB·서버는 전혀 건드리지 않은 순수 웹 리서치
  결과물이다(WebSearch/WebFetch만 사용). 회원가입·API 키 발급·실제 호출·
  코드/UI/Migration 구현은 하지 않았다.
- **선행 문서**: `docs/HOMEZ_V7_PROCUREMENT_CHANNEL_SURVEY_20260907.md`
  (2026-09-07 조사, 도매매/도매꾹/오너클랜/스페셜오퍼를 이미 1차로 다뤘으나
  대부분 [미확인]/[미착수]로 남아 있었다). 이 문서는 그 후속으로, 같은
  후보들을 더 깊게 재조사하고 새 후보(비셀러)를 추가한 것이다 — 완전히
  새로운 조사가 아니라 갱신·보강임에 유의.
- **계기**: 사용자가 보여준 유튜브 영상 2개(무재고 유통 부업 홍보 영상)를
  분석한 결과, **영상 안에서 직접 확인된 매입처는 없었다**(리드젠용
  카톡방 유입 미끼일 뿐 실제 소싱처 정보가 공개되지 않음). 이에 따라
  영상과 무관하게 독립적으로, 공식 자료만 근거로 후보를 재조사했다.
  **테무(Temu)는 매입처가 아니라 판매채널(마켓플레이스) 후보로 별도
  분류**하며 이번 매입처 조사 대상에서 제외했다.
- **조사 방법의 한계**: 자동화된 웹 조회 도구로 접근했기 때문에 로그인
  후에만 노출되는 정보(정확한 수수료율, API Key 발급 화면 세부 등)는
  다수 [미확인]으로 남았다. "미확인"은 추측하지 않고 그대로 표시했다 —
  실사용 전 반드시 해당 채널에 직접 로그인/문의로 재확인이 필요하다.
- **신뢰도 경고**: 조사 과정에서 추가 후보 "비셀러(beseller.net)"에 대해
  자동 조회 결과가 호출마다 서로 다른 대표자명·주소를 반환하는 현상이
  발견됐다(사업자등록번호는 두 결과 모두 동일했으나 대표자명·주소가
  달랐음). 페이지 렌더링/도구 추출 문제로 추정되며, 이 후보의 사업자
  정보는 신뢰도가 낮다고 판단해 별도로 표시했다 — 이 문서만으로 채택
  근거를 삼지 말 것.
- 홍보성 "수익 인증"·"매출" 문구는 후보 선정이나 평가 근거로 전혀
  사용하지 않았다.

## 종합 판단 (리서치 관점, 실행 판단 아님)

- **가장 공식 자료가 명확했던 후보는 스페셜오퍼((주)탑커머스)**로, 사업자정보·약관(위탁상품 조항, 개인정보 최소제공 조항, 청약철회 조항)까지 1차 출처로 확인됨. 다만 공식 API 문서 존재는 확인되지 않아 엑셀 기반 수동 연동으로 보인다.
- **도매매/도매꾹은 API(Key 인증) 자체는 공식으로 존재**하지만, 외부 판매채널(쿠팡/스마트스토어) 연동은 도매매가 직접 제공하는 것이 아니라 **제3의 API 대행사를 경유**하는 구조라는 점이 새로 확인된 중요 리스크다 — HOMEZ가 자체 주문/재고 파이프라인을 붙이려면 대행사 API를 추가로 조사해야 한다.
- **오너클랜은 사업자 전용 가입 + 자체 API 센터가 존재**하나, "타사 계정 API 연동 준비 중" 문구가 확인되어 현재 시점에 제3자 시스템이 오너클랜 계정을 API로 완전히 자동화할 수 있는지는 추가 확인이 필요하다.

- **역할 정의**: 아래 4개 후보에서 HOMEZ의 위치는 "판매자"가 아니라 **구매자(소싱/매입처로서 이용)**다. 즉 "판매회원 가입" 항목은 해당 플랫폼에 상품을 등록해 파는 셀러 가입이 아니라, HOMEZ(또는 HOMEZ의 판매자)가 상품을 조달하기 위한 구매자/개발자 계정 가입 기준으로 확인했다. 검색 과정에서 "한국 셀러가 알리바바닷컴에 입점하는 방법" 같은 반대 방향(한국 기업이 해외 플랫폼에 파는 방향) 자료가 다수 섞여 있었는데, 이런 자료는 이번 조사의 목적(HOMEZ가 매입처로 이용)과 맞지 않아 참고만 하고 채택 근거로 쓰지 않았다.
- **조사 방법의 한계**: 4개 후보 모두 공식 API 문서 페이지가 JavaScript로 동적 렌더링되는 SPA 구조라(`openservice.aliexpress.com/doc/*`, `openapi.alibaba.com/doc/*`, `open.1688.com/api/*`), 자동 조회 도구로는 "loading..." 상태만 확인되고 실제 문서 본문에 접근하지 못한 경우가 많았다. 이런 항목은 검색엔진 스니펫에 노출된 문서 내용(주로 문서 사이트를 인용한 기술 블로그를 통해 재확인 가능했던 경우)이나 정적 서브도메인(`developers.cjdropshipping.cn` 등)으로 대체 확인했고, 어느 쪽으로도 확인하지 못한 항목은 그대로 "미확인"으로 남겼다. **브라우저 자동조작 도구(Claude Browser)가 이번 조사 세션에서 외부 도메인 접근이 전부 거부되는 환경 문제가 있어 WebFetch만으로 조사했다** — 아래 "미확인" 항목 상당수가 이 기술적 제약 때문이며, 실사용 전 반드시 사람이 직접 로그인해서 재확인해야 한다.
- 홍보성 "수익 인증"·"매출" 문구는 후보 선정이나 평가 근거로 전혀 사용하지 않았다.
- **추가 후보 미채택 사유**: DHgate, Spocket도 검토했으나, DHgate는 공식 개발자 포털/API 문서를 자체 도메인에서 찾지 못했고(서드파티 스크레이퍼·비공식 통합툴만 확인됨), Spocket은 미국·유럽 공급자 중심이라 "해외 소싱 → 한국 채널 재판매"라는 HOMEZ 시나리오에 맞지 않고 공식 API 문서 접근도 확인하지 못해 채택하지 않았다 — 아래 4개 후보만 다룬다.

- 4개 후보 모두 식품 전문 플랫폼이 아니며, 공식 문서에서 식품 카테고리의 소비기한/보관온도/원산지/리콜 정보를 표준 API 필드로 제공한다는 근거는 찾지 못했다(전부 미확인).

- **HOMEZ 관점 코멘트**: 이 4개 해외 후보로 식품류를 소싱해 무재고 중개하려 하면, 해외 구매→국내 반입→수입신고·검사→한글표시 준비라는 절차가 매 주문 건별로 필요해질 수 있어, 일반 공산품 대비 자동화 난이도와 리드타임이 크게 올라간다. 즉 "무재고 중개"의 속도 이점이 식품 카테고리에서는 상당 부분 상쇄될 가능성이 높다 — 실행을 검토한다면 식품은 후순위로 두는 것이 안전하다는 것이 이번 조사의 리서치 관점 코멘트다(실행 판단 아님).
- 출처: [수입식품등의 수입신고 등 — 찾기쉬운 생활법령정보](https://easylaw.go.kr/CSP/CnpClsMain.laf?popMenu=ov&csmSeq=2034&ccfNo=1&cciNo=1&cnpClsNo=2), [수입식품등 신고 및 검사에 관한 규정 — 국가법령정보센터](https://www.law.go.kr/admRulLsInfoP.do?admRulSeq=2100000234842)

## 종합 판단 — 해외 후보 (리서치 관점, 실행 판단 아님)

- **결제 통화 관점에서 가장 진입장벽이 낮아 보이는 후보는 Alibaba.com**이다 — Trade Assurance가 KRW를 포함한 20개 통화를 공식 지원한다고 명문으로 확인되는 유일한 후보이며, 자체 "Dropshipping" 프로그램 URL도 공식으로 존재한다. 다만 프로그램 세부조건(MOQ·수수료)과 API 문서 세부는 확인하지 못했다.
- **API 문서가 가장 구체적으로 확인된 후보는 CJdropshipping**이다 — 인증 절차, 상품/재고 조회, 주문 생성/조회, 상태값까지 1차 문서로 확인됐다. 다만 쿠팡 등 한국 채널 네이티브 연동이 없어 HOMEZ가 자체 미들웨어를 만들어야 하고, 결제 통화가 USD 고정이며 한국어 지원도 확인되지 않는다.
- **AliExpress는 한국 법인이 별도로 존재할 만큼 한국 시장에 공식적으로 투자된 정황이 뚜렷하다**. 다만 Dropshipping API 자체는 개발자 승인제라 즉시 사용 가능한 게 아니고, 반품비는 원칙적으로 구매자 부담이라 무재고 중개 구조에서 반품 리스크를 HOMEZ 또는 판매자가 흡수해야 할 가능성이 있다.
- **1688.com은 4개 후보 중 진입장벽이 가장 높다** — 위안화 전용 정산(WorldFirst 등 제3자 결제대행 필수), 중국어 전용 인터페이스, API 신청에 중국 기업 자격이 사실상 전제된다는 정황, 해외 배송 자체가 예외적이라는 점까지 겹쳐, 현재로선 가장 부적합해 보인다. 다만 원가가 가장 낮은 시장이라는 점은 별도로 고려될 여지가 있다.

## 다음 단계 (실행 착수 아님, 권고만) — 해외 후보

신규 거래처 구현 착수는 트랙 A 전체 회귀 통과 후 별도 승인을 받아야 한다. 착수하게 될 경우 해외 후보 우선순위 권고:
1. **Alibaba.com** — KRW 결제 지원이 명문 확인된 유일한 후보이므로, 드롭쉬핑 프로그램의 실제 MOQ·수수료·API 세부조건을 로그인 후 직접 확인하는 것이 다음 우선순위.
2. **CJdropshipping** — API 스펙이 가장 구체적이라 기술 통합 난이도 예측이 쉽지만, 쿠팡 연동을 HOMEZ가 직접 만들어야 하므로 개발 리소스 산정이 먼저 필요.
3. **AliExpress Open Platform** — 개발자 승인 신청 자체(무료로 보이나 심사 필요)를 먼저 넣어보고 승인 조건·소요기간을 확인해야 실제 통합 가능 여부를 판단할 수 있음.
4. **1688.com** — 진입장벽이 가장 높으므로, 원가 이점이 결제대행 수수료·언어장벽·해외배송 예외구조를 상쇄할 만큼 큰지부터 사람이 직접 1688 상담(중국어) 또는 WorldFirst 문의로 재확인한 뒤에만 후보로 고려.

## 트랙 B 제한 준수 확인 (해외 조사분)

- 조사와 문서화만 수행했다. 회원가입·API 키 발급·실제 호출·코드/UI/Migration 구현은 전혀 하지 않았다.
- 홍보성 수익 사례를 선정 근거로 사용하지 않았다.
- 공식 문서에서 확인되지 않은 항목은 전부 "미확인"으로 표시했고, 서드파티/중국어 커뮤니티 자료로만 확인한 항목은 그 사실을 별도로 명시했다.
- 이 작업은 트랙 A(DB/Migration 조사)의 파일·DB·테스트·실행 서버를 전혀 건드리지 않았다.
