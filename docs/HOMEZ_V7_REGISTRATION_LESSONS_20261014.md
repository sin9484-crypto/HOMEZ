## 6. 신규 기능: URL로 상품 가져오기 (2026-10-14)

쿠팡 실등록을 반복하며 가장 시간이 걸린 부분(상품 정보를 사람이 옮겨 적기)을 줄이기 위한 기능이다.
흐름: **입력창에 URL → URL 검색 → 기재 내용 복사 → 수익 계산 → 상품 등록(초안 생성)**.

| 항목 | 내용 |

| 코드 | `app/domains/product_import/` (`html_tree`, `generic_extractor`, `onchannel_page`, `service`, `router`, `schema`) |
| 지원 | 온채널(공개 페이지 + 공식 API로 가격·옵션·배송비) + 일반 페이지(JSON-LD·OG·표, best-effort) |
| 재사용 | SSRF 방어 페이지 읽기(`media_asset/url_import.py`), 이미지 가져오기·긴 이미지 분할, `margin_calculator`, 후보·위저드 서비스 |

- 고시 확인(`CATEGORY_NOTICE_INFO_REQUIRED`)은 사용자 위임 지시(2026-10-15 "온채널에서 확인해라 지시하지 말고 상품 등록해라")에 따라 도구가 값을 채우고 사용자 계정으로 확인 처리했다 — 값의 출처는 온채널 정보고시와 이전 등록의 판매자 공통값이다.

### 16-1. #14 → #21 쿠팡 등록 결과와 막힌 지점 (2026-10-15)

**결과**: 쿠팡 상품 등록 요청 성공 — 제출 #17 `SUBMITTED`, 쿠팡 상품 번호 **16415163636**, HTTP 200 `SUCCESS`, 경고 없음. 위저드 #21(복제본). 쿠팡 POST 정확히 1건(가드 로그 대조). 쿠팡 쪽 승인 심사·노출 여부는 아직 조회하지 않았다(조회 GET 승인 대기).

**중간에 막힌 순서(전부 쿠팡 호출 전의 로컬 게이트 — 외부 호출 0)**
1. #14 제출 → `CHANNEL_POLICY_GATE_FAILED`: 정책 평가가 없고 `purchase_options`가 비어 있었다. 사전검사의 **경고** `CHANNEL_POLICY_NOT_EVALUATED`를 차단이 아니라고 넘겼다. **제출이 실패하면 위저드가 FAILED(수정 불가)가 되고 복제 외에 길이 없다** → 경고도 제출 전에 반드시 해소한다.
2. #14 복제 → #21: 출고지·반품지 조회 캐시가 **위저드 번호별**이라 GET 2회 재조회가 필요했고, 입력이 바뀌어 8단계 승인도 다시 받았다.
3. #21 제출 → `MODE_NOT_ALLOWED`: 안전 모드가 "추천만"이었다. 전송 사전점검은 **운영자 승인 모드**를 요구한다. → 모드는 **제출 전에** 확인한다(사용자만 변경 가능).
4. 모드 변경 후 `retry-failed`로 제출 #17을 새로 만들었다(승인·캐시 유지, 재복제 불필요) → 전송 사전점검 통과 → 사용자가 비밀번호 재확인 후 전송.

**기록할 특이사항**
- `쿠팡으로 전송` 직후 같은 화면의 "쿠팡 등록 확인"은 GET이라 예산(GET 0)에 막혀 `RuntimeError`로 실패했다 — 쿠팡에 가지 않았고, "등록되지 않음"이 아니다. **전송 예산에는 조회 GET을 함께 열어 두거나, 조회를 별도 승인으로 분리해 안내한다.**
- 전송 중 가드가 `CredWriteW`(자격증명 저장 시도) 1건을 차단했다 — 등록에는 영향이 없었지만 무엇을 저장하려던 호출인지 미확인.
- 출고지·반품지 코드, 택배사(CJGLS), WING 아이디, 반품비 2,500원은 이전 성공 등록(#12)의 판매자 공통값을 재사용했다.
- 도구의 `apply`는 이제 `purchase_options` 대표값을 채우고 정책 평가를 남긴다(코드 반영은 다음 재시작 때). 제출 전 점검 순서: 사전검사 경고 0 → 정책 평가 `CHANNEL_ELIGIBLE` → 안전 모드 → 8단계 승인 → 제출.

### 16-2. 판매자 고정값(WING 아이디·택배사) — 매번 입력·승인하지 않도록 (2026-10-15, 사용자 지시)

- **문제**: 상품마다 5단계에서 WING 아이디·택배사를 다시 입력하고 확인하는 것이 비효율이었다.
- **변경**: 기존 `user_settings`의 `listing_defaults`(소비자상담 전화번호 고정값과 같은 저장소, 마이그레이션 없음)에 `wing_user_id`·`delivery_company_code`를 저장한다. ① 5단계 WING 아이디·택배사 칸에 "고정값으로 저장" 버튼, 칸이 **비어 있을 때만** 자동 입력(입력·저장된 값은 덮어쓰지 않음), 비운 채 저장하면 삭제 ② 등록 도우미는 이 고정값을 **이전 등록 값보다 먼저** 쓰고 노트(`FIXED_DEFAULTS_USED`)로 남긴다. 형식이 틀린 고정값은 무시하고 이전 값으로 되돌아간다. 인증 정보는 저장하지 않는다(서비스가 거부).
- **현재 저장된 값**: WING 아이디 `sin945`, 택배사 `CJGLS`(이전 등록 #12·#14·#21에서 쓴 값) — 사용자 지시("고정값으로 입력")에 따라 저장.
- **적용 시점**: 코드(화면·등록 도우미)는 다음 앱 재시작 후 반영된다. 값 자체는 이미 저장됐다.
