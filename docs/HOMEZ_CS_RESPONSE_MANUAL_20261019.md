# HOMEZ 고객 응대(C/S) 응답 매뉴얼

작성일 2026-10-19 · 대상: HOMEZ를 쓰는 운영자(개발자가 아님) · 판매 채널: 쿠팡(WING) · 공급 방식: 무재고 중개·주문대행

> **이 문서를 읽는 법**
> - 🟢 **HOMEZ 사실** = 이 저장소의 코드·기록으로 확인한 것
> - 🟡 **일반 원칙** = 업계 관행·법의 일반 원칙이며, 쿠팡 정책·법무 확인이 필요할 수 있는 것
> - 🔴 **미확인** = 확인하지 못한 것. 추측하지 않고 WING 화면이나 담당자 확인으로 남겨 두었다
> - 답변 문안은 예시다. 그대로 복사하기 전에 **주문·상품 사실과 맞는지** 먼저 확인한다.

## 2. 기본 원칙 6가지

| # | 원칙 | 왜 | 이렇게 한다 |
|---|---|---|---|
| 1 | **아는 사실만 말한다** | 틀린 안내는 반품·분쟁이 된다 | 상품 페이지·주문·송장에서 확인한 것만. 모르면 "확인 후 안내드리겠습니다" |
| 2 | **약속은 지킬 수 있는 것만** | 날짜·보상 약속은 증거가 된다 | "오늘 중" 같은 시각 약속보다 "확인되는 대로" |
| 3 | **먼저 공감, 그 다음 사실, 마지막에 다음 단계** | 항의는 대부분 불안에서 시작한다 | 문안 구조: 사과/공감 → 확인한 사실 → 다음에 일어날 일 |
| 4 | **효능·의료 표현을 하지 않는다** | 쿠팡이 의료·효능 표현으로 상품을 반려한 전례가 있다 🟢 | "치료·예방·개선" 같은 말 금지 (7장) |
| 5 | **개인정보를 최소로** | 고객 이름·연락처·주소는 필요한 곳에서만 | 외부 메신저·AI·문서에 붙여 넣지 않는다 (6장) |
| 6 | **기록을 남긴다** | 같은 문의 반복·분쟁 때 근거가 된다 | 10장 양식 |

## 3. HOMEZ가 보여 주는 것 / 하지 않는 것 🟢

| 구분 | 내용 |
|---|---|
| ✅ 읽어서 보여 주는 것 | 쿠팡 반품·취소 요청(접수 번호·상태·시각·수량·주문 번호), 상품 문의와 콜센터 문의의 **답변 필요 여부**, 정산 요약 |
| ✅ 갱신 주기 | 반품·문의는 10분마다, 정산은 6시간마다 (허용이 켜져 있을 때) |
| ❌ 가져오지 않는 것 | **고객 이름·연락처·주소·문의 본문·반품 사유 본문**은 읽는 단계에서 버린다 → 내용은 **WING에서 직접** 본다 |
| ❌ 하지 않는 것 | 문의 **자동 답변**, 반품 **자동 승인**, 수령 확인, 환불 처리, 쿠팡 쓰기 호출 — 사람이 WING에서 한다 |
| ❌ 아직 없는 것 | 문의 답변 **초안 AI** (계획만 있음, 미구현) |

> ⚠️ **현재 상태 (2026-10-19 점검)**: 반품·문의·정산 자동 읽기는 **허용이 만료되어 꺼져 있다.** 이 상태에서는 HOMEZ 화면에 문의·반품이 **보이지 않을 수 있다.** 허용이 다시 켜질 때까지는 **WING에서 직접** 확인한다. (허용 부여는 승인 센터에서 사용자가 한다.)

## 4. 무재고 중개 모델에서 알아 둘 점

| 사실 | 고객 응대에 주는 영향 |
|---|---|
| 판매자는 **우리(쿠팡 판매자)**, 실제 배송은 공급처가 한다 🟢 | 고객에게는 **우리가 책임지고 안내**한다. "공급처 문제입니다"라고 떠넘기지 않는다 🟡 |
| 공급처(온채널 등)에 **주문을 넣은 뒤** 송장이 나온다 | 송장이 없으면 공급처 주문 상태부터 확인한다 |
| 공급처의 반품·교환 접수와 **공급사 답변 확인**은 **웹 화면에서 직접** 한다 (온채널 API에 반품·교환·취소·환불 요청과 답변이 없다) 🟢 | 고객 반품이 접수되어도 공급처 접수와 답변 확인은 별도 수작업이다. 답변이 오기 전에는 고객에게 "확인 중"으로 안내한다 |
| 공급처마다 반품 조건·기간·배송비가 다르다 | 공급처 조건 비교 문서를 참고한다: `docs/research/20261018_S0_SUPPLIER_CONDITIONS_COMPARISON.md` |
| 같은 상품 후보가 여러 공급처에 있을 수 있다 | 상품 옵션·구성을 고객에게 안내하기 전에 **현재 연결된 공급처 상품 기준**으로 확인한다 |

## 5. 상황별 응답 문안

공통 인사말 예: `안녕하세요, 고객님. 문의 주셔서 감사합니다.` · 맺음말 예: `추가로 궁금하신 점은 언제든 문의 주세요. 감사합니다.`

### 5-1. 배송

**A. 배송 언제 오나요? (송장 있음)**
- 먼저 확인: 송장 번호, 택배사, 배송 상태(HOMEZ 주문·배송 화면 또는 WING)
- 문안: `고객님, 주문하신 {상품명}은 {택배사} 송장 {송장번호}로 발송되었습니다. 현재 {상태}이며, 택배사 사정에 따라 도착일은 변동될 수 있습니다. 택배사 조회 화면에서 실시간으로 확인하실 수 있습니다.`
- 하지 말 것: 도착 "예정일"을 확정처럼 말하기

**B. 송장이 아직 없어요 / 발송이 늦어요**
- 먼저 확인: 공급처 주문 상태(접수/준비중/품절 여부), 주문 후 경과 시간
- 문안: `고객님, 배송이 지연되어 불편을 드려 죄송합니다. 현재 {확인한 사실 — 예: 상품 준비 중}이며, 발송 일정을 확인하고 있습니다. 확인되는 대로 다시 안내드리겠습니다.`
- 하지 말 것: 원인을 모른 채 "내일 발송"이라고 약속하기. 공급처 탓하기.
- 이어서: 공급처가 **품절**이면 → 5-4 취소 문안

**C. 배송 완료인데 못 받았어요**
- 먼저 확인: 택배사 배송 완료 시각·수령 방식(문 앞/경비실)
- 문안: `고객님, 택배사 기록상 {일시}에 {수령 방식}으로 배송 완료로 확인됩니다. 혹시 가족분이나 경비실, 문 앞 등 주변을 확인해 주시겠어요? 그래도 확인되지 않으시면 알려 주세요. 택배사에 배송 확인을 요청하겠습니다.`

### 5-2. 상품 문의

**D. 사양·구성·호환 문의**
- 먼저 확인: 상품 페이지·상세 이미지·공급처 상품 정보에 **적힌 것**
- 문안(확인됨): `고객님, 해당 상품은 {확인한 내용}입니다.`
- 문안(확인 불가): `고객님, 문의하신 {항목}은 현재 상품 정보만으로는 정확히 확인되지 않아, 확인 후 다시 안내드리겠습니다.`
- 하지 말 것: 추측으로 "될 겁니다", 다른 제품 경험을 근거로 말하기

**E. 재고·옵션 문의**
- 문안: `고객님, 현재 주문 화면에 표시되는 옵션({옵션들})에서 선택하실 수 있습니다. 표시되지 않는 옵션은 준비되어 있지 않습니다.`
- 하지 말 것: "곧 들어옵니다" 같은 입고 약속

**F. 성분·인증·원산지 문의**
- 먼저 확인: 상품 정보고시 · 인증 표기(KC 등)
- 문안: `고객님, 해당 정보는 상품 상세 페이지의 상품정보제공고시에 {내용}으로 표기되어 있습니다.` / 고시에 없으면 `확인 후 안내드리겠습니다.`
- 하지 말 것: **효능 단정** ("피부에 좋습니다", "통증이 줄어듭니다")

### 5-3. 취소

**G. 발송 전 취소 요청**
- 먼저 확인: 상태가 "상품준비중 이전"인지, 공급처 주문이 이미 나갔는지
- 문안(가능): `고객님, 취소 요청을 확인했습니다. 아직 발송 전이라 취소 처리하겠습니다. 결제 수단에 따라 환불은 영업일 기준 며칠 걸릴 수 있습니다.` (기간은 확인한 사실만)
- 이어서: 공급처 주문이 나갔다면 **공급처 취소도 별도로** 해야 한다 (공급처 화면에서 직접)

**H. 발송 후 취소 요청**
- 문안: `고객님, 이미 발송된 상품이라 취소 대신 수령 후 반품으로 도와드리겠습니다. 수령 후 반품 접수를 진행해 주시면 안내에 따라 처리하겠습니다.`

### 5-4. 품절로 우리가 취소해야 할 때
- 문안: `고객님, 주문해 주셨지만 공급 사정으로 해당 상품 재고가 소진되어 부득이 주문을 취소하게 되었습니다. 불편을 드려 진심으로 죄송합니다. 결제 금액은 전액 환불 처리됩니다.`
- 하지 말 것: 대체품을 임의로 보내기 (고객 동의 없이)

### 5-5. 반품·교환·환불

**I. 단순 변심 반품**
- 먼저 확인: 수령일, 상품 상태(개봉·사용·포장 훼손), 상품 페이지의 반품 안내
- 문안: `고객님, 반품 요청 확인했습니다. 단순 변심 반품은 {기간} 이내, 상품이 사용되지 않은 상태에서 가능하며 반품 배송비는 {고객/판매자 — 확인한 기준}에서 부담합니다. 접수하신 대로 회수 일정을 안내드리겠습니다.`
- 하지 말 것: 상품 상태를 보기 전 "무조건 환불" 약속. 법적 기간·부담 주체는 6장 표 확인 🟡

**J. 불량·파손·오배송**
- 먼저 확인: 사진(WING 문의에 첨부된 것), 주문 옵션, 송장
- 문안: `고객님, 불편을 드려 죄송합니다. 보내 주신 사진을 확인했습니다. 상품 문제는 저희 책임으로 반품(또는 교환) 배송비 없이 처리해 드리겠습니다. 원하시는 방법(환불/교환)을 알려 주세요.`
- 이어서: 공급처에 불량·오배송 사실과 사진을 전달하고 **공급사 답변(수거 방식·반품 배송비)을 확인**한다 (4장, 6장). 답변 전에는 고객에게 "확인 중"으로 안내한다

**K. 환불은 언제 되나요?**
- 먼저 확인: 반품 단계(회수 중/입고 확인 전/완료)
- 문안: `고객님, 현재 반품이 {단계}입니다. 상품 회수 및 확인 후 환불이 진행되며, 환불 시점은 결제 수단과 쿠팡 처리 절차에 따라 달라집니다. 진행 상황을 계속 확인하겠습니다.`
- 하지 말 것: 구체 환불 날짜 약속 🔴 (쿠팡 처리 기간 미확인)

**L. 교환 요청**
- 문안: `고객님, 교환 요청 확인했습니다. 교환은 {가능 여부 — 재고 확인 후}입니다. 재고 확인 후 안내드리겠습니다.`
- 이어서: 재고가 없으면 환불로 안내

### 5-6. 항의·감정 대응

**M. 화가 난 고객**
- 구조: ① 불편 인정 ② 지금 확인한 사실 ③ 다음 단계 ④ 짧게
- 문안: `고객님, 불편과 걱정을 드려 정말 죄송합니다. 말씀해 주신 {문제}를 확인했고, {확인한 사실}입니다. {다음 단계}를 진행하겠습니다.`
- 하지 말 것: 방어("규정상…"만 반복), 고객 탓, 감정적 어조, 길게 해명하기

**N. 낮은 별점·리뷰 협박 ("환불 안 해주면 리뷰 쓰겠다")**
- 대응: 협박에 반응하지 말고 **정상 절차**대로 처리한다. 보상을 약속해 리뷰를 바꾸게 하려는 시도는 하지 않는다 🟡 (쿠팡 정책 위반 소지 🔴 미확인)

## 6. 반품 처리 절차 (HOMEZ + WING + 공급처)

| 순서 | 누가 | 어디서 | 할 일 |
|---|---|---|---|
| 1 | 고객 | 쿠팡 | 반품 접수 |
| 2 | HOMEZ | 오늘 할 일 | 반품이 보임 (읽기 허용이 켜져 있을 때, 10분 간격) 🟢 |
| 3 | 운영자 | WING | 사유·사진 확인 → **변심 / 불량 / 오배송**으로 가른다 (이에 따라 반품 배송비 부담이 달라진다) |
| 4 | 운영자 | **온채널 판매자 화면** | `반품/교환 요청`을 **접수**한다. 내용에 쿠팡 주문 번호·반품 접수 번호·사유·전량/일부를 쓰고 **고객 이름·연락처·주소는 쓰지 않는다** 🟢 |
| 5 | 온채널 공급사 → 운영자 | **온채널 판매자 화면** | **공급사 답변을 확인한다** — 공급사 확인 여부, 수거(회수) 방식, 반품 배송비. **HOMEZ는 이 답변·협의 내용을 읽지 못한다** (아래 설명) |
| 6 | 운영자 | WING | 회수 진행 → 입고 확인 후 **수령 확인** 처리 (`RETURNS_UNCHECKED` → `RETURNS_COMPLETED`) 🟢. HOMEZ는 자동 승인·수령 확인을 하지 않는다 |
| 7 | 운영자 | 정산·수익 | 환불·정산 반영 확인 (정산은 6시간마다 읽음) |
| 8 | 운영자 | 기록 양식 | 결과·원인 기록 (10장) |

### 온채널 답변은 사람이 직접 확인한다 🟢

| 구분 | 내용 |
|---|---|
| **HOMEZ가 읽는 것** | 온채널 **주문 상태 코드**뿐이다. 접수 뒤 화면 상태는 "반품/교환 처리중(클레임 접수)"이고, HOMEZ는 주문 상세를 GET으로 읽어 `취소반품`이면 "확인됨", `환불`이면 "환불됨"으로 표시한다. 요청을 처음 접수했다는 **"요청했어요" 기록**은 사람이 남긴다 |
| **HOMEZ가 못 읽는 것** | 공급사가 남긴 **답변 문장**, 수거 방식, 반품 배송비 협의 내용. 온채널 OpenAPI(v0.1)에 반품·교환·취소·환불 **요청과 답변 API가 없고** 주문 상태 코드만 있다 |
| **그래서** | 접수한 뒤 **온채널 판매자 화면을 직접 열어 공급사 답변을 확인**해야 다음 단계(고객 안내·WING 수령 확인)로 넘어갈 수 있다. 답변이 없으면 "공급사 확인 전"으로 두고 고객에게는 "확인 중"이라고만 안내한다 |
| **주의** | 협의가 **완료되면 취소·재협의가 되지 않는다**(2026-10-16 접수 건에서 확인한 화면 안내). 수거 방식과 반품 배송비를 **확인한 뒤에** 협의를 완료한다 |
| **🔴 미확인** | 공급사 답변이 달리면 알림(이메일·문자)이 오는지(온채널 화면 상단 알림은 답변 후에도 0건이었다), 공급사의 평균 응답 시간(1건 관측: 약 2일 9시간), **교환** 요청의 처리 흐름(우리는 단순 변심 **반품** 1건만 접수해 보았다) |

> 실제로 있었던 일(2026-10-17): 쿠팡 반품 접수 → 온채널에 반품 요청 접수(공급사 확인 "미확인", 협의 진행 중) → HOMEZ가 주문 상태 "반품/교환 처리중"을 읽어 기록. 이때 쿠팡 쪽 `RETURNS_UNCHECKED`는 사용자가 WING에서 수령 확인하기 전 상태로 남아 있었다. 즉 **온채널 접수는 쿠팡 수령 확인보다 먼저** 할 수 있고, 수거 방식 협의가 끝나야 회수·입고가 진행된다.

> 공급사 답변 실제 사례(2026-10-19, 온채널 화면에서 직접 읽음 🟢 — 1건 관측이라 일반화하지 않는다):
>
> | 항목 | 관측 내용 |
> |---|---|
> | 응답 시간 | 접수(10-17 00:03) → 공급사 첫 답변(10-19 09:41). 약 2일 9시간(주말 포함) 걸렸다 |
> | 수거 방식 | 공급사가 **계약한 롯데택배로 회수**한다고 안내 |
> | 반품 배송비 | 공급사가 **6,000원을 환불 금액에서 차감**한다고 안내. 주문 금액은 8,310원(상품 5,310원 + 배송비 3,000원)이며, 실제 환불액은 확인 전이다 |
> | 추가 요청 | **새 안심번호 확인 요청** — 기존 안심번호로는 회수가 어려울 수 있다는 이유. 일단 기존 번호로 회수 접수는 진행한다고 함 |
>
> 이 사례에서 얻은 응대 규칙:
> 1. **반품 배송비 차감은 사용자(운영자)가 수용 여부를 판단**한다. 변심 반품이면 소비자 부담이 원칙이지만(아래 법의 일반 원칙 🟡), 쿠팡에서 고객에게 어떻게 청구·안내되는지 확인한 뒤 협의를 완료한다. 협의 완료 후에는 되돌릴 수 없다.
> 2. **안심번호 요청에 답하려면 고객의 새 안심번호가 필요**하다. 번호는 쿠팡 쪽 정보이므로 답변에 개인정보를 옮겨 적는 방식은 쓰지 않는다. 번호 전달 방식은 🔴 미확인이다.
> 3. 협의 창을 **열면 공급사 답변에 "확인일"이 찍힌다**(우리 쪽에서 읽음 처리). 확인만 하려고 열어도 기록이 남는다.
> 4. 이 답변은 HOMEZ가 읽지 못하므로 **HOMEZ 화면은 여전히 "반품/교환 처리중"으로만 보인다.** 공급사 답변이 달렸는지는 사람이 온채널에서 확인한다.

### 고객이 쿠팡 앱에서 보는 반품 화면 🟢 (사용자가 제공한 쿠팡 앱 화면, 2026-10-19)

단순 변심 반품을 접수한 고객의 "취소·반품·교환목록" 화면이다. 상품은 백산수(쿠팡 판매가 12,050원)이며 화면에 주문번호는 없다.

| 화면 항목 | 내용 |
|---|---|
| 반품 사유 | 필요 없어짐 (단순 변심) |
| 상품 회수지 | 고객 주소(일부 가려짐). **변경 불가**로 표시된다 |
| 안내 문구 | 반송장을 받았다면 교환·환불이 완료될 때까지 보관, "교환/반품 접수 후 상품은 언제 가져가나요?" 링크 |
| 환불 안내 | 상품금액 12,050원 − 배송비 3,000원 − 반품비 3,000원 = **환불 예상금액 6,050원** (환불 수단: 토스뱅크) |

이 화면에서 알 수 있는 것:
1. **변심 반품은 고객이 왕복 배송비를 부담한다.** 쿠팡 화면은 원래 배송비 3,000원과 반품비 3,000원, 합계 6,000원을 환불에서 뺀다. 고객 문의에서 "왜 6,050원만 환불되나요"가 나오면 이 구조로 설명한다.
2. **고객 6,000원 부담과 공급사 6,000원 차감이 같은 금액이다.** 공급사는 환불 8,310원에서 반품 배송비 6,000원을 빼 2,310원을 돌려준다(위 사례). 우리가 매입에 쓴 돈 8,310원 중 6,000원은 돌려받지 못하고, 고객 결제 12,050원 중 6,000원은 고객에게 돌려주지 않는다. 즉 **수수료를 빼기 전 기준으로 서로 상쇄되는 구조**다.
3. 고객은 **회수지를 바꿀 수 없다.** 공급사가 요청한 새 안심번호도 고객이 쿠팡 앱에서 바꾸는 방식이 아니라 우리가 확인해 전달해야 할 가능성이 있다(🔴 미확인).

> 🔴 **미확인 — 정산 반영:** 쿠팡이 고객에게서 뺀 배송비 3,000원·반품비 3,000원이 판매자에게 정산되는지, 반품된 판매분의 판매 수수료를 쿠팡이 돌려주는지는 이 화면만으로 알 수 없다. 위 "상쇄" 계산은 **쿠팡 정산 내역을 읽어 확인하기 전까지 추정**이다. 반품 완료 뒤 정산·수익 화면에서 실제 금액을 확인해 이 표를 확정한다.

### 7-2. AI로 C/S 문안을 만들 때 주의점 🟢🟡

> 현재 HOMEZ에 **고객 문의 답변을 만드는 AI는 없다**(3장). 아래는 (a) 지금 사람이 ChatGPT·Claude 같은 AI에 문안을 부탁할 때 지킬 점이고, (b) 문의 답변 초안 AI를 만들 때 **설계 규칙으로 그대로 옮길 점**이다. HOMEZ의 다른 AI 기능(상품 반려 설명, 시스템 점검 설명)에서 실제로 쓰고 있는 규칙을 C/S에 맞춰 정리했다.

| # | 주의점 | 이유 (이번 작업에서 확인한 것) | 이렇게 한다 |
|---|---|---|---|
| 1 | **고객 개인정보를 AI에 넣지 않는다** | 이름·연락처·주소·문의 본문은 HOMEZ도 일부러 읽지 않는다(3장). 스크린샷에 회수지 주소·전화 일부가 보였다 | 주문 번호·접수 번호·사유 분류만 넣는다. 이름·주소·전화는 가리거나 뺀다 |
| 2 | **금액·기한·환불액은 AI가 정하지 않는다** | 같은 반품에서 고객 환불 6,050원(12,050−3,000−3,000)과 공급사 환불 2,310원(8,310−6,000)이 **서로 다른 계산**이었다. AI가 하나로 섞어 말하기 쉽다 | 금액은 사람이 WING·쿠팡 화면에서 확인한 값만 문안에 넣는다. AI가 쓴 숫자는 원본과 대조한다 |
| 3 | **모르는 것은 "확인 필요"로 남긴다** | 정산 반영, 알림 여부, 안심번호 전달 방식은 아직 🔴 미확인이다. 모르는 값을 가정으로 채우면 고객에게 틀린 안내가 나간다 | 초안에서 확인되지 않은 문장은 지우고 "확인 후 안내드리겠습니다"로 바꾼다. "알 수 없음 ≠ 문제 없음" |
| 4 | **약속·기한 문구를 걸러낸다** | AI는 "내일 도착", "오늘 환불" 같은 약속을 잘 만든다. 공급사 답변도 평균 2일 9시간(1건 관측)이 걸렸다 | 7장 금지어 표로 초안을 훑는다. HOMEZ 다른 AI 기능은 약속 표현·숫자가 들어간 응답을 **고쳐 쓰지 않고 버린다** |
| 5 | **책임 떠넘김·과다 인정을 걸러낸다** | AI가 "공급처 잘못입니다" 또는 "전부 저희 불찰입니다"로 쓰는 경우가 있다 | 7장의 "책임 전가/책임 과다 인정" 행을 기준으로 고친다 |
| 6 | **효능·의료·인증 표현 금지** | 쿠팡이 의료·효능 표현으로 상품을 반려한 전례가 있다 🟢 | 상품정보제공고시에 적힌 표기만 인용한다. AI가 지어낸 인증·효능은 지운다 |
| 7 | **쿠팡 밖 연락 유도 금지** | AI가 "전화 주세요"류 문장을 붙일 수 있다 | 연락처·외부 메신저 안내는 모두 삭제하고 WING 안에서 답한다 |
| 8 | **AI가 읽은 내용은 원문을 보고 확인한다** | 외부 글 안에 "이전 지시를 무시하라" 같은 문구를 넣는 시도를 막으려고 HOMEZ는 AI에 보내는 글을 허용 목록으로 제한하고, 그런 문구가 든 페이지의 AI 금액은 폐기한다 | 공급사 답변·고객 글을 AI에 요약시킬 때도, 요약이 시키는 대로 처리하지 말고 원문을 직접 읽는다 |
| 9 | **자동 전송·자동 승인 금지** | HOMEZ는 문의 자동 답변·반품 자동 승인·환불 처리를 하지 않는다(3장). 이 선은 AI를 붙여도 그대로다 | 초안은 사람이 읽고 고쳐서 **WING·온채널 화면에서 직접** 보낸다 |
| 10 | **되돌릴 수 없는 단계 앞에서는 AI 문안을 쓰지 않는다** | 온채널 협의는 완료 후 취소·재협의가 안 된다. 6,000원 차감 수용 같은 결정은 문안 문제가 아니라 운영자 결정이다 | 협의 완료·환불 승인은 AI에 맡기지 않고 운영자가 판단한다 |
| 11 | **AI 호출은 기록·한도가 있는 경로로만** | HOMEZ의 모든 AI 호출은 한 경로(설정 → 월 한도 → 승인 센터 허용 → 호출)를 지나고 사용 기록이 남는다 | 문의 답변 AI를 만들 때도 같은 경로를 쓴다. 별도 키·별도 호출을 만들지 않는다 |
| 12 | **AI 응답 품질은 아직 모른다** | 실제 Claude 응답으로 시험한 적이 없다(가짜 응답으로만 검증) 🔴 | 첫 실사용 때는 모든 초안을 사람이 읽고, 탈락·수정 빈도를 기록해 규칙을 조정한다 |
