## 1. Aside: 수집에서 등록까지의 연결

영상 설명상 후기 수집, 후기 분석, 상세페이지 진단·개선, 카페24 등록을
연결한다. 수집 건수와 데모 성공은 완전성·반복 성공률의 증거가 아니다.

HOMEZ 적용:
1. 상품 URL/API 자료에서 텍스트·이미지·옵션을 수집하고 출처와 시각을 보존한다.
2. 이미지 판독값은 관측값으로 저장한다. 확인된 상품 사실과 구분한다.
3. 상품 사실·이미지 문구·등록값 사이의 수량, 규격, 옵션 충돌을 찾는다.
4. 문제가 있는 영역만 수정안으로 만들고 원본과 변경 근거를 비교한다.
5. 후기의 설명 부족은 상세페이지 개선으로, 실제 품질 문제는 공급처 또는
   상품 재평가로 연결한다. 이미지 편집으로 품질 문제를 감추지 않는다.
6. 승인된 자료를 기존 Listing Wizard로 전달해 재입력을 줄인다.

재사용 후보: media_asset 파일·편집·생성 흐름, 후보 증거, 등록 승인 패키지.
신규 후보: OCR 관측·충돌 모델, 후기 근거 연결, 수정안 평가.
효과 지표: 등록 소요시간, 재입력 횟수, 오류 누락률, 수정안 채택률,
상품당 분석 비용. 브라우저 등록은 API 부재 업무부터 제한적으로 평가한다.

공식 참고: https://aside.com/
기술 설명: https://aside.com/blog/how-we-built-the-sota-browser-agent-that-outperforms-fable

## 2. Amazon: 조사 결과를 실제 실험으로 연결

영상은 후보 선정, 공급처 문의, 샘플 검수, 소량 주문으로 이어지는 4주
계획을 제안한다. '소싱이 80%'와 수익 제목에는 입증 자료가 없다.
FBA 사입 모델을 HOMEZ의 국내 무재고 위탁 모델에 그대로 적용하면 안 된다.

HOMEZ 적용:
1. 기존 후보·선정·매입 상태를 먼저 대조하고, 단계 사이 누락된 다음 행동과
   증거 연결을 보완한다. 중복되는 새 프로젝트 도메인을 먼저 만들지 않는다.
2. 공급처 견적에 단가, MOQ, 배송비, 납기, 유효기간을 같은 형식으로 기록한다.
3. 샘플 검수는 신규 공급처·고위험 상품 등 조건별로 설계한다. 사용자가 정한
   최초 검증 원칙을 고려하며 모든 상품에 새 의무로 강제하지 않는다.
4. 국내 위탁배송과 해외 사입/FBA의 원가 항목을 별도 프로필로 관리한다.
5. 출시 후 실제 마진·반품·배송 성과로 후보 평가를 교정한다.

후보 3개, 조사 7일, 4주 운영 같은 숫자는 제안값이며 확정 기준이 아니다.
AI 광고 분석을 금지할 근거는 없다. 상품별 데이터와 실험 결과를 제공하고
계산은 검증 가능한 코드로 수행하며, 변경 효과를 별도로 측정한다.

공식 참고:
- https://sell.amazon.com/tools/product-opportunity-explorer
- https://sell.amazon.com/pricing/estimate

## 3. 통합 개발 판단

| --- | --- | --- |
| 등록 준비도 | 후보 평가에 정보 누락·편집 작업량 추가 | 후보별 실제 준비시간과 비교 |
| 이미지 리딩 | 기존 미디어에 관측·충돌 표시 | 규격·수량 오독과 충돌 누락 측정 |

| 견적 비교 | 기존 매입처·상품 식별자 활용 | 배송비 포함 동일 조건 비교 |

V8 이미지 리딩 목표는 이미 채택됐다. 나머지는 개선 후보이며 별도 확정
목표가 아니다. V7 실사용 검증을 진행하면서 조사·설계를 축적할 수 있다.
개발 착수 시 효과, 구현 비용, 데이터 확보 가능성을 비교해 순서를 정한다.
