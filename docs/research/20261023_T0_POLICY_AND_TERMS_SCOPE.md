# 약관·정책 AI T0 — 범위 확정안 (2026-10-23)

> 계획서(`HOMEZ_AI_AGENT_WORK_PLANS_20261018.md` §5)의 T0 "범위 확정"을 **권고안**으로 정리했다. 결정이 필요한 항목은 사용자가 바꿀 수 있고, 그때까지는 아래 기본값으로 만들었다.

## 1. "서버"의 뜻 (결정 1)

- 기본값(권고): **지금은 데스크톱 앱 운영만** 다룬다. 앱의 점검(T1·T2)이 이미 이 범위다.
- 클라우드 서버 관리는 V10(다른 판매자용) 이후의 일이라 이번에는 만들지 않았다(T5, 별도 계획서).

## 2. 감시할 플랫폼 정책 페이지 (결정 2)

규칙 카탈로그(`channel_policy/rule_catalog.py`)가 근거로 삼은 공식 페이지가 감시 후보다.

| 플랫폼 | 페이지 | 영향받는 규칙 |
|---|---|---|
| 쿠팡 | 마켓플레이스 정보센터 "판매 불가 품목 안내"(`blog-news7`) | 판매 금지·제한 품목, 원산지, 인증, 성인 표시 |
| 쿠팡 | 정보센터 "상품 정보 입력, 무엇이 달라졌나요?"(`marketplace3p-product-info-update-uid`) | 상품 식별번호(바코드·품번), 브랜드·구매옵션 |
| 쿠팡 | Open API 문서의 카테고리 메타 조회 | 상품정보 고시, 필수 구비서류, 인증 정보 |
| 네이버 스마트스토어 | 근거를 확보하지 못함(접근이 막혀 있었다) | 규칙은 자리표시(PLACEHOLDER)로만 존재 |

- 확인 주기: 권고는 **월 1회 + 쿠팡 공지 알림이 올 때** 사용자가 직접 복사해 비교한다(아래 §3 이유).

## 3. 공지를 자동으로 읽어도 되는가 — 🔴 미확인

- 플랫폼 공지 페이지를 **자동 수집**하는 것이 약관상 허용되는지 확인하지 못했다.
- 그래서 T3는 **사용자가 복사한 이전·이번 글을 비교**하는 방식으로 만들었다(`POST /channel-policy/watch/compare`). 서버가 페이지를 가져오지 않는다.
- 자동 읽기를 붙이려면 ① 약관 확인 ② 승인 센터 "읽기" 허용 목적 추가가 먼저다.

## 4. 약관 필요 조항 (결정 3 포함)

- `channel_policy/terms_checklist.py`에 **공통 13개 + 구매대행 2개 + 위탁판매 2개** 점검 조항을 넣었다(조항 번호는 법령 조문을 적지 않았다 — 법무가 정한다).
- 약관 앱 적용은 결정 기록상 **V10 시점**이다. 지금 만든 것은 **점검표·낱말 점검·본문 없는 뼈대**뿐이며 모두 "법률 자문 아님·법무 검토 필수"가 붙는다. 조항 문장을 AI가 쓰게 하는 기능은 만들지 않았다(법적 효력이 달린 문서).

## 5. 이번에 만든 것과 보류

|---|---|---|
| T1·T2 | ✅ 이전 라운드(+이번 라운드 확장) | 운영 상태 진단·AI 원인 설명 |
| T3 | ✅ 수동 스냅샷 비교 | AI 요약은 **보류** — 외부 글을 AI에 넣으면 지시문 주입 위험이 있어 별도 검증 장치가 필요하고, 결정적 비교·영향 후보만으로 먼저 쓸 수 있다 |
