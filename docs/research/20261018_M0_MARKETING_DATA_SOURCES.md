# M0 마케팅 AI 데이터 원천 조사: 네이버 API HUB 트렌드·쇼핑인사이트와 쿠팡 Open API

확인일: 2026-10-18 KST. 사용자 승인("M0 공식 문서 읽기 승인")에 따른 **공식 문서 읽기 전용** 조사. 로그인·키 사용·API 호출은 하지 않았고 코드·DB·자격증명은 건드리지 않았다. 마케팅 AI 계획(`docs/HOMEZ_AI_AGENT_WORK_PLANS_20261018.md` §2)의 M0 산출물이며 **구현·연동 승인이 아니다.**

방법: 공식 페이지를 요약 도구로 읽었다. 숫자·조항은 **계약이나 설계 확정 전에 원문을 다시 열어 확인**해야 한다. 읽지 못했거나 문서에 없는 것은 "없음/미확인"으로 구분해 적었다(문서에 없다는 것이 "제공되지 않는다"는 뜻은 아니다).

## 1. 네이버 API HUB (데이터랩 계열)

출처: [검색어 트렌드](https://api.ncloud-docs.com/docs/naver-api-hub-search-trend), [쇼핑인사이트 키워드](https://api.ncloud-docs.com/docs/naver-api-hub-shopping-insight-keywords), [쇼핑인사이트 분야](https://api.ncloud-docs.com/docs/naver-api-hub-shopping-insight-categories), [개요](https://api.ncloud-docs.com/docs/naver-api-hub-overview)

| API | 엔드포인트 | 줄 수 있는 것 | 제한 (문서 기준) |
|---|---|---|---|
| 검색어 트렌드 | `POST /search-trend/v1/search` | 검색어 그룹별 기간 추이(일/주/월), 기기·성별·연령 필터 | 2016-01-01부터, 그룹 최대 5개·그룹당 검색어 최대 20개 |
| 쇼핑인사이트 분야별 | `POST /shopping/v1/categories` | 쇼핑 분야별 클릭 추이 | 2017-08-01부터 |
| 쇼핑인사이트 키워드별 | `POST /shopping/v1/category/keywords` | 분야 안에서 키워드별 클릭 추이 | 키워드 그룹 최대 5쌍, 쌍당 비교 검색어 1개, `category`는 네이버쇼핑 `cat_id` |
| 쇼핑인사이트 기기·성별·연령 | `.../category/keyword/{device,gender,age}` | 키워드 추이의 기기(pc/mo)·성별·연령(10~60대) 분해 | 위와 같음 |

- 인증: 헤더 `X-NCP-APIGW-API-KEY-ID`, `X-NCP-APIGW-API-KEY` (현재 앱의 트렌드 어댑터가 이미 같은 방식).
- **응답은 절대 검색량이 아니라 상대 비율**이다: 조회 구간의 최댓값을 100으로 놓은 값(`ratio`). 서로 다른 조회 사이의 값을 직접 비교하거나 "검색 N회"로 해석하면 안 된다.
- 호출 한도·무료 사용량·약관: **문서에 없음.** 상태 코드 표에 `429`가 "하루 허용량 초과"로만 적혀 있고 수치는 없다. 요금 안내와 약관 페이지는 별도 주소라 이번 승인 범위에서 읽지 않았다(**미확인**).
- 앱 상태(저장소 확인): `NaverDataLabTrendAdapter`는 2026-09-07에 실호출로 13주 시계열 수신을 확인했다(상태 문서). 쇼핑인사이트 어댑터는 **아직 없다.**

## 2. 쿠팡 Open API (개발자 센터)

출처: [API 목록](https://developers.coupang.com/ko/api), [매출내역 조회](https://developers.coupang.com/ko/api/settlement/sales-detail-query), [지급내역조회](https://developers.coupang.com/ko/api/settlement/settlement-detail-query), [호출 제한 정책 안내](https://developers.coupang.com/hc/en-us/articles/20414599556889-Introduction-of-Open-API-rate-limit-policy), [API 연동 협약서](https://developers.coupang.com/hc/ko/articles/19906831184793-API-%EC%97%B0%EB%8F%99-%ED%98%91%EC%95%BD%EC%84%9C)

"목록에 없음"은 이 개발자 센터 API 목록 기준이다. 쿠팡 광고센터 등 **다른 경로의 제공 여부는 이번에 확인하지 않았다(미확인).**

### 2-2. 매출내역 조회 `GET /v2/providers/openapi/apis/api/v1/revenue-history`

- 파라미터: `vendorId`, `recognitionDateFrom`/`To`(매출인식일, `YYYY-MM-dd`, **최대 31일**, 종료일은 **전일까지**), `token`(첫 호출은 빈 값, 이후 `nextToken`), `maxPerPage`(기본 50, **최대 50**).
- 매출인식일은 "배송완료 + 7일" 또는 "구매확정" 기준이다 → **주문 직후가 아니라 지연된 실적**이다.
- 응답은 **주문(`orderId`) 단위**이고 `items[]`에 **옵션(`vendorItemId`) 단위** 명세가 있다: `quantity`, `salePrice`, 할인(쿠팡지원·판매자·다운로드 쿠폰), `saleAmount`, `settlementAmount`, 서비스이용료(`serviceFee`, `serviceFeeRatio` 등), `taxType`. 반품 건은 `saleType = REFUND`로 구분된다(**환불 금액의 부호는 문서에 없음** — 예시는 양수).
- `productId`는 바뀔 수 있어 대사 키로 쓰면 안 되고 `vendorItemId`를 쓴다(문서 설명).
- 호출 한도·오류 코드(400 외): 문서에 없음.

### 2-3. 호출 제한과 협약

- 호출 제한 정책(2023-07-10 시행): 초당 5회 초과 `vendorId`는 즉시 차단되고 `429`를 받으며, 기준 이하로 내려가면 수분~수십 분 뒤 재개. 판매자 ID 단위, 전체 API 합산. 분당·일일 한도는 **문서에 없음.**
- API 연동 협약서(공지 2023-06-23)는 **셀러툴사업자와 쿠팡 간의 협약**이다. 관련 조항: 제3조③3 "통합적 운영관리를 수행하기 위한 것 외의 목적으로 API에서 데이터를 추출하여 데이터베이스화"하는 행위 금지, 제3조③2 취득 정보의 무단 복제·저장·가공·배포·제3자 제공 금지, 제8조 협약 목적 외 이용·제3자 제공 금지, 제3조③5·③10 호출량 편법 증가·우회 금지, 제3조③9 API 키 유출 금지, 제5조③ 위반 시 API 연동 제한·키 일시정지. "크롤링"·"경쟁 정보 수집"이라는 표현은 **문서에 없음**.
- **쿠팡 소비자 사이트 이용약관**(자동 수집 금지 조항 확인용): 서버가 `403`을 돌려줘 **읽지 못했다.** 우회하지 않았다. 계획대로 쿠팡 검색 결과의 대량 수집은 하지 않는다.

## 3. 마케팅 AI 설계에 주는 결론

1. **키워드·상품명 제안(M1)의 시장 신호는 네이버 상대 비율뿐**이다(쿠팡 검색 데이터 없음). 화면에 "네이버 검색 관심도 참고, 쿠팡 검색량이 아님"을 고정 표시한다. 값이 없으면 신호 없이도 동작하되 "신호 없음"을 표시한다.
2. **경쟁 가격(M2)은 공식 API가 없으므로** 사용자가 URL을 직접 넣는 방식(계획서 결정 1)이 유일한 합법적 시작점이다. 한 번에 2~5개, 사용자가 건건이 입력, 읽기 전용, 대량 수집·검색 결과 수집 없음. 대상 사이트의 약관 준수는 사이트마다 달라 사용자 책임이며, 결과에 출처·시각·"표시가일 뿐 판매 실적이 아님"을 고정한다.
3. **성과 기록(M4)의 가능한 원천은 매출내역(판매수량·실현 수수료·반품 여부)** 뿐이다. 노출·클릭·전환은 얻을 길이 없으므로 M4 지표는 판매·반품·실현 마진으로 한정한다. 매출 인식이 지연되므로(배송완료+7일) 제안과 결과 사이의 시차를 표에 명시한다.
4. **호출 예산**: 초당 5회·판매자 ID 단위 합산 한도가 있으므로 매출내역 조회는 승인 센터 허용(횟수형 읽기)과 페이지 사이 간격을 둔다. 31일 이내 구간씩 순차 조회한다.
5. **협약 적합성**: 협약서는 "통합적 운영관리" 목적과 제3자 제공 금지를 둔다. 현재처럼 판매자 본인이 자기 키로 자기 데이터를 쓰는 용도는 부합하지만, **V10에서 다른 판매자에게 제공하는 형태는 셀러툴사업자 협약 대상일 수 있어 법무/쿠팡 확인이 필요하다**(이번에 결론내지 않음).
