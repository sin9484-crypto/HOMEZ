## 2. 실제 운영에서 이미 확인된 사실(문서·기록에서)

- 첫 실제 온채널 발주(2026-10-14)에서 **재고 SKU 수동 연결·수수료 근거·속성 비교·호출 예산**이 제품 갭으로 드러났다(메모리 기록).
- 반품 사례(쿠팡 고객이 반품 요청 후 취소했으나 온채널에는 취소가 반영되지 않아 물품이 회수된 건): **반품 손익 계산이 순 0원**이었고, 공급처 쪽 반영은 사람이 문의해야 했다. 이 건은 사용자가 "그냥 넘어가자"로 결정했다.
- 쿠팡 의류 수수료율은 🔴 확인하지 못했다(가정값 사용 중 — 화면에서 "가정"으로 보여야 한다).

## 3. 갭 순위(권고)

1. **실제 반려·문의·품절 빈도를 모르는 것**이 가장 큰 틈이다 — 무엇부터 자동화할지 근거가 없다.
2. 공급처 가격·재고를 **읽는** 경로가 없다(P2·S3가 저장된 값·고정 값으로만 계산한다).
3. P2·P3·S3는 **API만 있고 화면이 없다** — 쉬운 보기·위저드에 붙이는 일이 남았다.
4. 쓰기(P5)는 별도 승인 전에는 하지 않는다.

## 4. 승인이 필요해 하지 않은 일

- **빈도 집계**: 운영 DB를 읽기 전용으로 열어 반려·문의·품절 건수를 세려면 DB 접근 승인이 필요하다(읽기 전용 집계 쿼리만, 개인정보 제외).
- **쿠팡 쓰기 API 문서 확인**(재고·가격·상품 수정·문의 답변): 공식 문서 읽기 승인 후 `docs/research/`에 기록하고 P5 계획서를 쓴다.
- **P5 쓰기 기능**: 횟수형 WRITE 허용·사용자 확인·결과 재조회 검증이 먼저다. 이번 라운드에서는 만들지 않았다(보류 사유: 외부 쓰기는 사용자 승인 없이 열 수 없다).
