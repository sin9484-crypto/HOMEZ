# V8 판매채널·공급처·URL 수집 타당성 조사

조사일: 2026-09-21. 범위: 공개 공식 문서. 로그인, 자격증명 조회, 실제 업무 API, 코드·DB 변경 없음.
목적: V8 범위를 빠뜨리지 않고 검토하되, 문서 존재를 실제 계정 이용 가능·수익성·운영 검증으로 오인하지 않는다.
이 보고서는 후보 선별이다. 모든 플랫폼을 구현하거나 모든 법적 조건을 확인했다는 뜻이 아니다.

## 1. 결론과 과거 판단 정정

1. 판매채널 추가는 네이버 스마트스토어를 우선 후보로, ESM 계열을 다음 후보로 제안한다. 발급받았다는 키가 실제 필요한 권한을 갖는지는 별도 확인이다.
2. 국내 공급처 API 우선 후보는 도매매/도매꾹이다. 공식 `setOrder`가 존재하므로 반드시 제3자 주문대행사를 거쳐야 한다는 종전 판단은 철회한다. Private API 권한 승인과 예치금이 필요하며 주문 생성 자체가 금전 실행이다.[S5-S7]
3. 해외 기술 검증 우선 후보는 CJdropshipping이다. 한국 배송·총비용·상품 적법성이 확인됐다는 뜻은 아니다. 공식 sandbox가 있고 기본값은 실환경이므로 반드시 명시적으로 격리한다.[S11-S13]
4. 네이버 구형 쇼핑 검색 API는 공식 공지상 2026-07-31 종료, API HUB 이관 제외다. 옛 설명 페이지가 열려도 현재 호출 가능의 증거가 아니다. HUB 쇼핑 인사이트를 상품 목록 검색이나 상품별 실제 판매량 API로 취급하지 않는다.[S1-S3]
5. 오너클랜의 '타사 계정 연동 준비중' 문구는 자기 계정용 HOMEZ 연동 불가를 뜻하지 않는다. 공개 API 센터는 확인했으나 매뉴얼·계약·권한 확인이 남았다.[S8]
6. Alibaba.com의 KRW 결제 지원 여부만으로 진입장벽이 가장 낮다고 평가하지 않는다. 1688의 'WorldFirst 필수·중국 기업 필수'도 모든 거래에 적용되는 확정 조건으로 재사용하지 않는다. 계정 유형·지역·구매 방식별 재확인이 필요하다.

## 2. 판매채널 후보 비교

우선순위는 기술적 제안이며 사용자 확정 선택이 아니다. 모든 후보의 현재 계정 수수료·정산주기·상품군 제한·API 권한은 계정/계약 확인 대상이다.

사방넷은 판매채널이 아니라 통합 연동 대안이다. 직접 Adapter와 이용료·기능범위·장애 대응·데이터 반출을 비교한다. 공식 sandbox의 고정 응답은 실제 판매채널 연동 증거가 아니다.[S21]
Amazon·Shopify·AI 쇼핑 채널은 기존 동향 보고의 관찰 후보로 유지한다. V8 첫 채택 목록에 자동 편입하지 않는다.

해외 플랫폼의 구매 가능과 한국 고객에게 합법적으로 재판매·배송 가능은 다른 문제다. 기술 우선순위는 수익성 순위가 아니다. 해외 식품은 초기 추천 대상에서 제외하는 것을 제안한다. 수입판매/구매대행 방식과 품목별 신고·표시·검사 조건을 구분해야 하며, 모든 거래에 동일한 검사가 필수라고 단정하지 않는다.[S28,S29]

## 4. 네이버 데이터와 한 시간 추천 설계

- API HUB: 검색·트렌드 관측. 스마트스토어 커머스 API: 권한을 가진 판매자의 업무 데이터. 별도 서비스인 데이터솔루션/Cloud Data Box는 별도 권한·비용 조사 대상이다.
- 공식 HUB 개요는 한시 무료, 검색 합계 월 775,000회, 검색어 추이/쇼핑 인사이트 각각 월 50,000회, 키당 50 RPS를 안내한다. 구매 계정의 실제 한도와 향후 유료화는 실행 전 재확인한다.[S2]
- 31일 기준 매시간 100회 요청은 74,400회다. '1시간 갱신'만 정하고 키워드 수·페이지·재시도를 무제한으로 두면 월 한도를 넘는다. 배치·캐시·활성 후보 우선·공유 예산을 설계한다.
- 쇼핑 클릭 지수는 상대 지표다. 서로 다르게 정규화된 요청의 점수를 곧바로 절대 비교하지 않는다. 시장 판매량·조회수처럼 표시하지 않는다.[S3]
- 현재 HUB 사용 안내와 종료 공지의 검색 종류가 일부 불일치한다. 구체적인 상품 검색은 종료 공지를 우선하며, 계정 콘솔/현재 명세 확인 전 보장하지 않는다.
- 1시간마다 조회해도 원천 데이터가 매시간 새로 생성되는 것은 아니다. 수집 시각과 데이터 기준 기간을 별도 표시한다.

## 5. URL 등록·검색 전체 흐름

URL 입력 → 출처/접근권한 검사 → API 또는 구조화자료/허용 HTML → 필요 시 허용된 사용자 보조 브라우저 → 필드 추출 → 근거·누락·충돌 표시 → 후보 저장 → 비교 → 등록 초안.

검색은 3개 기능으로 분리한다: 외부 키워드 탐색, 공급처 카탈로그 검색, HOMEZ 저장 후보 검색. URL 하나를 저장하는 기능과 인터넷 전체를 검색하는 기능을 같은 완료 항목으로 처리하지 않는다.

| 설계 항목 | 처리 |
| --- | --- |
| 상품/옵션 | Product/ProductGroup/Offer 구조화자료 활용 가능 [S25]. 이름·이미지만으로 동일 상품 확정 금지 |
| URL 정규화 | 추적값 제거 전 옵션·규격 쿼리 의미 확인. 원본 URL 보존 |
| 필드 | 제조사·모델·원산지·규격·세트수량·옵션·가격·통화·배송·재고·반품·이미지 사용권, 없는 값은 미확인 |
| 신뢰 | 필드별 출처/관측시각/추출방법/근거 위치/충돌 보존. AI 확신도는 사실 확인과 다름 |
| 중복 | 이미지 중복 표시는 묶되 서로 다른 출처·옵션 증거 삭제 금지 |
| 동적 페이지 | 로그인·CAPTCHA 우회 금지. 접근 불가/수동 자료 요청 상태 제공 |
| 보안 | SSRF 방어: http(s) 제한, 내부/loopback/link-local IPv4·IPv6 차단, DNS·리다이렉트·브라우저 하위요청 검증, 시간/크기/MIME 제한 [S26] |
| 외부 콘텐츠 | 프롬프트 주입을 지시로 실행 금지, HTML 정화, 스크립트/파일 실행 금지, 고객정보·키 전송 금지 |
| 권리 | 열람 가능≠수집 허용≠이미지 재사용 허용≠재판매 허용. 약관·라이선스 증거 별도 |
