# S0 공급처 조건 통합 조사: 국내 위탁 후보 비교와 우선 연동 후보

확인일: 2026-10-18 KST. 사용자 승인("S0 문서 읽기 승인")에 따른 **공식 문서 읽기 전용** 조사. 가입·인증·API 호출·주문·결제는 하지 않았고 코드·DB·자격증명은 건드리지 않았다. 상품 서칭 AI 계획서(`docs/HOMEZ_AI_AGENT_WORK_PLANS_20261018.md` §3)의 S0 산출물이며 **구현·연동 승인이 아니다.**

방법: 오늘 공식 페이지 4개를 다시 읽고(아래 §1), 기존 조사 노트(2026-10-05~18, 이 폴더)와 `20260921_V8_CHANNEL_SUPPLIER_URL_FEASIBILITY.md`를 통합했다. 페이지는 요약 도구로 읽어 **계약·가격 판단 전에 원문을 다시 열어 확인**해야 한다.

## 1. 오늘 공식 문서에서 확인한 사실

### 오너클랜 (GraphQL)
- 출처: [API 이용 안내](https://ownerclan.com/V2/service/api-center-guide.php), [주문 API](https://ownerclan.com/V2/service/api-center-order.php)
- 인증: JWT. **판매사 아이디·비밀번호를 인증 주소로 POST**해 토큰을 받는다(본문에 `service: "ownerclan"`, `userType: "seller"`, `username`, `password`). 이후 `Authorization: Bearer`.
- **운영(Production)과 시험(Sandbox) 주소가 모두 문서화**돼 있다(API·인증 각각). 시험 환경의 계정 발급 조건·금전 격리 수준은 페이지에 없다.
- 주문 생성: `recipient`(필수), `products`(필수, `itemKey`·`quantity`·`optionAttributes`), 선택 `note`·`sellerNote`·`ordererNote`·`customsClearanceCode`. **외부 주문키(중복 방지 키)는 문서에 없다**(오너클랜 주문코드 `key`와 장부용 `note`만 있고, `note`는 검색 가능). 생성 시 결제 방식은 문서에 없다(반환 주문의 `transactions`는 "오클랜머니 사용 내역").
- 취소: `cancelOrder`는 **결제 완료(paid)** 주문만, `requestOrderCancellation`은 **배송 준비중(preparing)** 주문만 가능. 반품·교환을 **만드는 API는 문서에 없고**, 주문에 읽기 전용 `refundDetails`("반품 요청 내역")만 있다.
- 배송 추적: 별도 추적 API는 없고 상품 필드(`trackingNumber`, `shippingCompanyName/Code`, `shippedDate`)와 `allOrders`의 `shippedAfter/Before` 필터로 조회한다.
- 주문 분리: 공급사(`vendorKey`)나 배송비 방식(`shippingType`)이 다르면 **한 번에 넣은 주문이 여러 건으로 나뉘어 생성**될 수 있다.
- **페이지에 없는 것**: 가입·API 이용 자격과 비용, 호출 한도, IP 제한.

### 도매꾹·도매매 (Open/Private API)
- 출처: [OPEN API 이용 방법](https://openapi.domeggook.com/ko/articles/OPEN-API-%EC%9D%B4%EC%9A%A9-%EB%B0%A9%EB%B2%95-bd7265d8), [키 발급](https://openapi.domeggook.com/ko/articles/Open-API--Private-API-%EB%B0%9C%EA%B8%89-75c11d02), [API 문서 목록](https://openapi.domeggook.com/main), [구매 주문서 목록 조회](https://openapi.domeggook.com/ko/articles/%EA%B5%AC%EB%A7%A4-%EC%A3%BC%EB%AC%B8%EC%84%9C-%EB%AA%A9%EB%A1%9D-%EC%A1%B0%ED%9A%8C-7804b44f)
- 도매꾹 ID로 키를 발급(ID당 최대 5개). **Open API(문서 4개)**는 키 발급 즉시 사용, **Private API(문서 29개)**는 "로그인/주문수집/발주처리 등"이며 **관리자 승인(2~3영업일, 이메일·알림 통지)** 뒤에만 사용한다.
- **별도 샌드박스(개발) 환경이 없다**고 공식 안내한다 — 주문·결제 시험은 연동 측이 직접 책임진다.
- 상품 등록 API(`setItemBatch`)는 사업자 인증을 마친 사업자 회원만 쓴다.
- 구매 주문서 목록 조회(`getOrderList`, GET, 버전 4.0)가 문서화돼 있고 **로그인으로 받은 세션 ID(`sId`)**가 필요하다. 주문 상태에 입금예정·승인대기·결제완료·배송준비중·배송중·배송완료·구매종료·구매취소·판매취소·반품중이 있다.
- **확인하지 못한 것**: Private API 29개의 제목(페이지가 목록을 그리지 않음)이라 **주문 생성·취소·반품 API의 존재 여부는 확인하지 못했다**(상태 목록에 "반품중"이 있다는 사실만으로 API 존재를 단정하지 않는다). 키 발급 자격(사업자 요건)·비용·호출 한도·IP 등록 요건은 이 페이지들에 없다(기존 노트: 상품정보 동기화 API는 호출 IP 등록 필요, 기존 STOMP 방식은 2026-12-31 종료).

## 2. 후보 비교 (국내 위탁, 쿠팡 판매용)

기준: HOMEZ의 쿠팡 무재고 위탁은 ① 상품·옵션·가격·재고 조회 ② 주문 생성 ③ 중복 주문 방지 ④ 취소 ⑤ 반품 ⑥ 송장 추적 ⑦ 시험 환경 ⑧ 한국 사업자 가입이 모두 필요하다. 값은 모두 **문서에 적힌 것만**이다("미확인"은 없다는 뜻이 아니다).

| 항목 | 온채널(현재 연동) | 오너클랜 | 도매매·도매꾹 | 스페셜오퍼 | 비셀러 |
|---|---|---|---|---|---|
| ① 상품·가격·재고 조회 | 공식 API(조회) | GraphQL `item` 등(상품·옵션·제조국·배송비·상태·변경 이력, KRW) | Open API(문서 4개) + 상품정보 동기화 API(Private 승인·IP) | 공식 API(인증키, 카테고리·상품) | 공개 API 근거 없음(엑셀 업로드) |
| ② 주문 생성 | `order/regist`(포인트 차감) | `createOrder`류(문서화) | Private API "발주처리" 계열(제목 미확인) | 주문 생성·조회 문서화 | 주문 엑셀 업로드 |
| ③ 중복 방지 | `sale_code` 중복 허용 — 직접 보완 | **외부키 없음**(`note` 검색으로 보완 가능성) | 미확인 | `external_key` 있으나 보장 미확인 | 미확인 |
| ④ 취소 | **API 없음** | paid=`cancelOrder`, preparing=`requestOrderCancellation` | 상태 "구매취소/판매취소"만 확인, API 미확인 | 미확인 | 미확인 |
| ⑤ 반품 | **API 없음**(사용자 주장은 문서 URL 미확인) | **생성 API 없음**(읽기 `refundDetails`만) | "반품중" 상태만 확인, API 미확인 | 미확인 | 미확인 |
| ⑥ 송장 추적 | 주문 조회 | 상품 필드·`allOrders` 필터 | 주문서 목록 조회(배송 상태) | 주문 조회 | 미확인 |
| ⑦ 시험 환경 | 없음 | **있음(문서화)** | **없음(공식 명시)** | 미확인 | 미확인 |
| ⑧ 가입·권한 | 판매신청 필수 | **미기재**(계정·API 권한 확인 필요) | Private API 관리자 승인 2~3영업일, 사업자 요건 미기재 | 인증키 발급 자격 미확인 | 사업자 가입 요건 미확인 |
| 인증 방식 | 인증키 | **ID·비밀번호 → JWT** | **ID·비밀번호 로그인 → 세션 ID** | 인증키 | — |

해외 후보(CJ, BigBuy, Syncee, Zendrop, HyperSKU, AliExpress, 1688, Alibaba, Faire)는 기존 노트대로 **국내 흐름 검증 뒤**로 두고 이번 우선순위에서 제외한다(통관·결제 통화·반품 조건이 모두 미확인이고 Faire는 한국 미지원).

## 3. 권고 (결정은 사용자)

1. **1순위 후보: 오너클랜** — 시험 환경이 문서화된 유일한 국내 후보이고 주문 생성·취소·취소 요청이 문서에 있다. 먼저 **읽기 전용 상품 조회 어댑터**(S3)로 시작하고 주문 쓰기는 별도 승인으로 분리한다.
2. **2순위 후보: 도매매(Private API 승인 후)** — 승인 조건과 주문 API 제목을 확인하기 전에는 설계하지 않는다. 시험 환경이 없어 주문 쓰기 시험은 더 위험하다.
3. 나머지는 보류. 해외 후보는 국내 흐름 검증 뒤.

### 오너클랜을 1순위로 볼 때 풀어야 할 문제
- **비밀번호 기반 인증**: 토큰을 받으려면 판매사 ID·비밀번호가 필요하다. HOMEZ는 비밀값을 Windows 자격증명 저장소에만 두지만, 매입 흐름에서는 CAPTCHA·OTP·평문 자격증명을 배제한다는 기존 방침이 있다 → **계정 비밀번호를 자격증명 저장소에 두는 것을 허용할지 사용자가 결정**해야 한다(허용하지 않으면 이 후보는 막힌다).
- **중복 주문 방지**: 외부 주문키가 없다 → 주문 생성 전 HOMEZ 주문 키를 `note`에 넣고 생성 직전 `note`로 기존 주문을 조회해 중복을 막는 방식이 가능한지 **시험 환경에서 검증**해야 한다(문서상 `note`는 검색 가능, 중복 방지는 문서에 없음).
- **주문 분리**: 한 내부 주문이 여러 외부 주문으로 나뉠 수 있다 → 내부 주문 1 : 외부 주문 N 관계와 부분 취소·부분 출고 표시가 필요하다.
- **반품 API 없음**: 온채널과 같다 → 반품은 공급처 화면·문의에서 사람이 처리하고 HOMEZ는 요청·진행 기록만 한다(기존 방식 유지).

## 4. 사용자 확인이 필요한 일 (제가 대신할 수 없는 것)

가입·계정 생성·API 권한 신청은 제가 하지 않는다(계정 생성 금지 규칙).
1. **오너클랜** 판매사 계정 가입 요건과 **API 이용 권한·비용·시험 환경 계정**을 사용자가 직접 확인(고객센터 문의 가능).
2. **도매매** Private API 권한을 신청할지, 신청한다면 사업자 인증 상태.
3. **자격증명 정책**: 위 비밀번호 저장 허용 여부.
4. 우선순위 확정: 오너클랜 → 도매매 순서로 가도 되는지.

## 5. 다음 단계 제안

- (사용자 확인 뒤) **S1**: 후보 정규화·중복 묶기(공급처 무관, URL·CSV 기반 — 지금 바로 시작 가능, 공급처 계약 불필요).
- **S2**: 후보 사전 평가 v2(Phase E 계산·위험 규칙 → 후보 큐 화면) — 공급처 무관, 바로 가능.
- **S3**: 오너클랜 읽기 전용 어댑터 — 위 1~3 확인 뒤.

이 조사에서 바뀐 우선순위나 코드는 없다. 기존 조사 문서·V7 흐름은 그대로이다.
