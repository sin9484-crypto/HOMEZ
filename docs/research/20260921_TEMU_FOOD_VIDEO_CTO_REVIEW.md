# 식품 위탁판매 영상: HOMEZ CTO 분석

기록일: 2026-09-21. 분석·제안이며 기능 구현 또는 실거래 승인이 아니다.
출처: https://www.youtube.com/watch?v=O-DYrhUETCo
증거: 사용자가 제공한 0:00~24:17 자막 전체. 영상 화면·통장·세무서류·공급처 사이트는 직접 확인하지 않았다. 자동자막의 숫자·고유명사 오류 가능성이 있다. 원문 전체는 저장하지 않는다.

## 결론

영상은 새로운 무재고 기술보다 상품 탐색, 공급처 확보, 등록, 최초 매칭 재사용, 주문서 일괄 전달이라는 운영 조합을 보여준다. HOMEZ는 이 흐름을 재사용하되, 순이익·자금 회전·예외 처리까지 연결해야 한다. 경쟁 우위는 현재 입증된 것이 아니라 실운영에서 검증할 가설이다.
V7 출시 필수 범위를 확대하지 않는다. 기존 옵션 연결 채택과 승인 기반 실거래 검증을 먼저 끝낸다. 테무·식품 특화·새 파일 연동은 후속 검토다.

## 2. 수익 주장 검토

- 70억원 매출·20억원 순이익은 출연자 주장이다. 약 28.6% 이익률을 뜻하지만 비용·세금·기간·법인 범위가 확인되지 않았다. 입금과 매출 서류는 순이익 증거가 아니다.
- 4:50~4:59의 8,200만원 매출, 2,000만원 이익, 25%, 진행자의 2,500만원 표현은 일치하지 않는다. 자막 오류 가능성도 있어 조작으로 단정하지 않는다.
- 꽃게 1kg 8,000원과 판매상품 2kg 25,300원을 같은 규격으로 비교하면 상품가 차액은 9,300원이다. 배송·수수료·할인·클레임 비용 전이며 등급·원산지·생물/냉동 동일성도 미확인이다.
- 오징어 27,800원 - 16,400원 = 11,400원 역시 순이익이 아니다.
- 가상 예시: 위 오징어에 배송 3,500원, 채널비용 10%, 클레임충당 3%를 가정하면 4,286원이 남는다. 세금·인건비·고정비 전이다. 이 비율들은 실제 테무 요율이나 HOMEZ 확정값이 아니다.
- 주문 500개의 정상 처리 시간은 묶음으로 줄일 수 있지만 품절·주소오류·반품 대응은 주문량과 함께 늘 수 있다. 하루 2~3시간이 모든 판매자에게 재현된다는 근거는 없다.
- 카드로 매입해도 무자본이 아니다. 일 매입 100만원, 매입부터 입금까지 12일이라는 가정이면 약 1,200만원의 자금 또는 신용한도가 묶인다. 반품·정산보류 여유는 별도다.
- 플랫폼 전체 이용자 수와 일부 상위 상품의 리뷰 수는 식품 구매수요·신규판매자 성공률의 증거가 아니다. 성공 사례만 있어 실패율은 알 수 없다.
- 무료 가이드·단체방 유입 구조는 자막으로 확인되지만 유료 교육·소개 수익은 확인되지 않았다. 사기나 허위라고 단정하지 않는다.

## 3. 외부 공식 확인과 한계

Temu 공식 Seller Center는 확인했으나 한국 계정의 식품 입점 허용 범위, 수수료, 광고 지원 기간, 배송 완료 후 정산 조건, API 권한을 확인하지 못했다. 다른 국가의 조건을 한국 조건으로 쓰지 않는다.
https://seller.temu.com/

국세청은 미가공 식료품 등 일부 재화의 부가가치세 면세를 안내한다. 모든 식품·모든 세금 면제로 확장하면 안 된다. 품목별 처리와 실제 세액은 별도 확인 대상이다. 면세액을 그대로 추가 순이익으로 계산하지 않는다.
https://s.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7804&mi=2483

배송 완료 후 7일이라는 자막 표현을 주문 후 7일로 바꾸지 않는다. 현재 계약 확인 전에는 정산 예측의 확정값으로 사용하지 않는다.

## 4. HOMEZ 응용 설계

### V7: 기존 범위의 완성 및 운영 관찰

1. 옵션 연결: 판매채널 옵션 → 내부 SKU → 공급처 상품·옵션·환산수량을 최초 확인 후 재사용한다. 이름만 비슷하다고 자동 확정하지 않는다. 연결 변경 시 이미 승인된 주문 스냅샷은 유지한다.
2. 검토·승인: 연결된 주문은 기존 발주 검토로 보내고, 가격 상승·품절·미확인 배송비·UNKNOWN은 별도로 보류한다. 이번 영상으로 자동결제 승인을 확대하지 않는다.
3. 실비용 대조: 판매가-공급가가 아니라 실제 배송·수수료·반품 등을 포함해 예상/확정 차이를 관찰한다. 기존 구현 완료 여부는 이번 문서에서 재감사하지 않았다.
4. 운영 측정: 주문당 작업시간, 재입력 횟수, 연결 재사용률, 예외율, 실제 이익을 관찰한다. 신규 계측 기능을 V7 출시 조건으로 추가하지 않는다.

현재 상태 문서상 옵션 연결 v2는 패치·격리 검증 단계이며 제품 저장소 채택 전이다. 영상과 같은 최초 매칭 재사용이 이미 운영 중이라고 표현하지 않는다.

이미지 생성으로 중량·원산지·등급·실물 구성을 바꾸거나 근거 없는 할인·효능을 만들지 않는다. 공급처 이미지 제공과 무제한 재사용 허가는 구분한다.

## 5. 가상 운영 시나리오

가정: 사과 3kg 판매 옵션, 공급처 동일 규격 상품, 첫 연결은 사용자가 확인했다. 특정 공급처·가격·거래 승인이 아니다.
1. 주문 20건을 수집하고 주문·품목 식별자로 중복을 제거한다.
2. 정상 17건에는 저장된 옵션 연결을 제안하고, 3건은 가격 변경·배송지역·옵션 불일치로 분리한다.
3. 사용자가 정상 건의 총액·배송비·납기·한도를 검토해 승인한다.
4. API 또는 승인된 파일 전달로 처리하고 공급처 주문번호를 품목별로 대조한다.
5. 1건이 응답 불명이면 재전송하지 않고 확인 대기로 둔다.
6. 배송과 정산 이후 확정 이익을 비교한다. 예외 대응시간을 포함해 묶음 처리의 실효성을 평가한다.
이는 목표 흐름 설명이지 현재 모든 기능이 구현됐다는 보고가 아니다.

## 6. 우선순위와 기존 연구 관계

- 우선: 기존 옵션 연결 채택과 V7 반자동 실거래 검증. 식품·테무 추가를 현재 출시의 새 의무로 삼지 않는다.
- 운영 후: 반복 수작업이 실제로 큰 공급처부터 파일 연동 또는 API 확대를 선택한다.
- 기존 20260914 영상 분석의 자료-등록 연결 및 V8 이미지 리딩 설계를 재사용한다. 별도 이미지 생성 도메인을 중복 신설하지 않는다.
- 기존 20260918 구현 응용 연구와 중복되는 추천·수익·운영 분석은 후보로 통합하고 확정 개발 요청으로 승격하지 않는다.
- 이전 다른 영상의 공급처 비공개 판단을 이번 영상에 그대로 적용하지 않는다. 이번 자막은 셀러오션이라는 탐색 경로를 명시한다. 다만 실제 공급처 6곳의 신원은 여전히 미확인이다.

## 작업 범위

보고서·색인만 기록. 제품 코드·설정·DB·Migration 변경 없음. 실제 상거래 API 호출 없음. 문서 전용이므로 제품 회귀·트랜잭션·동시성 시험은 실행하지 않음. 프로젝트 출시 판정은 변경하지 않는다.
