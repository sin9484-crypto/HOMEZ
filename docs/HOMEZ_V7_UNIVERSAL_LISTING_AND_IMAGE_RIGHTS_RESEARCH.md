## 2. 이미지 저작권·상표권 승인 정책 (신규 — 사용자 확정 요구사항 원문 반영)

이미지를 생성·편집·합성한 뒤 저작권·상표권·초상권·디자인권 검토 결과를 사용자에게 표시한다.
위험 수준에 따라 사용자가 진행 여부를 선택하게 하되, **사용자 선택만으로 위법 가능성이 해소되는 것처럼 설계하지 않는다.**

### 2.1 권리 검토 시점(12개, 매번 자동 검토)

1. 외부 이미지 URL 입력
2. 이미지 파일 업로드
3. 누끼 생성
4. 배경 합성
5. 여러 이미지 조합
6. 생성형 AI 이미지 생성
7. 텍스트·로고·인증마크 삽입
8. 대표 이미지 지정
9. 상세페이지 생성
10. 옵션 이미지 연결
11. 8단계 최종 승인
12. 실제 판매채널 제출 직전

원본이 안전해도 **파생 이미지 생성 후 다시 검사**한다(원본의 안전이 파생물에 자동 상속되지 않음).

### 2.2 권리 상태 (10종)

`USER_OWNED` / `OFFICIAL_SUPPLIER` / `LICENSED_COMMERCIAL` / `PUBLIC_DOMAIN` /
`AI_GENERATED_BACKGROUND_ONLY` / `RIGHTS_REVIEW_REQUIRED` / `RIGHTS_UNVERIFIED` /
`RIGHTS_CONFLICT_DETECTED` / `RIGHTS_REJECTED` / `RIGHTS_VERIFIED`

상태 이름만이 아니라 아래 근거를 함께 저장한다:
원본 출처, 원본 URL, 권리 보유자, 이용허락 유형, 상업적 이용 허용 여부, 수정 허용 여부, 이용기간,
증빙파일/reference, 확인 사용자, 확인 시각, 원본 SHA-256, 파생 이미지 SHA-256, 생성 모델,
prompt hash, 변환 이력, 검토 결과, 사용자 결정, 결정 사유.

### 2.3 위험 등급

**LOW** — 사용자 직접 촬영, 공급처 상업이용 명시 허가, 상업이용·수정 허용 라이선스 증빙 보유, 권리확인된 누끼+자체 배경 조합.
→ 검토 결과 표시 후 정상 진행 가능.

**MEDIUM** — 출처·권리는 확인됐으나 허용범위 불명확, 타사 상표·로고 포함, 기존 패키지·광고와 유사 가능성,
라이선스 만료일/수정허용 미확인, 공급처 제공이지만 재판매자 사용범위 불명확.
→ 경고 표시 + 추가 증빙 또는 사용자 확인 요구. 정확한 위험·미확인 항목 표시.

**HIGH** — 경쟁 판매자 사진/상세페이지 도용, 타인의 쿠팡·네이버 상세페이지 재사용, 워터마크·상호·저작권 표시 제거,
타사 광고문구·레이아웃 실질적 복제, 패키지·로고·상표를 AI로 유사 생성, 증빙없는 인증마크·시험결과 삽입,
상업이용 금지 라이선스, 권리자 사용중단 요청, 실제와 다른 외형·수량·용량 생성, 출처 은닉·허위 입력.
→ **사용자 선택권으로 우회 불가, 제출 강제 차단.** 상태는 `RIGHTS_REJECTED` 또는 `RIGHTS_CONFLICT_DETECTED`로 저장.

### 2.4 사용자 경고 화면

한 화면에 표시: 이미지 미리보기, 이미지 역할, 원본 출처, 생성·편집 방식, 권리 상태, 위험 등급,
발견된 상표·로고·워터마크, 유사성 위험, 상업적 이용 허용 여부, 수정 허용 여부, 증빙 유무,
미확인 항목, 판매채널 제출 가능 여부, 필요한 조치.

고정 문구:
> "이 이미지는 저작권·상표권 또는 기타 권리 확인이 필요합니다. 판매에 사용하기 전에 이미지의 소유권 또는 상업적 이용 허가를 확인해 주세요. 사용자의 확인은 실제 권리자의 허가를 대신하지 않습니다."

버튼: 증빙자료 등록 / 원본 이미지 교체 / 이미지 다시 생성 / 수정 후 재검사 / 이번 이미지 사용 안 함 / 검토 후 진행 / 상세 근거 보기.
**HIGH 위험에서는 "검토 후 진행" 버튼을 표시하지 않는다.**

### 2.5 사용자 선택 가능 조건 (전부 충족해야 함)

LOW 또는 MEDIUM 위험 / 출처 기록됨 / 권리 보유자·제공자 기록됨 /
상업적 이용 여부 확인됨(또는 확인 책임을 사용자가 명시적으로 수락) /
금지 라이선스 아님 / 워터마크 제거 아님 / 경쟁 판매자 이미지 복제 아님 /
상품 사실 불일치 없음 / 필수 증빙 존재함.

진행 선택 시 저장: `user_id, company_id, asset_id, risk_level, acknowledged_issues, rights_evidence_reference, decision, decision_reason, decided_at, image_fingerprint, policy_version`.
**이미지가 변경되면 기존 사용자 확인은 무효화된다**(channel_policy의 fingerprint 무효화와 동일 철학).

### 2.6 경고와 최종 제출 승인의 분리

```
이미지 권리 확인 → 상품 사실성 확인 → 카테고리·고시 검증 → 가격·마진 검증
→ 8단계 승인 → 제출 직전 전체 fingerprint 재확인 → 실제 제출 승인
```
저작권 경고에서 "진행"을 선택했다고 실제 쿠팡 제출까지 자동 승인되지 않는다. 완전히 별개의 게이트.

### 2.7 참고 상품 URL 사용 제한

대상: `https://www.coupang.com/vp/products/8687771994?itemId=25222807981&vendorItemId=92219139295`

허용: 이미지 역할 분석, 정보 배치 순서 분석, 모바일 가독성 분석, 구매자 필요 정보 종류 분석, 대표·추가·상세 이미지 기능 분류.

### 2.8 AI 생성 이미지 사실성 검사 (저작권과 별개 차단축)

## 5. 사용자에게 재보고 — 수정된 구현 범위

- V7 범위가 4건 → **8건**으로 늘었습니다(3장 표). 그중 4건은 신규 저작권/상표권 정책이며, 원래 V8로 미뤄뒀던 Compliance 성격 작업이 앞당겨진 것입니다.
- `UNCONFIRMED`/`ROOT_CAUSE_UNPROVEN` 5개 항목(0장)은 **구현 착수와 무관하게** 로그인된 실제 세션에서 읽기 전용 재조회로 먼저 닫아야 합니다 — 이걸 확인하지 않고 "구매옵션 검증"부터 구현하면, 애초에 그게 진짜 원인이 아니었을 경우 헛수고가 됩니다.
- 아직 구현에 착수하지 않았습니다.

**결정이 필요합니다:**
1. V7 범위를 8건 전부로 확정할까요, 아니면 저작권 정책(5–8) 중 일부만 V7에 포함할까요?
2. `UNCONFIRMED` 5개 항목을 먼저 재조회부터 할까요(HOMEZ 재로그인 필요), 아니면 이 상태로 구현 설계만 계속할까요?
