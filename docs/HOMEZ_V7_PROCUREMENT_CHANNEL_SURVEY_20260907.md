## 0. 가장 중요한 발견 — "매입처"를 세 그룹으로 나눠야 한다

조사 전에는 "국내 대형 쇼핑몰(네이버·11번가·G마켓 등)에서 공식
API로 물건을 산다"는 그림을 막연히 가정하기 쉽지만, 실제로 확인한
결과는 다르다.

- 네이버 커머스API·11번가 오픈API는 **전부 "판매자가 자기 스토어를
  운영하기 위한" API**다(상품 등록, 내 스토어에 들어온 주문 수집,
  배송·CS 처리). **"고객으로서 물건을 구매하는" API가 아니다.**
  이런 API가 없다는 게 계약을 안 해서가 아니라,애초에 이 플랫폼들이
  "구매자용 발주 API"라는 상품 자체를 팔지 않을 가능성이 높다는
  뜻이다. [추정 — 원문에 "구매자 API는 제공하지 않는다"는 명시적
  부인 문구는 찾지 못했으나, 검색된 모든 문서가 판매자 기능만
  설명함]
- 반면 **도매매/도매꾹(Domeggook)** 은 이미 **위탁판매(dropship)
  전용 B2B 도매 플랫폼**이고, 실제로 **오픈API로 발주까지 가능한
  구조**를 공개 문서에서 확인했다[확인됨]. 오너클랜·펀앤·도매창고·
  허브셀러·스페셜오퍼 등도 같은 성격의 위탁배송 공급망이다[추정 —
  각 사이트 개별 API 존재 여부는 미확인].
- **해외**는 AliExpress Open Platform이 승인제(2~5영업일)로
  드롭쉬핑/제휴 API를 공식 제공하고, **주문 생성 API가 실제로
  존재**한다[확인됨].

**결론(제안)**: `app/domains/retail_purchase/provider.py`의
`OfficialMarketplacePurchaseProvider`("대형 쇼핑몰의 공식 구매/파트너
API")는 네이버·11번가·G마켓 같은 **B2C 소비자 마켓플레이스에는 실제
상품이 없을 수 있다** — 이 Provider 코드가 실제로 맞아떨어지는
대상은 오히려 **AliExpress Open Platform(해외)** 이고, **국내는
`DirectSupplierProvider`("고정 공급처 자동 발주")가 이미 가리키고
있던 도매매류 B2B 위탁배송 공급처**가 훨씬 현실적인 첫 대상이다.
`DirectSupplierProvider`는 현재 "사용자 확정 보류(수익화 모델 별도
검토)" 상태인데, 이 조사 결과가 그 보류의 이유(기술적 불가능이
아니라 비즈니스 모델 결정 필요)를 다시 확인해준다 — **이번 조사로
그 보류를 해제하지 않는다.**

"계약 필요"로 표시해 온 것과 일치한다. 실제로 이 경로를 살리려면
①플랫폼에 구매자용 파트너 프로그램이 별도로 있는지 사업 담당
채널로 직접 문의하거나, ②"사용자 매입처 계정 연결"(사람이 최초
인증하고 이후 절차를 HOMEZ가 대신 수행) 방식으로 접근하는 수밖에
없어 보인다 — 다만 후자는 `docs/HOMEZ_V7_RETAIL_PURCHASE_SAFETY_
GUIDE.md`가 이미 "소비자 계정을 저장하거나 자동 로그인하지 않는다
— 이 기능은 설계에 아예 존재하지 않는다"고 명시한 기존 제약과
정면으로 부딪힌다. **이 제약을 이번 조사로 바꾸지 않는다** — 바꿀지
여부는 사용자 판단이 필요한 사안이다[외부확인필요/사용자 결정
필요].

## 5. 병행수입

이번 조사에서 병행수입 전용 "매입 채널"이나 API는 찾지 못했다 —
병행수입은 보통 **동일한 해외 구매 채널(§3)을 그대로 쓰되, 통관·
수입신고를 병행수입 사업자 자격으로 처리하는 절차상의 차이**로
보인다. 관세·통관·수입신고 실무는 이번 세션이 조사할 수 있는
영역을 벗어난다 — **[외부확인필요, 법무·통관 전문 검토 필요]**
(이미 `docs/HOMEZ_V7_INTEGRATED_PROCUREMENT_GOALS_20260907.md` §5에
동일하게 기록됨).

## 6. 다음 단계 제안(순서 4번 진행 시 참고)

이번 조사 결과를 순서 4번("공통 매입 장부·상태 처리 완성")에 바로
반영할 항목은 없다 — 4번은 코드 감사 작업이라 이 조사와 독립적으로
진행 가능하다. 다만 순서 6번("공식 API 매입 연결")·7번("사용자
계정 기반 매입 연결")·8번("외부 구매대행 업체 연결")에 착수할 때는
이 문서의 우선순위를 참고할 것을 제안한다(제안, 확정 아님).

1. **도매매/도매꾹류 국내 B2B 위탁배송 공급처** — API 존재가 가장
   확실하고, `DirectSupplierProvider`라는 기존 코드 인터페이스도
   이미 있다. 다만 사용자 확정 보류(수익화 모델) 해제가 먼저
   필요하다.
2. **AliExpress Open Platform** — 해외구매대행 첫 후보로 가장
   근거가 명확하다.
3. **네이버·11번가 등 B2C 마켓플레이스의 "구매자 API"** — 존재
   여부부터 각 플랫폼 사업 담당 채널에 직접 문의해야 한다(현재
   조사로는 근거가 약함).
4. **구매용 가상카드** — 어느 매입처가 먼저 뚫리느냐에 맞춰, 그
   결제를 지원하는 카드사/핀테크를 그때 선정하는 것이 순서에 맞다
   (매입처 없이 카드부터 계약하는 것은 낭비일 수 있음).
