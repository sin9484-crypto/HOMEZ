# HOMEZ UI·기능 개선 — 시안 분석과 단계별 계획 (2026-10-15)

사용자가 `Desktop\ui 개선 이미지`에 둔 시안 7장(01 오늘 할 일 / 02 상품 / 03 주문·배송 / 04 정산·수익 / 05 분석 / 06 설정 + 확장자 없는 "ui 개선 버전" = 상품 등록 5단계)을 분석하고, 현재 앱과 대조해 정리한다. 시안의 숫자·상품은 전부 "예시 데이터"이므로 값으로 가져오지 않는다. 이전 관찰은 `docs/HOMEZ_UI_REDESIGN_RESEARCH_20261014.md`.

## 1. 시안이 말하는 공통 원칙

| 원칙 | 시안에서 보이는 형태 |
|---|---|
| 업무 중심 메뉴 6개 | 오늘 할 일 · 상품 · 주문·배송 · 정산·수익 · 분석 · 설정 (+ 도움말). 현재 앱은 39개 메뉴·8개 묶음 |
| 같은 틀 | 상단: 검색 · 계정/채널 선택 · 알림 · **긴급 중지** / 제목 → 업무 탭 → 요약 칩 → 표 → **오른쪽 상세 패널** |
| 사람이 알아보는 정보 우선 | 상품 사진·이름·공급처·판매채널을 표 첫 줄에 (현재 등록 목록은 ID·상태·단계·날짜) |
| 상태는 색·말로 | 확인 필요(빨강)·승인 대기(주황)·처리 중(파랑)·완료(초록) 칩 + 다음 작업 버튼 |
| 근거와 출처 노출 | 분석: "확인된 정보 / 확인할 정보 / 분석 근거"; 등록: "입력 정보 출처(공급처·회사 기본값·직접 수정)" |
| 되돌리기 쉬운 변경 | 설정: 변경안 vs 현재 방식, "변경 확인" 패널, 재인증 후 적용 |

|---|---|---|---|
| 01 오늘 할 일 | 전체 업무 · AI 제안 · 운영 우선순위 · 주문 예외 · 정산 차이 | overview, ai-proposals, operations-priorities, order-exceptions, settlement-differences | **"전체 업무" 통합 목록**(확인 필요/승인 대기/처리 중 집계 + 표 + 선택 업무 패널), 최근 처리 목록 |
| 02 상품 | 상품 후보 · 등록 준비 · 판매 중 · 재고 · 등록 결과 · 속성 비교 · 판매중지 | candidates, listing-wizard, marketplace-listing, inventory, listing-status-sync, product-attr-comparison, recall-blocks | 등록 목록에 **상품명·사진·공급처·채널·단계 n/10·확인사항**(위저드 목록 API 확장), 오른쪽 등록 진행 패널 |
| 03 주문·배송 | 전체 주문 · 발주 · 배송 · 반품·교환 · 환불 · 처리 이력 | order-fulfillment, purchase-task, shipment, return-order, refund | 요약 칩(발주 검토/배송 준비/배송 중/예외 확인), **반품 처리 진행(접수→회수→검수→환불) 패널** — 데이터 모델 존재 여부 확인 필요 |
| 04 정산·수익 | 정산 대조 · 상품별 예상 수익 · 실제 손익 · 자금 현황 | channel-settlement, margin-analysis, finance | 예상 vs 실제 정산액·차이·상태 표, **정산 내역 비교 패널(판매금액·수수료·추가 공제)** |
| 05 분석 | 트렌드 · 신제품 · 상품 비교 · 선별 기준 · 고급 분석 | trend, new-product, decision, ai-learning | **상품 비교**(검색 조건·비교 대상·선택 상품 분석, 확인된/확인할 정보) — 근거 상태 표기 규칙 |
| 06 설정 | 판매채널·공급처 · 자동화·안전 · 가격·비용 기준 · 결제 수단 · 환불 · 사용자·권한 · 계정·보안 · 알림 · 시스템 | store-connection, supplier-capability, safety, price-stock-safety, currency, payment, account-security, system | 기능별 실행 방식 표(현재 vs 변경안) + 변경 확인 패널 |
| 상품 등록 5단계 | 배송·반품 · 채널 상품정보 · 옵션·고시 | listing-wizard 5단계(`lwRenderFulfillmentStep` 계열) | 왼쪽 단계 목록(완료 체크)·상품 머리글·**오른쪽 "이번 단계 확인"**·**"기본값" 표시**·하단 고정 버튼 |

## 3. 현재 앱과의 간격(관찰된 사실)
- 메뉴 39개, 같은 업무가 여러 묶음에 흩어져 있음(예: 정산 차이 검토는 "AI 업무", 정산은 별도 묶음).
- 시안의 "기본값" 칩은 방금 구현한 **판매자 고정값(listing_defaults: WING 아이디·택배사·소비자상담 전화번호)** 과 직결된다 — 5단계에서 "기본값/직접 수정"을 구분해 보여 주는 단계가 다음 후보.
- 사이드바 라벨은 1024px 이하에서 아이콘만 남아 구분이 어려웠다(이번에 해결).

## 4. 단계별 계획과 진행

| 단계 | 내용 | 위험 | 상태 |
|---|---|---|---|
| **1. 구조** | 업무 메뉴 6개 + 화면 위쪽 업무 탭. 기존 메뉴 버튼은 DOM에 그대로(권한 숨김·가이드 ID·기존 테스트의 기준), 접어 두고 "전체 메뉴 보기"로 펼침. 가이드(투어)가 접힌 메뉴를 가리키면 자동 펼침 | 낮음(화면 삭제 없음, 한 곳 되돌리기) | **완료**(테스트 17건) |
| 2. 오늘 할 일 허브 | "전체 업무" 통합 목록 + 요약 칩 + 선택 업무 패널 | 중간 — 기존 4개 화면의 데이터를 모으는 읽기 전용 집계 API 필요 | 미착수 |
| 3. 상품 > 등록 준비 | 위저드 목록에 상품명·사진·공급처·채널·단계·확인사항, 오른쪽 진행 패널 | 중간 — 목록 응답 확장(기존 필드 유지) | 미착수 |
| 4. 등록 화면 | 5단계 탭 분리·기본값/출처 표시·이번 단계 확인 패널·하단 고정 버튼 | 높음 — 위저드 코드가 크고 저장·버전 충돌 로직과 얽힘. 저장 동작을 바꾸지 않고 **표시 계층만** 먼저 | 미착수 |
| 5. 주문·정산·분석·설정 | 요약 칩 + 오른쪽 상세 패널 공통 컴포넌트, 반품 진행 패널, 정산 비교 패널, 설정 변경 확인 패널 | 중간~높음 — 일부는 새 데이터 필요 | 미착수 |
| 0. 시각 통일(병행) | 시안의 초록 계열 강조색·카드·표 스타일을 토큰으로 통일 | 낮음 | 이번에 탭 강조색만 반영(`--ok`) |

원칙: 각 단계는 화면을 지우지 않고 추가→검증→전환 순서로 하며, 저장·승인·전송 동작은 바꾸지 않는다. 금융·승인 관련 확인(재인증, 중복 방지)은 시안대로 더 눈에 띄게 하되 약화하지 않는다.

## 5. 1단계 구현 메모(2026-10-15)
- `console.js`: `SECTION_NAV`(6개 업무·탭 구성), `buildSectionNav`/`refreshSectionNav`/`sectionIdFor`. 같은 화면이 두 업무에 속하면(정산 차이 검토) 보던 업무를 유지. 상세 화면(`*-detail`)은 목록 탭 아래로 본다.
- 권한은 새로 만들지 않고 기존 `.nav-item`의 hidden 상태를 읽는다.
- `console.css`: 접힌 기존 메뉴, 탭 막대, 좁은 사이드바(641~1024px)에서 아이콘 아래 짧은 라벨.
- 번역: `nav.section_*` 등 10키(ko/en). 테스트 `tests/test_section_nav_ui.py`: 기존 모든 화면이 탭으로 도달 가능한지, 번역·권한·가이드 연동 포함.
- 한계: 1·2단계 사이 "오늘 할 일" 첫 탭은 기존 대시보드이며 시안의 통합 목록이 아니다. 시안의 화면 레이아웃(오른쪽 패널·요약 칩)은 아직 적용되지 않았다.
