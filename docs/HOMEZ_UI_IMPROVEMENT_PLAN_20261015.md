# HOMEZ UI·기능 개선 — 시안 분석과 단계별 계획 (2026-10-15)

사용자가 `Desktop\ui 개선 이미지`에 둔 시안 7장(01 오늘 할 일 / 02 상품 / 03 주문·배송 / 04 정산·수익 / 05 분석 / 06 설정 + 확장자 없는 "ui 개선 버전" = 상품 등록 5단계)을 분석하고, 현재 앱과 대조해 정리한다. 시안의 숫자·상품은 전부 "예시 데이터"이므로 값으로 가져오지 않는다. 이전 관찰은 `docs/HOMEZ_UI_REDESIGN_RESEARCH_20261014.md`.

## 1. 시안이 말하는 공통 원칙

| 원칙 | 시안에서 보이는 형태 |
|---|---|
| 업무 중심 메뉴 6개 | 오늘 할 일 · 상품 · 주문·배송 · 정산·수익 · 분석 · 설정 (+ 도움말). 현재 앱은 39개 메뉴·8개 묶음 |
| 같은 틀 | 상단: 검색 · 계정/채널 선택 · 알림 · **긴급 중지** / 제목 → 업무 탭 → 요약 칩 → 표 → **오른쪽 상세 패널** |

## 3. 현재 앱과의 간격(관찰된 사실)
- 메뉴 39개, 같은 업무가 여러 묶음에 흩어져 있음(예: 정산 차이 검토는 "AI 업무", 정산은 별도 묶음).
- 시안의 "기본값" 칩은 방금 구현한 **판매자 고정값(listing_defaults: WING 아이디·택배사·소비자상담 전화번호)** 과 직결된다 — 5단계에서 "기본값/직접 수정"을 구분해 보여 주는 단계가 다음 후보.
- 사이드바 라벨은 1024px 이하에서 아이콘만 남아 구분이 어려웠다(이번에 해결).

## 4. 단계별 계획과 진행

| 단계 | 내용 | 상태 |
|---|---|---|
| **1. 구조** | 업무 메뉴 6개 + 화면 위쪽 업무 탭. 기존 메뉴 버튼은 DOM에 그대로(권한 숨김·가이드 ID·기존 테스트의 기준), 접어 두고 "전체 메뉴 보기"로 펼침 | 완료·커밋(`ab8bd4d`) |
| **2. 오늘 할 일 > 전체 업무** | 주문 예외·정산 차이·AI 제안·운영 우선순위·진행 중인 등록 작업을 한 목록으로(확인 필요/승인 대기/처리 중 칩, 표, 오른쪽 선택 업무 패널). **새 백엔드 없음** — 기존 5개 읽기 API를 `Promise.allSettled`로 읽고, 못 읽은 원본은 안내하며 나머지만 보여 줌. 새 판정 없음 | 구현·테스트 16건 |
| **3. 상품 > 등록 목록** | 위저드 목록 API에 **선택 필드만 추가**(상품명·공급처·판매채널·단계 n/10·대표 사진 id·확인사항 코드, 저장된 값에서만 계산, 일괄 조회로 N+1 없음) + 화면: 사진·상품명·단계·확인사항 칩, 행을 고르면 오른쪽 등록 진행 패널 | 구현·테스트 28건(서버 11 + 화면 17) |
| **4. 등록 화면** | **표시 계층만**: 상품 머리글, 왼쪽 단계 목록(완료 ✓·도달한 단계로 이동), 오른쪽 "이번 단계 확인"(마지막 사전검사 결과 중 이 단계 항목 + 입력 정보 출처 범례 + 다음 단계), 하단 고정 버튼(저장 후 다음 / 초안 저장), 5단계를 3탭(배송·반품 / 채널 상품정보 / 옵션·고시)으로 나눔(칸은 숨기기만 하고 옮기거나 지우지 않음, 숨은 탭의 오류는 탭에 표시·자동 열기), 고정값 칸에 "기본값/직접 수정" 칩. 저장·승인·전송 코드는 변경 없음 | 구현·테스트 20건 |
| **5. 목록 공통** | 주문·배송·반품·환불·정산 대조 목록 위에 **상태별 건수 칩**(칩을 누르면 기존 상태 필터와 같은 값으로 재조회, 전체 기준 건수, 있는 상태만 표시). 주문 상태 번역 10개 추가(표에서 영어 코드 대신 한글) | 구현·테스트 13건 |
| 5 중 **하지 않은 것** | 아래 "남은 시안 항목" 참고 | — |

### 남은 시안 항목(구현하지 않았고 이유)
- **헤더의 "긴급 중지" 버튼**: 실제 비상 정지를 일으키는 동작이라 위치만 옮기는 변경이 아니다. 현재 안전 화면의 기존 동작·확인 절차를 그대로 두고, 헤더 배치는 별도 승인 후.
- **설정 > 자동화·안전의 "변경 확인" 패널(현재 방식 vs 변경안, 재인증 후 적용)**: 안전 모드·한도 변경은 재인증·감사 기록과 얽혀 있어 화면만 바꾸면 안 된다. 별도 설계·승인 필요.
- **분석 > 상품 비교(근거 상태·확인된/확인할 정보)**: 공급가·배송비·수수료 근거 데이터가 화면에 필요한데, 현재 비교 데이터 원본이 없다(온채널 API 미조회 상품 등). 데이터 설계가 먼저.
- **정산 대조의 "예상 vs 실제 정산액·추가 공제 비교 패널"**: 이 앱의 정산 데이터는 현재 0건이라 화면을 검증할 수 없고 추가 공제 항목 모델이 있는지 확인하지 못했다. 정산 대조 목록에는 상태 칩(대조 필요/일치/정산 예정에 대응하는 MISMATCH/MATCHED/PENDING_SETTLEMENT)만 적용.
- **반품 진행 패널**: 반품·배송·환불 상세에는 이전 시안 작업(2026-09-10)의 진행 현황(`statusTimelineHtml`)이 이미 있다. 시안의 "검수" 단계는 이 앱의 반품 상태(접수→승인→수령→완료/거절)에 없어 만들지 않았다.
- 시각 통일(초록 강조색 토큰화)은 새 화면에만 적용(`--ok`), 전체 테마 교체는 하지 않았다.

## 5. 1단계 구현 메모(2026-10-15)
- `console.js`: `SECTION_NAV`(6개 업무·탭 구성), `buildSectionNav`/`refreshSectionNav`/`sectionIdFor`. 같은 화면이 두 업무에 속하면(정산 차이 검토) 보던 업무를 유지. 상세 화면(`*-detail`)은 목록 탭 아래로 본다.
- 권한은 새로 만들지 않고 기존 `.nav-item`의 hidden 상태를 읽는다.
- `console.css`: 접힌 기존 메뉴, 탭 막대, 좁은 사이드바(641~1024px)에서 아이콘 아래 짧은 라벨.
- 번역: `nav.section_*` 등 10키(ko/en). 테스트 `tests/test_section_nav_ui.py`: 기존 모든 화면이 탭으로 도달 가능한지, 번역·권한·가이드 연동 포함.
- 한계: 1·2단계 사이 "오늘 할 일" 첫 탭은 기존 대시보드이며 시안의 통합 목록이 아니다. 시안의 화면 레이아웃(오른쪽 패널·요약 칩)은 아직 적용되지 않았다.
