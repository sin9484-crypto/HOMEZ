## 2. 핵심 질문과 현재의 답

**"공급처 이미지의 형식을 학습해서 비슷한 이미지를 만들 수 있나?"**
- **형식(레이아웃·크기·구성)은 학습·재현할 수 있다** — 가로세로, 대표 이미지 수, 상세 이미지의 섹션 순서(대표 컷 → 특징 → 실측표 → 착용컷 → 세탁·배송 안내), 배경 종류, 글자 영역 위치는 **통계적 사실**이라 규칙·템플릿으로 만든다.
- **제품 그림 자체를 새로 생성하는 것은 지금 원칙상 금지**이고(CTO 지시), 의류·속옷처럼 실물 사실성이 중요한 상품은 **실물 사진에서 벗어나면 허위·오인 위험**이 크다.
- **공급처 이미지를 모델 학습 데이터로 쓰는 것**은 법적으로 별개 문제다. 공급처가 허락한 것은 보통 "판매 목적의 상품 이미지 게시"이지 "AI 학습"이 아닐 수 있다 — **미확정, 법률·약관 확인 필요**(이 문서는 법률 자문이 아니다).

→ 결론(설계 방향): **"학습"을 둘로 나눈다.** ① 형식 사실을 뽑는 **분석기**(규칙 기반, 권리 위험 낮음, 지금 시작 가능) ② 이미지를 만드는 **생성기**(기존 합성 엔진 확장, 제품은 실제 사진 사용). 신경망으로 픽셀을 학습하는 모델은 3단계 이후, 사용자 결정과 권리 확인 뒤에만 다룬다.

## 3. 설계 제안 (단계별, 한 번에 하나)

### 3-1. 구성도
```
권리 게이트(사용권 증빙) → 분석기(형식 추출) → 형식 프로필 저장소 → 카테고리 스타일 가이드(집계)
                                                         ↓
 사용자 사진/허락된 사진 + 텍스트 → 생성기(기존 composition·detail_page_generator 확장) → 검증기 → 사용자 승인
```

### 3-2. 구성 요소
1. **권리 게이트**: 상품별 사용권 증빙(`ImageRightsEvidence`)이 없으면 분석 결과를 저장·학습에 쓰지 않는다. 분석 대상과 *학습 대상*을 분리해 기록한다.
2. **분석기(로컬, 결정적)**: 이미지 디코드 → 크기·종횡비·파일형식 → 배경 종류(흰색/단색/장면, 모서리 픽셀 샘플) → 피사체 영역(기존 rembg 제공자) → 세로 이미지의 **섹션 경계**(가로 행 전체가 거의 단색인 구간을 기준) → 섹션별 면적·색상 팔레트 → (선택) 글자 영역. 출력은 픽셀이 아니라 **형식 프로필 JSON**(수치·분류)이다.
3. **형식 프로필 저장소**: 상품·이미지·분석기 버전·권리 증빙 번호를 묶어 저장(원본은 승인된 보관 위치에만). 신규 테이블이 필요하면 Migration은 **별도 승인**(이 문서는 만들지 않는다).
4. **스타일 가이드(집계)**: 카테고리(의류/패션잡화/스포츠) 단위 분포 — 대표 이미지 수, 상세 이미지 높이 분포, 섹션 순서 빈도, 글자 밀도. 초기에는 **통계만**(학습 모델 아님). 표본이 적으면(예: 상품 7개) 가이드를 "참고"로만 표시한다.
5. **생성기**: 기존 엔진을 **프로필 매개변수로 구동**한다 — 대표 이미지 1000×1000 정사각 흰 배경, 상세 이미지는 780px 폭·섹션 템플릿(특징/실측표/세탁 안내/배송 안내), 긴 상세 이미지는 `image_split`로 분할. 입력은 사용자가 가진 실물 사진 + 사용자가 입력한 글(제품을 새로 그리지 않음).
6. **검증기**: 쿠팡 규격(대표 ≥500×500, 상세 폭 780·높이 ≤5,000, 대표 이미지 흰 배경·글자·워터마크 금지)과 권리·사실성 검사. 하나라도 실패하면 **생성 차단**(자동 보정 금지).
7. **사람 승인**: 모든 생성 결과는 사용자가 확인·승인해야 등록 단계로 넘어간다(자동 게시 없음).

### 3-3. 생성 모델(선택 사항, 지금은 보류)
`ImageGenerationProvider`에 실제 외부 이미지 생성 API를 붙이는 것은 **사용자·CTO 결정 사항**이다 — 비용, 키 보관(채팅·문서에 키 금지), 생성물의 사실성 검사, 상표·초상권, "AI 생성" 표기 정책이 먼저 정해져야 한다. 허용하더라도 **배경·장면 같은 비제품 요소**에 한정하고 제품 형상은 실물 사진을 쓴다.

### 3-4. 평가 지표
규격 통과율, 형식 프로필과의 일치도(크기·섹션 순서), 사용자 승인율, 쿠팡 반려 사유 빈도(반려가 생기면 학습 신호로 기록), 생성 시간·비용.

## 4. 미확정·사용자 결정 필요
1. 공급처 이미지를 **분석(형식 추출)에 쓰는 것**과 **모델 학습에 쓰는 것**을 구분해 허용할 범위. 학습은 "사용권 확인" 상품에 한정할지.
2. 생성 대상 우선순위: 대표 이미지 / 상세 이미지 / 옵션별 이미지(색상 변형) 중 무엇부터.
3. 신규 Python 의존성(글자 인식 등) 허용 여부와 Migration 허용 시점.
4. 외부 이미지 생성 API를 허용할지(보류 권장).

**한계(솔직한 기록):** `kind_hint`(사진형/그래픽형)와 `content_ratio`는 색 다양성·배경 대비로 추정한 **힌트**이며 의미 분류(대표 컷·실측표·세탁 안내 같은 역할)가 아니다. 역할 분류에는 사람이 붙인 라벨이 필요하다(P4). 세로가 가로의 3배 미만인 이미지는 섹션 분석을 하지 않는다(폴라 니트 상세 9장). 위 수치는 **분석 결과이며 이미지 사용권이 확인되었다는 뜻이 아니다** — 해당 이미지는 모두 `RIGHTS_UNVERIFIED` 상태다.

**권장 다음 단계:** ① 사용자가 위 해석(특히 "흰 배경 대표 이미지 생성이 가장 가치 큼")에 동의하는지 확인 → ② P3로 건너뛰어 **흰 배경 대표 이미지 생성 + 섹션 경계 분할**을 기존 엔진 확장으로 먼저 만든다(신경망·외부 API 없이 가능). ③ 형식 프로필 저장(P2)은 Migration 승인 후.

## 7. P3 구현: 컨셉 선택과 섹션 경계 분할 (2026-10-14, 사용자 요청)

사용자 요청: "여러 가지 컨셉으로 만들 수 있게 하고, 컨셉을 선택할 수 있게 섹션을 구분 짓고, 섹션 경계 분할을 진행한다."

### 7-1. 컨셉(`image_concepts.py`)
컨셉 = 배경 + 글자 색 + 포인트 색의 묶음. 같은 실제 제품 사진에 컨셉만 바꿔 여러 분위기의 이미지를 만든다(제품은 다시 그리지 않음).

| 코드 | 이름 | 쓸 수 있는 용도 | 성격 |
|---|---|---|---|
| `CLEAN_WHITE` | 깔끔한 흰 배경 | 대표·추가·상세 | 쿠팡 대표 이미지에 안전한 기본형 |
| `SOFT_BEIGE` | 소프트 베이지 | 추가·상세 | 따뜻한 내추럴 |
| `FRESH_MINT` | 청량한 민트 | 추가·상세 | 위생·여름·스포츠 |
| `BLUSH_PINK` | 은은한 핑크 | 추가·상세 | 여성·아동 |
| `CALM_GRAY` | 차분한 그레이 | 추가·상세 | 기능성·남성 |
| `MIDNIGHT_PREMIUM` | 미드나이트 프리미엄 | 추가·상세 | 고급스러운 어두운 배경 |

- **대표 이미지(MAIN)에는 흰 배경 컨셉만 허용**한다(실측에서 공급처 대표 이미지는 흰 배경 0/10이었고, 쿠팡은 흰 배경을 권장).
- 글자 가독성은 테스트로 보장한다(본문 대비 ≥7:1, 보조 글자 ≥4.5:1, 포인트 색 ≥3:1, WCAG 수식).

### 7-2. 섹션 구분
상세 페이지는 **5개 섹션**(`BRAND` 브랜드 소개, `HERO` 대표 사진, `FEATURES` 주요 특장점, `SPECS` 스펙 표, `USAGE` 사용법)으로 구분되고, **페이지 전체 컨셉**(`concept_code`)과 **섹션별 컨셉**(`section_concepts`)을 따로 고를 수 있다(섹션별이 우선). 없으면 기존과 똑같은 흰 배경이다(기존 테스트 16건 불변). 사용자가 포인트 색을 직접 바꿨으면 그 색을 존중한다.

### 7-3. 섹션 경계 분할(`section_split.py`)
세로로 긴 상세 이미지를 고정 1,200px로 자르지 않고 **섹션 사이 빈 여백의 한가운데**에서 자른다.
- 조각 높이 600~1,500px, 선호 1,200px에 가장 가까운 경계를 고른다. 자르고 남는 부분도 600px 이상이 되게 해 작은 자투리가 생기지 않는다.
- 빈 여백이 범위 안에 없으면 가장 빈 줄에서 자르고 `FORCED`로 표시한다(숨기지 않는다).
- **픽셀을 바꾸거나 버리지 않는다** — 조각을 이어 붙이면 780px로 줄인 원본과 정확히 같다(테스트).
- 같은 합성 이미지에서 고정 높이 분할은 내용을 자르고 섹션 분할은 자르지 않음을 테스트로 비교한다.

### 7-4. 연결(API·서비스)
| 위치 | 변경(기본값은 모두 기존 동작) |
|---|---|
| `POST /media-assets/split`, `POST /media-assets/upload-long-detail-image` | `mode: "FIXED"(기본) \| "SECTION"` |
| `POST /media-assets/background-composition` | `concept_code`, `purpose`(MAIN\|ADDITIONAL) — 컨셉을 고르면 컨셉 배경 사용, MAIN은 흰 배경 컨셉만 |
| `POST /media-assets/generate-detail-page` | `concept_code`, `section_concepts` |
| `GET /media-assets/concepts?purpose=` | 화면에서 고를 컨셉 목록(미리보기 색 포함) |
| `GET /media-assets/detail-sections` | 섹션 목록(키·한글 이름) |
| URL 가져오기(`product_import`) | 새로 가져오는 긴 상세 이미지는 **섹션 경계 분할**을 쓴다 |

### 7-5. 검증
신규 테스트 35건(`test_media_section_split` 18, `test_media_image_concepts` 17) 통과, 변이 검사 3종(남는 부분 제한 제거, 대표 이미지 컨셉 제한 제거, 섹션별 컨셉 무시) 모두 테스트가 잡았고 복원 확인. 분석기 22건 포함 media_asset·product_import·쿠팡 이미지 관련 기존 25개 모듈 통과.

### 7-6. 한계·남은 일
- **흰 배경 대표 이미지 자동 생성은 아직 못 한다** — 공급처 대표 이미지(연출 컷)에서 제품만 오려 내는 배경 제거(rembg)가 필요하다. 이 기능은 코드에 연결돼 있지만 최초 실행 때 모델 파일을 내려받는 네트워크 호출이 있고(CTO 승인 항목), 이번 세션에서는 실행하지 않았다. 사용자 승인 후 시험한다.
- 컨셉 선택 **화면(UI)** 은 아직 없다 — API로 먼저 제공했다. 위저드 3단계 화면에 컨셉 선택기를 붙이는 것은 다음 단계다.
- 이미 가져온 7개 상품의 상세 조각(고정 높이 분할)은 그대로다. 새 코드는 앱을 다시 시작해야 반영되며, 반영 뒤 `POST /media-assets/split`에 `mode: "SECTION"`으로 원본을 다시 나눌 수 있다(원본 보존, 새 조각 생성).

### 7-7. 실제 시험 결과 (2026-10-14, 방수 생리팬티 #14, 사용자 승인 "1.2.3 승인")

**섹션 경계 분할(상세 원본 #26, 19,812px):** 고정 높이 분할 대신 13조각(높이 719~1,480px, 폭 780)으로 나눴다. 조각을 이어 붙이면 780px 축소본(15,453px)과 **픽셀 동일**. 12개 경계는 완전한 빈 여백이고, 1개 경계(#120|#121)는 은은한 그라데이션 배경의 사진 패널이 맞닿는 지점이라 줄 대비 13~14가 남았지만 눈으로 확인한 결과 물체는 잘리지 않았다. → **빈 줄 기준(대비 ≤6)이 그라데이션·질감 배경에서는 지나치게 엄격**해 이런 경계를 `FORCED`로 분류할 수 있다(개선 과제: 빈 줄 기준을 구간 평균 대비로 보정). 두 번째 원본(#40, 1,732px)은 한 조각이라 기존 조각(#41)을 그대로 쓴다. 위저드 #14의 이미지 선택을 새 조각(#115~#127, #41)으로 교체했다.

**배경 제거(rembg u2netp):** 모델 파일 1개를 GitHub 공개 릴리스에서 **GET 1회**로 받아(`registration71\u2net`) 대표 이미지 #25에서 제품을 오렸다(34초, #128). 컨셉 5종(#129~#133)을 합성했고, 대표 이미지(MAIN)에 핑크 컨셉을 요청하면 서버가 400으로 거부함을 확인했다.

**한계(눈으로 확인):** #25는 **모델 착용 컷**이라 배경 제거가 모델의 다리와 오른쪽 아래 원형 색상 샘플까지 남긴다 → **이 컷은 대표 이미지 소스로 부적합.** 제품만 찍힌 컷(예: 8색을 펼쳐 놓은 상세 조각)을 소스로 삼아야 흰 배경 대표 이미지가 깔끔하게 나온다. 왼쪽 위에 흐릿한 잔상이 약간 남는 곳도 있다.

**다음(제안):** ① 소스 후보를 분석기로 고른다(흰 배경 비율이 높고 섹션 하나가 사진 한 장인 조각) → ② 그 조각에서 제품 오려 내기 + 컨셉 합성 → ③ 사용자가 마음에 드는 컨셉을 고르는 화면(UI).

## 8. 적응형 배경 설계 (2026-10-14, 사용자 요청 — "상품이 부각될 수 있게 배경을 만든다. 상품이 다양하므로 배경을 고정하지 않는다")

미리 정한 컨셉(7절)은 **제품과 상관없이 고정된 색**이라는 한계가 있다. 그래서 제품의 색을 분석해 **제품마다 다른 배경**을 제안하는 `background_designer.py`를 추가했다.

### 8-1. 방식(제품은 다시 그리지 않는다)
1. **제품 색 분석**: 누끼의 불투명 픽셀만으로 주요 색 4개(점유율), 평균 밝기·채도, 대표 색조를 구한다. 밝은/어두운/무채색 제품을 구분한다.
2. **후보 생성**: 보색 파스텔, 같은 색 톤, 이웃 색 파스텔, 스포트라이트(어두운 제품), 깊은 대비 배경·짙은 중립 회색(밝은 제품), **선명한 색 배경**, 흰 배경. `variation`(0~11)을 바꾸면 같은 제품도 다른 색조 묶음이 나온다.
3. **점수화**: 제품 주요 색과 배경의 CIE Lab 색 차이(ΔE)를 점유율로 가중해 0~100점을 매기고, **대비가 큰 순서**로 돌려준다. 배경에 묻히는 색이 제품의 35% 이상이면 `low_contrast`로 경고(작은 안감 한 색 때문에 과하게 경고하지 않도록 비중 기준을 쓴다).
4. **그리기**: 배경(단색·세로 그라데이션·방사형) 위에 제품을 가운데 놓고, 선택하면 부드러운 그림자를 더한다. 제품 픽셀은 바꾸지 않으며 기본은 확대하지 않는다(`max_upscale` 1.0~2.5로 작은 크롭만 제한적 확대 허용).
5. **대표 이미지(MAIN)는 흰 배경만** 허용한다(규칙 유지). 흰 제품이 흰 배경에 묻히면 경고와 그림자 권장을 함께 알린다.

### 8-2. API
`POST /media-assets/background-suggestions`(읽기 전용: 제품 색 요약 + 배경 제안 목록) → 사용자가 고른 제안으로 `POST /media-assets/adaptive-composition`(`suggestion_code`, `purpose`, `variation`, `shadow`, `fill_ratio`, `max_upscale`) → 파생 이미지(파일 이름에 `adaptive-<제안>-<용도>.png`). 컨셉 합성도 파일 이름에 `concept-<컨셉>-<용도>.png`를 남겨 대표·추가 이미지를 구분할 수 있게 했다(허용 용도에 "추가"가 없고 모두 `MAIN`으로 저장되는 구조라서).

### 8-3. 실제 확인(방수 생리팬티 상세 조각에서 오린 분홍·회색·검정)
| 제품 | 상위 제안(대비) | 관찰 |
|---|---|---|
| 분홍 | 깊은 대비(청록) 100, 짙은 회색 100, 선명한 청록 86, 보색 파스텔 41 | 밝은 제품에 어두운·선명한 배경이 가장 돋보인다 |
| 회색 | 깊은 대비(갈색) 100, 짙은 회색 100, 선명한 황금색 85 | 무채색 제품은 따뜻한 색 배경이 대비를 만든다 |
| 검정 | 이웃 색 파스텔 100, **선명한 녹색 100**, 보색 파스텔 100, 옅은 회색, 스포트라이트 | 어두운 제품은 밝은 배경이 좋고 선명한 색도 선택지로 나온다 |

→ 같은 흰 배경 컨셉을 모든 제품에 쓰는 것이 아니라 **제품마다 다른 배경 묶음**이 나옴을 확인했다. 단, 다음 한계가 있다.

### 8-4. 한계(솔직한 기록)
- **소스 해상도**: 상세 조각(780px)에서 오린 제품은 작아서 캔버스를 채우려면 2배 안팎 확대가 필요하다(화질 저하 가능). 원본 해상도 소스(상품 페이지의 대표 이미지 원본, 또는 사용자가 촬영한 사진)가 훨씬 낫다.
- **가장자리**: 배경 제거 결과의 가장자리에 옅은 번짐이 있어 어두운 배경에서 약하게 보일 수 있다(알파 가장자리 보정은 후속 과제).
- 점수는 **색 차이** 기준이다. 구도·분위기·브랜드 취향은 반영하지 않으므로 사용자가 최종 선택한다.
- 사용권: 공급처 이미지로 만든 이미지는 `RIGHTS_UNVERIFIED`를 그대로 물려받는다 — 위저드 3단계에서 사용자가 확인해야 등록에 쓸 수 있다.

## 9. 화면: 위저드 3단계 "배경 고르기" (2026-10-14)

| 단계 | 화면 동작 |
|---|---|
| 열기 | 버튼을 누르면 카드 아래에 패널이 열린다(다시 누르면 닫힘). 서버가 제품 색을 분석(`/media-assets/background-suggestions`, 읽기 전용)하고 분석한 제품 색을 점으로 보여 준다 |
| 고르기 | 용도(**추가·상세: 다양한 배경** / **대표: 흰 배경만**), 그림자·작은 사진 확대(최대 2배) 옵션, 제안 타일(미리보기 색, 이름, 대비 점수, 이유, **묻힘 경고/그림자 팁**). "다른 색조 보기"로 같은 제품의 다른 색조 묶음(12종 순환) |
