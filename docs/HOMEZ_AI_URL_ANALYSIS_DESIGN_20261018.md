# URL 상품 분석 · 단가 · 이익 계산 AI 도우미 설계 (Phase E)

작성: 2026-10-18 · 상태: **설계 초안(구현 전, 승인 대기)** · 외부 호출 0 · Migration 0

## 1. 목표

사용자가 상품 URL을 넣으면 AI가 페이지를 읽어 **상품을 해석**하고, HOMEZ가 **단가와 이익을 계산**해 "등록할 만한가"를 근거와 함께 보여 준다.
등록 승인·가격 확정·쿠팡 전송은 하지 않는다(사용자 몫).

## 2. 지금 있는 것 (실제 코드 확인)

| 기능 | 위치 | 상태 |
|---|---|---|
| URL 읽기(제목·설명·가격 문구·이미지·고시, 온채널은 공식 API로 공급가·배송비) | `product_import/service.py::search` | 있음. SSRF 방어·크기 제한 포함 |
| 이익 계산(판매가 제안, 마진율, 손익분기, 최소 18% 판정) | `product_import/service.py::propose_margin`, `marketplace_listing/margin_calculator.py` | 있음. 순수 Decimal 계산 |
| 후보·위저드 초안 생성 | `product_import/service.py::create_draft` | 있음 |
| 글 초안 AI(Claude) | Phase B (`ai_draft_service.py`) | 구현·시험 완료, 실제 호출 전 |
| **빠진 것** | 옵션·수량·용량 해석과 **단가 환산**, 카테고리 추정, 수수료율 근거, 위험 신호, "왜 이 판단인가" 설명, 한 번에 이어지는 흐름 | 없음 — 지금은 사람이 하나씩 입력 |

현재 한계: 수수료율은 **10.8% 가정값**이고(코드가 "가정"이라고 경고함), 옵션 구성(예: 3개입×200ml)을 사람이 읽어 원가를 환산한다.

## 3. 핵심 원칙 (금융 정합성)

1. **AI는 돈을 계산하지 않는다.** AI는 페이지에서 *사실을 뽑고 해석*만 하고, 금액·단가·마진은 **기존 계산기 코드**가 계산한다.
2. **AI가 뽑은 숫자는 근거 인용이 있어야 한다.** 각 값에 페이지 원문 조각(`evidence`)을 붙이게 하고, 서버가 그 조각이 실제 페이지 글에 있는지·숫자가 그 조각에 있는지 확인한다. 없으면 버린다(고쳐 쓰지 않음).
3. **공식 값이 AI 해석보다 우선**한다. 온채널 공식 API의 공급가·배송비가 있으면 그 값을 쓰고, AI 해석과 다르면 경고만 한다.
4. **모르는 비용은 0으로 두지 않는다.** 원가·배송비·수수료율이 확정되지 않으면 계산을 막고 "무엇이 필요한지"를 알려 준다(`missing_cost_fields`, 기존 규칙과 동일).
5. **가정은 가정이라고 표시한다.** 가정값(수수료율, 반품 예비율, 포장비)은 결과 카드에 별도 줄로 나열한다.
6. 판정(등록 가능 / 보류 / 비추천)은 **규칙**이 낸다: 마진율 ≥ 회사 목표·최소 18%, 필수 값 확인 완료, 높은 위험 신호 없음. AI는 판정 *이유 설명 글*만 쓴다.

## 4. 흐름

```
URL 입력
 ① 읽기(기존 search, AI 없음)        → 제목·설명·가격 문구·옵션 문구·고시·온채널 공급가
 ② AI 해석(Claude 1회, 사용자 클릭)   → 구조화 JSON(아래 §5), 값마다 evidence
 ③ 서버 검증(결정적)                  → evidence 실재·숫자 일치·금지 표현·범위 확인, 탈락 항목 사유 표시
 ④ 계산(기존 계산기)                  → 판매 단위당 원가, 환산 단가, 판매가 제안(목표 마진 3단계), 마진율, 손익분기
 ⑤ 판정(규칙)                         → 등록 가능 / 보류(부족한 값 목록) / 비추천(이유)
 ⑥ 사용자가 선택                      → "후보·위저드 초안 만들기"(기존 create_draft) — 이때 분석 결과를 후보 근거로 저장
```

사용자가 누르는 단계: 분석 시작 → (값 확인·수정) → 초안 만들기. 8단계 승인과 쿠팡 전송은 기존 그대로 별도.

## 5. AI가 돌려주는 구조 (검증 대상)

- `product`: 상품 종류, 브랜드/제조사(없으면 null), 판매 구성 — 예: `{pack_count: 3, unit_volume: "200ml"}` (**각 값에 evidence**)
- `cost_facts`: 공급가(VAT 포함 여부), 배송비 조건, 최소 주문 수량 — 각 evidence 필수
- `category_candidates`: 쿠팡 카테고리 후보 이름 1~3개(코드는 만들지 않음 — 코드는 기존 카테고리 조회로 사용자가 확정)
- `risks`: 코드 목록 + 한 줄 이유 — 브랜드/상표(IP), KC 인증 대상 가능성, 어린이·식품·화장품 등 규제 분류, 금지 품목, 파손·부피·무게 배송비 위험, 반품 곤란
- `unknowns`: 페이지에 없어서 모르는 것(사용자에게 물어볼 목록)
- `rationale`: 판단 설명 글(검증 통과 후 표시만, 판정에 영향 없음)

## 6. 계산 (코드, AI 없음)

- 판매 단위 원가 = 확정된 공급가 ÷ 구성 수량(올림·반올림 규칙은 기존 계산기와 동일), 배송비·포장비·반품 예비율 반영
- **환산 단가**(예: 100ml당, 1개당) = 판매가 ÷ (수량 × 용량) — 용량·수량이 검증을 통과한 경우에만 표시
- 판매가 제안 = 기존 `derive_sale_price_for_margin_rate`(목표 18%/25%/30% 3안, 10원 단위 올림)
- 결과: 마진액·마진율·손익분기·최소 마진 충족 여부, 시나리오(수수료율 ±, 반품률 ±) 민감도 표
- 수수료율은 **플랫폼 수수료 출처(§6-1)** 에서만 받는다. 출처가 없으면 계산하지 않는다(10.8% 가정 폐기).

### 6-1. 플랫폼 수수료 출처 (사용자 결정 1, 2026-10-18)

쿠팡 전용이 아니므로 플랫폼마다 같은 인터페이스(`ChannelFeeSource`)를 둔다. 등록 전에 아래 순서로 수수료율을 구하고, **출처 등급을 결과에 표시**한다.

1. `PLATFORM_API` — 플랫폼 공식 API가 카테고리별 수수료를 주면 그 값(읽기 호출, 허용 센터 목적 `FEE_LOOKUP`, 조회 시각 기록)
2. `USER_CONFIRMED` — API가 수수료를 제공하지 않는 플랫폼은 사용자가 카테고리·플랫폼별로 직접 확인해 저장한 값(저장 시각·입력자 기록)
3. 둘 다 없으면 **`FEE_UNKNOWN` — 이익 계산과 판정을 보류**하고 필요한 값을 알려 준다.

**미확인 사실**: 쿠팡 공개 API(카테고리 메타데이터 포함)가 수수료율을 주는지, 다른 플랫폼은 어떤지는 아직 공식 문서로 확인하지 않았다(코드·문서에 근거 없음). 구현 첫 단계에서 **공식 문서 읽기 확인(읽기 전용, 사용자 승인 필요)** 으로 확정하고, 제공하지 않으면 2번 경로만 쓴다. 문서에 없는 호출은 만들지 않는다.

### 6-2. 부가세(VAT)와 입력 방식 (사용자 결정 4)

- **URL 모드**: AI가 페이지에서 VAT 표기("부가세 포함/별도", 면세 표기)를 찾아 evidence와 함께 돌려준다. 표기가 없으면 `VAT_UNKNOWN` → 판정 보류, 사용자에게 선택을 요청한다(자동 가정 금지).
- **직접 입력 모드**(URL 없이 판매자가 직접 등록): 원가 입력 시 **VAT 포함/별도/면세 선택이 필수**이고, 선택 전에는 계산하지 않는다.

### 6-3. 판정 기준 (사용자 결정 3 승인)

기준 마진율 = max(회사 설정 `min_target_margin_rate`, 18%). 경쟁 가격은 사용하지 않고(결정 2) **원가 + 설정 마진율**만으로 판매가 제안·판정한다. 경쟁 가격 분석은 추후 마케팅 AI와 협의 후 별도 설계.

## 7. 비용·안전 통제 (Phase B 재사용)

- 월 한도·단가 설정, 승인 센터 허용(새 목적 `AI_ANALYSIS`, 횟수형만), 호출별 사용 기록(`AI_ANALYSIS_USAGE`)
- 입력 크기 제한: 페이지 글 최대 약 1만 2천 자로 자르고, 호출 전 최악 추정액을 월 한도와 대조
- **프롬프트 주입 방어**: 페이지 글은 `<page_data>` 안의 자료로만 취급, AI에게 도구·행동 권한이 없다(JSON만 반환), 출력은 스키마·evidence 검증을 통과해야 쓰인다
- 보내지 않는 것: 우리 판매가·원가·마진·연락처·주문 정보(AI는 *페이지 사실*만 받는다. 계산은 서버에서)
- 로그인이 필요한 도매 사이트·JS로만 그려지는 페이지는 읽지 못할 수 있다 → 경고하고, "페이지 글 붙여넣기" 보조 입력을 제공한다(자격증명은 쓰지 않는다)

## 8. 저장

새 테이블 없음. 분석 결과는 `ProductCandidateEvidence`(append-only, 기존 `notes_payload` 방식)에 `AI_ANALYSIS:` 접두로 저장해 초안 생성 후 추적·재현할 수 있게 한다(모델명·토큰·비용 포함). 초안 만들기 전의 분석은 저장하지 않고 화면에만 둔다.

## 10. 위험과 한계

- AI는 페이지의 **진위**(가짜 가격, 오래된 정보)를 알 수 없다. 공급처 공식 API가 없는 URL은 가격이 *페이지 표시값*일 뿐이다 → 결과 카드에 출처와 읽은 시각을 표시한다.
- 시장 가격·경쟁 강도·판매량은 **알 수 없다**(외부 데이터 없음). AI가 추측해 말하지 않도록 `unknowns`로 처리한다.
- 수수료율 근거가 없으면 이익 계산은 "가정 기반"이다 → 표시 고정.
- 위험 신호(상표·인증)는 *가능성 알림*이지 법적 판단이 아니다.

## 11. 결정 기록 (2026-10-18)

1. 수수료율: 등록 전 플랫폼 API로 확인 — 쿠팡만 가정하지 않는다. API 제공 여부는 공식 문서 확인 전까지 **미확인**(§6-1). → 구현 단계 **E0(공식 문서 읽기 확인)** 추가
2. 경쟁 가격 분석: **이번 범위 제외**(추후 마케팅 AI와 협의). 원가 + 최소 18%(회사 설정 중 높은 값)로 진행.
3. 판정 기준: **승인**(§6-3).
4. VAT: URL은 페이지 표기 확인, 직접 등록은 필수 기재(§6-2).

## 13. E0 결과 — 쿠팡 수수료 API 확인 (2026-10-18, 공식 문서 읽기 전용)

- **카테고리 메타정보 조회**(`…/meta/category-related-metas/display-category-codes/{code}`): 응답 필드는 `isAllowSingleItem`, `attributes`, `noticeCategories`, `requiredDocumentNames`, `certifications`, `allowedOfferConditions`이며 **수수료·수수료율 필드가 없다.**
- **상품 조회**(`…/seller-products/{sellerProductId}`): 문서 필드 표에는 수수료 항목이 없고, **응답 예시에만** `items[].saleAgentCommission`(예시값 9)이 보인다. 설명·형식이 문서화돼 있지 않고, 이미 등록된 상품(상품 번호 필요)에서만 읽을 수 있다 → **등록 전 수수료 확인 수단이 아니다.** 등록 후 실제 적용 요율 대조용으로는 쓸 수 있으나 비문서화 필드라 신뢰 근거로 삼지 않는다(실제 응답 확인은 별도 승인 시 읽기 1회).
- **결론**: 쿠팡은 등록 전에 수수료율을 API로 확인할 수 없다 → `PLATFORM_API` 경로는 쿠팡에는 비어 있고, **`USER_CONFIRMED`(WING에서 사용자가 확인해 저장) 또는 `FEE_UNKNOWN`(계산 보류)** 만 쓴다. 따라서 구현 범위에서 **허용 목적 `FEE_LOOKUP`은 만들지 않는다**(호출할 문서화된 API가 없다). 다른 플랫폼은 아직 연동돼 있지 않아 확인하지 않았다(연동 시점에 같은 방식으로 문서 확인).
- 출처: 쿠팡 Open API 공식 문서(developers.coupang.com, 카테고리 메타정보 조회 / 상품 조회).
