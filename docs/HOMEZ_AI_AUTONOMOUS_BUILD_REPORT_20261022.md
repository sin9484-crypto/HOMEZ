## 공통 제작 기준 (모든 단계)

1. **AI는 읽고 설명한다 → 결정적 코드가 계산한다 → 규칙이 판정한다 → 사람이 확인한다.** 돈·기한·금액·권리 판정은 AI가 하지 않는다.
2. **모르는 것은 정상이 아니다.** 읽지 못한 값·모르는 코드는 `unknown`/"확인 필요"로 남기고 통과시키지 않는다(fail-closed).
3. **읽기와 쓰기를 분리한다.** 점검·미리보기는 DB·파일에 쓰지 않고(시험으로 행 수 불변을 확인), 외부 호출이 있는 경로는 별도 POST + 확인.
4. **기존 구조를 재사용한다.** 새 규칙을 따로 만들지 않고 기존 코드(`describe_health`, `has_current_acknowledgement`, `_persist_generated_asset`)의 판정을 그대로 쓴다.
5. **시험 방식:** 경계값·거절 시험·읽기 전용·멱등, **변이 검사**(규칙을 일부러 망가뜨려 시험이 잡는지 확인, 파일 해시로 원복 검증), 소스 수준 시험 + Node에서 실제 화면 함수 실행, 격리 서버(임시 DB·가짜 제공자)에서 실제 경로 확인.
6. **문서와 상태 기록:** 단계마다 이 문서와 `docs/HOMEZ_PROJECT_STATE.md`에 사실만 추가한다. 못 돌린 시험·못 확인한 것은 사유와 함께 적는다.

## 0. 반영 A — 시스템 점검(T1·T2) 확장: 감시가 조용히 멈추는 경우

**왜:** 2026-10-21 점검에서 주문 자동 감지가 승인 센터 허용 만료로 약 79시간 멈춰 있었는데, 앱 화면은 "일이 없다"와 "감시를 못 한다"를 구분하지 못했고 사람이 점검 스크립트를 돌려서야 알았다.

**구현한 기능**
- `diagnostics/health_summary.py`(순수 규칙): 새 점검 `DETECTION`(신규 주문 자동 감지)·`READS`(읽기 허용).
  - 감지: 운영 화면이 이미 쓰는 `describe_health` 코드를 그대로 옮긴다 — 허용 없음 WARN, 오류 모드 FAIL, 일시 중지·실패·연결 정보 확인 불가·환경 제한 WARN, 꺼 둠 INFO, 정상으로 보여도 마지막 시도가 30분 넘게 지났으면 `DETECTION_STALE` WARN.
  - 읽기 허용(주문·배송 / 반품·문의·정산 / 상품 상태): 지금 쓸 수 있으면 통과, 전에 있었는데 못 쓰면 WARN, 한 번도 허용한 적이 없으면 INFO.
- `diagnostics/health_service.py`(읽기 전용 수집): 최근 감지 상태·기능 모드·허용 행을 읽는다. `ExternalCallPolicyService.authorize`는 만료 표시·요청 생성(쓰기)을 하므로 **쓰지 않고** 같은 "쓸 수 있음" 판정을 읽기만으로 다시 구현했다.
- `diagnostics/health_ai_service.py`(T2): 새 코드 8개의 고정 뜻(`CODE_MEANING`)과 AI에 보내는 허용 목록 사실(경과 분, 목적 이름 3종)을 더했다.
- 쉬운 보기(`easy_view.js`·`easy_texts.js`): 오늘 브리핑 "점검 필요" 줄에 새 문구(한국어·영어).

**제작 기준**
1. **모르는 것은 정상이 아니다** — 상태를 읽지 못했거나 모르는 코드면 `unknown`, 통과로 세지 않는다(기존 T1 원칙).
2. **새 규칙을 만들지 않는다** — 감지 상태 판정은 이미 있던 `describe_health` 하나를 단일 출처로 재사용(코드 두 벌이 어긋나지 않게).
3. **읽기만 한다** — 점검이 허용 상태를 바꾸면 안 된다(만료 표시·요청 생성 없음). 시험이 행 수 불변·ACTIVE 상태 유지로 확인한다.
4. **조치는 사용자가 하는 일로만** — T2 설명은 "승인 센터 허용 다시 주기·앱 켜기"처럼 판매자가 하는 일로만 안내하고 앱이 대신한다고 쓰지 않는다(기존 T2 검증이 약속 표현을 버린다).
5. **한 번도 허용한 적 없는 것은 INFO** — 새 설치 환경에 영구 경고를 띄우지 않는다. 전에 있었다가 끝난 것만 WARN.
6. **권장안 선택(질문 대신):** 마지막 시도 경과 기준은 감지 주기(5분)의 6배인 30분. 주문·배송 읽기 허용에는 "마지막 호출 경과" 점검을 넣지 않았다 — 추적 대상이 0건이면 호출 자체가 없어 정상 상태가 거짓 경고가 되기 때문이다(🔴 별도 근거가 생기면 추가).

**시험·검증**
- 신규 `test_health_detection_checks` 33건(규칙 경계·읽기 허용 판정 12가지·읽기 전용 증명·T2/쉬운 보기 문구 짝), 기존 `test_health_summary`(19)·`test_health_ai_service`(29)·`test_health_ai_ui`·`test_easy_*` 통과. 기존 시험은 정상 스냅샷 고정물에 새 키를 더하고 "통과 코드 집합"에 두 코드를 더했으며, 의미 있는 단언을 약화하지 않았다. `test_every_warn_or_fail_code_has_a_fixed_meaning`은 표 기반 코드도 세도록 **강화**했다.
- 변이 검사 27건: 25건은 첫 실행에서 감지, 2건은 변이 패턴이 파일과 맞지 않아(줄바꿈 형식) 패턴을 고쳐 재실행해 감지 — 27건 전부 감지.

**한계·미확인**

## 1. 이미지 AI — 참고 사진으로 만들기

앞서 R1(요청 명세, 커밋 `f80c89a`)을 만들었고, 이번에 서비스·API(R3a)와 화면(R3b)을 연결했다. **실제 이미지 생성 API는 연결하지 않았다 — 시연용(FAKE) 제공자만 쓴다.**

### R3a — 서비스·API
**구현한 기능**
- `media_asset/reference_generation_service.py`(신규): `preview`(쓰기 없음)·`generate`(FAKE 제공자 실행 → 파생 자산 저장).
- API 3개(`media_asset/router.py`·`schema.py`): `GET /media-assets/reference-generation/presets`, `POST …/preview`, `POST /media-assets/reference-generation` — 전부 `admin_guard`.

**제작 기준**
1. **회사 범위** — 다른 회사 자산은 "없음"과 같은 응답(404).
2. **권리** — 자산의 `rights_status`와 이 회사의 *현재* 확인 기록(이미지가 바뀌면 자동 무효)을 규칙에 넘긴다. 거부(RIGHTS_DENIED)는 항상 차단. 결과는 참고 사진의 권리 상태를 **물려받기만** 하고 격상하지 않는다(위저드는 확인된 자산만 선택할 수 있어 그대로 이어진다).
3. **대표(MAIN)는 서비스가 강제한다** — `confirmed_main`이 정확히 `True`가 아니면 실행 전에 거절하고 **작업 행도 남기지 않는다**(화면에만 의존하지 않음).
4. **멱등** — 같은 입력은 같은 계획 지문·같은 바이트 → 같은 자산으로 합쳐진다(반복 실행해도 자산이 늘지 않고 작업 기록만 남는다).
5. **기록** — 작업(`ImageGenerationJob`, operation REFERENCE_GENERATION)에 계획 요약(사진 바이트 제외)을 남기고 결과마다 행을 남긴다. 검수 전이라 결과의 safety는 `UNKNOWN`(통과라고 기록하지 않음). "AI 생성" 표기는 이미지 픽셀이 아니라 작업 기록·파일 이름(`aigen-…`)·응답에만 둔다(워터마크 금지, 사용자 지시).
6. **Migration 없음** — 기존 컬럼만 사용.
7. **실패 처리** — 제공자 오류·일부 실패·차단 항목은 기록하고 저장하지 않으며, 예상치 못한 오류는 상세를 노출하지 않는다.

**시험·검증** — 신규 `test_reference_generation_service` 33건(미리보기 쓰기 없음, 권리·범위, 생성·승계·기록·멱등, 대표 확인, 제공자 오류·부분 실패·차단, 경로·스키마·권한). 변이 21건: 19건은 첫 실행에서 감지, 1건은 패턴을 고쳐 재실행해 감지, 1건(제공자가 FAILED 항목에 바이트를 붙여 보낸 경우를 저장하지 않는지)은 시험을 보강한 뒤 감지 — 21건 전부 감지. **격리 서버(임시 DB·임시 미디어 폴더·가짜 제공자)에서 실제 HTTP로 18개 항목 전부 통과**(무토큰 401, 권리 경고 전 400, 확인 후 미리보기·실행, 반복 시 같은 자산, 대표 확인 전 400·후 200, 개수 초과 422, 없는 자산 404, 같은 소유자 목록에 3장).

### R3b — 위저드 화면
**구현한 기능** — 이미지 단계의 원본 사진 카드에 "참고 사진으로 만들기" 버튼과 패널(`console.js`: `lwOpenReferencePanel` 외 헬퍼 7개, 한국어·영어 문구 35개씩).
- 용도(추가·상세·대표), 배경·포즈 각각 최대 3개 선택, 장수(조합 수 이하·최대 6), 미리보기(장수·예상 비용·경고·검수 항목), 만들기.
- 항상 보이는 안내: 시연용 생성기라 샘플 이미지, 워터마크·글자 없음과 표기는 이미지 밖, 윙 '이미지 자동 수정 동의' 확인.
- 사용권: 금지 사진은 막고, 미확인 사진은 경고 확인 체크(확인 기록 POST) 뒤에만 진행.
- 대표: 기본 선택을 **흰 배경 단색 스튜디오 + 원본 포즈**로 두고, 반려 위험 경고와 최종 확인 체크를 보여 주며 체크 전에는 요청을 보내지 않는다. 미리보기는 최종 확인 없이 볼 수 있지만 `confirmed_main=true`를 보내지 않는다.

**제작 기준** — 화면이 먼저 알려 주되 서버가 같은 규칙으로 다시 막는다(이중 방어); 서버가 준 글은 모두 이스케이프; 한도(3개·6장)는 선택 단계에서 막아 사용자가 이유 없이 거절당하지 않게 한다; `hidden` 속성으로 버튼을 숨기지 않는다(기존 `.btn` 결함 회피); 끝나면 목록을 처음 상태로 다시 그리고 맨 위에 만든 장수를 알린다.

**시험·검증** — 신규 `test_reference_generation_ui` 23건(Node에서 실제 화면 함수 실행 + 소스 배선·문구 짝). **실제 브라우저에서 실제 서버에 대고 클릭 검증**: 경고 확인 전 만들기 → 요청 없이 오류, 확인 체크 → 확인 기록 POST, 미리보기, 배경 4번째 선택 무시, 2장 생성 → 배너, 대표 선택 → 기본값·경고·확인 칸, 사용권 오류가 대표 확인보다 먼저, 대표 확인 없이 실행 → 요청 없이 오류, 확인 후 실행 → 성공. (위저드 안에서 카드까지 가는 전체 경로는 전용 시드가 없어 패널 함수만 실제 DOM에서 구동했다 🔴.)

**한계** — 실제 생성 제공자 없음(정책 I0 미확인·가드 허용·비용 승인 필요), 검수 4항목은 자동 검사가 없는 "요구 선언", 시연용 결과는 32×32 샘플 이미지, 위저드 카드 안에서의 시각 확인 미실시.
**변경 파일** — `media_asset/{reference_generation_service(신규),router,schema}.py`, `app/web/{console.js,i18n/ko-KR.js,i18n/en-US.js}`, 시험 3개(신규).

## 2. 상품 서칭 AI — S3 (공급처 비의존 구조)

**구현한 기능**
- `supplier/offer_rules.py`(신규, 순수): 공급처 이름을 모르는 공급 조건 평가 — 최저 판매가(마진 하한), 마진, 배송비 비중, 반품 부담, 위탁·최소 주문·가격 공개 여부로 `READY/HOLD/EXCLUDE`와 이유를 낸다. `rank_offers`는 최대 50건을 결정적 순서로 정렬.
- `supplier/offer_provider.py`(신규): 공급처 **읽기 전용 어댑터 경계**. 지금은 `FAKE`·`MANUAL`(사용자 직접 입력)뿐이고, 오너클랜·도매매는 "아직 만들지 않았다"고 거절한다.
- `POST /product-import/supplier-offers/rank`(`product_import/router.py`·`schema.py`): 위저드 생성 권한, AI·바깥 호출·저장 없음. 응답에 쓴 가정값과 "수수료율은 가정(의류 실제 수수료율 미확인)" 안내를 함께 낸다.

**제작 기준**

1. **원본은 건드리지 않는다.** 결과는 항상 새 파생 자산(`source_asset_id`=원본)이다.
2. **권리는 만들 때 한 번만 물려받고 격상하지 않는다.** `_persist_generated_asset`이 바이트가 같으면 기존 자산을 돌려주는데, 그때 다른 출처의 기존 자산의 출처·권리·파일 이름을 덮어쓰면 권리 격상(RIGHTS_UNVERIFIED → VERIFIED)이 될 수 있어 `adopt_derived`가 "새로 생긴 GENERATED이고 출처가 비어 있을 때만" 연결하고, 같은 출처면 그대로, 다르면 건드리지 않고 알린다(시험으로 고정).
3. **범위·한도를 서버가 다시 막는다** — 둘 다 0이면 거절(할 일이 없음), 범위·정수·참/거짓 값 거절(`strict`), 장수 20장, 다른 회사 자산은 NOT_FOUND, 사용 금지 사진은 SKIPPED.
4. **같은 입력은 같은 결과**(결정적) → 반복해도 자산이 늘지 않는다(멱등).
5. 이미지에 글자·워터마크를 넣지 않는다.

**시험·검증** — `test_batch_adjust` 20 · `test_batch_adjust_service` 23(스키마 값 거절 보강 포함) · `test_batch_adjust_ui` 16건. 변이 34건 중 33건 첫 실행에서 감지, 1건(`strict=True` 제거 — 문자열 `"5"`·`True`가 정수로 통과) 시험 보강 후 감지.

## 1-3. 이미지 AI — 컨셉별 독립 작업 I2 · 장면 배경 I3 · 카테고리 추천

**왜:** 컨셉마다 허용 수준·검사 항목을 명세로 가진 구조(I1, `e97e610`)를 실제 작업으로 연결하고, 단색·그라데이션뿐이던 컨셉에 **질감·조명 장면**을 더하며, 상품 분류에 맞는 컨셉을 추천한다.

**구현한 기능**
- `media_asset/scene_backgrounds.py`(신규, 순수): 코드가 그리는 장면 배경 5종 — 린넨·나무결·종이(질감)와 따뜻한/차가운 스포트라이트(조명). 같은 입력이면 같은 그림(고정 시드), 질감 세기는 상한이 있어 제품이 묻히지 않는다.
- `composition.py`: `BackgroundKind.SCENE` 추가(`scene_code`), `image_concepts.py`: **L1 장면 컨셉 5종**(`LINEN_NATURAL`·`WOOD_WARM`·`PAPER_SOFT`·`SPOTLIGHT_WARM`·`SPOTLIGHT_COOL`)과 명세 검증 규칙(L0에 장면 금지·알려진 장면 코드·장면 종류 일치·색 규칙). 처음 6종은 그대로다.
- `media_asset/concept_inspection.py`(신규): 컨셉마다 **검사를 숫자로** 돌린다 — 제품 보존(제품 픽셀이 그대로인 비율 ≥ 0.99), 배경 대비(≥ 1.3, 미달은 경고), 대표 규격(정사각·≥1000px·흰 배경), 글자 없음(구조상 없음), 정책 적합(**검사 수단 없음 → NOT_CHECKED**).
- `media_asset/concept_run_service.py`(신규) + `POST /media-assets/concept-runs`: 누끼 한 장으로 컨셉 최대 6개를 **각각 따로** 만든다. 상태 `CREATED/REUSED/CHECK_FAILED/SKIPPED/FAILED`. 검사에서 FAIL이면 **저장하지 않는다**.
- `media_asset/concept_recommendation.py`(신규, 규칙) + `GET /media-assets/concept-recommendations`: 상품 분류 글을 명세의 `good_for`·`avoid_for`와 포함 관계로 비교해 어울리는 컨셉을 앞으로, 피해야 할 컨셉은 **숨기지 않고 이유와 함께** 따로 보여 준다.
- 화면: 누끼(GENERATED) 카드의 "컨셉으로 여러 장 만들기" 패널(용도·분류 입력·추천·최대 6개 선택·컨셉별 결과와 검사 내용, 한국어·영어 문구 51개씩).

**제작 기준**
1. **제품은 다시 그리지 않는다** — 합성만 하고, 제품 픽셀이 그대로인지를 검사가 숫자로 확인한다. 이 라운드의 컨셉은 전부 로컬 Pillow 합성(L0·L1)이라 **외부 접촉·비용이 없다**. 생성형(L2) 컨셉은 만들지 않았다.
2. **컨셉마다 독립** — 한 컨셉의 건너뜀·검사 실패·합성 오류가 다른 컨셉을 막지 않는다. 합성 오류의 내부 메시지는 응답·작업 기록에 노출하지 않는다.
3. **검사하지 못한 것은 통과가 아니다** — 정책 적합은 NOT_CHECKED, 글자 없음은 BY_CONSTRUCTION(사진을 들여다본 검사가 아님)으로 그대로 보인다. 화면은 "쿠팡 이미지 정책 적합은 자동 확인하지 못한다"를 항상 알린다.
4. **대표(MAIN)는 흰 배경 컨셉만** — 장면 컨셉은 대표에 쓸 수 없다(명세·서비스·화면에서 모두).
5. **추천은 권고일 뿐** — 규칙이 정하고(AI 없음) 모든 컨셉을 사용자가 직접 고를 수 있다. 분류를 모르면 추천 없이 기본 순서(`category_known=False`)로 알린다. `good_for`·`avoid_for`는 설명에서 이끌어 낸 **보수적 기본값**이며 법무·시장 검증을 거치지 않았다(🟡).
6. 멱등·원본 보존·권리 승계는 R2와 같은 `derived_assets.adopt_derived`. 같은 누끼·컨셉·용도면 같은 자산.
7. **권장안 선택(질문 대신):** 장면 컨셉의 어울림 목록은 보수적으로 적었고, 기준값(제품 보존 0.99·대비 1.3·질감 세기)은 시험으로 확인된 값이 아니라 **초기 기본값**이다(🟡 실제 사진으로 조정 필요).

**시험·검증** — `test_scene_backgrounds` 17 · `test_concept_inspection` 21 · `test_concept_run_service` 31 · `test_scene_concepts` 16 · `test_concept_ui` 14건, 기존 I1 시험(`test_image_concept_spec`·`test_media_image_concepts`)은 "6종 고정"을 "앞 6종 고정 + 총 11종"으로 갱신했을 뿐 의미 있는 단언을 약화하지 않았다. 변이 검사 100건: 장면·검사 25건(21건 첫 실행 감지, 1건 시험 보강 후 감지, 3건은 **동등 변이·조정용 값** — 크기에 `True`를 넣어도 범위 검사에 걸림 / 투명도 없는 제품은 비율이 0이라 `pixels > 0`이 중복 / 나무결 혼합 비율 0.45는 시험으로 고정하지 않은 조정값 🟡), 컨셉 작업·추천·API 29건(24건 감지, 5건 시험 보강 후 감지 — 저장 오류 때의 되돌림·일부만 맞는 분류 글·힌트 60자 경계·API가 용도를 넘기는지), 명세·합성 17건(16건 감지, 1건 오류 문구 단언 보강), 화면 29건(26건 감지, 2건 보강 후 감지, 1건 동등 변이 — 상태 글은 번역표에서 온 값이라 이스케이프 유무가 달라도 출력이 같음).

## 5. 마케팅 AI — M4-full (제안과 성과 연결)

**구현한 기능** — `ai_learning/suggestion_outcomes.py`(순수): **채택한 제안**(상품명·검색어·가격)을 쿠팡 옵션 ID에 연결해 제안일 **전·후**의 판매·반품을 나란히 보여 준다(하루 평균 판매 수량 포함).
**제작 기준**
1. **"맞았다/틀렸다"를 판정하지 않는다.** 항상 `causal: False` — 계절·할인·광고·경쟁을 가를 수 없다. 시험이 "적중·성공·효과가 있" 같은 표현이 출력에 없음을 확인한다.
2. **표본이 작으면 판단하지 않는다** — 전·후 어느 쪽이든 판매 주문 10건 미만이면 `INSUFFICIENT`.
3. 채택하지 않았거나(`adopted`가 정확히 True가 아님)·옵션 연결 없음·날짜 읽기 불가·전/후 기간 없음은 이유를 달아 **평가하지 않는다**. 제안일 당일은 '후'. 같은 옵션에 제안이 여럿이면 겹침 경고.
4. 집계는 기존 `marketing_outcomes.summarize`를 그대로 쓴다(중복 제거·부호 처리 동일).
5. **저장은 아직 없다** — 제안 기록 테이블의 **Migration 초안**만 `docs/migration_drafts/20261023_00_create_marketing_suggestion_record_schema.sql.draft`에 두었다. `migrations/` 폴더에 두면 앱 시작 때 승인 대기 Migration이 되므로 **일부러 밖에 뒀다**(Model·적용은 사용자 승인 후). 시험이 임시 SQLite에서 초안을 실행해 열·제약·색인을 확인하고, 두 번째 적용 실패와 rollback 주석 동작까지 확인한다. **실제 DB에는 적용하지 않았다.**
**시험·검증** — `test_suggestion_outcomes` 19건. 변이 20건 중 16건 첫 실행에서 감지, 2건 시험 보강 후 감지, 2건은 **동등 변이**(도달 불가능한 경계)다.
