  행(id=1)의 `failure_detail` 정정(별도의, 이미 성공한 명령)만 반영돼

## ③ 가격 필드 의미와 등록 준비표

### 3-1. "옵션 가격 확인"과 "공급가 미확인"의 차이(기존 자료로 해소)

`docs/HOMEZ_ONCHANNEL_OPENAPI_FINDINGS_20260908.md`의 기존 확정 사실
("온채널 용어로 **판매사(seller) = HOMEZ**, 온채널의 공급망에서 상품을
사서 자기 채널에 파는 쪽")과 `docs/HOMEZ_ONCHANNEL_OPENAPI_SPEC_
20260908.json`의 공식 필드 정의를 대조해 이 둘의 차이를 확정한다:

| 엔드포인트 | 필드 | 라벨(공식) | 의미 |
|---|---|---|---|
| `GET seller/product/{code}`(19차에서 실제 호출한 것) | `option_price` | 판매가 | 온채널이 "판매사"(=HOMEZ)에게 공급하는 가격 — **HOMEZ 입장에서는 매입원가로 기능할 가능성이 높다**(온채널이 파는 쪽, HOMEZ가 사는 쪽이라는 역할 정의에 근거한 해석이지, "공급가"라는 이름의 필드가 직접 있는 것은 아니다) |
| 〃 | `disc_price` | 최종 준수가 | 별도 필드 — 실제 청구 시 `option_price`를 대체/조정하는 값인지는 **이번 응답에서 캡처하지 못해 미확인**(아래 3-3 참고) |
| 〃 | `recom_cus_price` | 권장소비자가 | 소비자 권장가 — `option_price`와 별개 필드로 명확히 분리돼 있어, `option_price`가 "소비자가"가 아니라는 근거로도 쓸 수 있다 |
| `GET supplier/product/{code}`(HOMEZ가 호출하지 않는, 반대 방향 API) | `onch_price` | 공급가 | 이 필드가 문자 그대로 "공급가"이지만, **HOMEZ 계정은 "판매사" 역할이라 이 엔드포인트 자체를 쓸 권한·용도가 없다**(기존 확정 사실 재인용) |

**결론**: "옵션 가격(`option_price`) 확인됨"과 "공급가 미확인"은 모순이
아니다 — `option_price`가 HOMEZ 입장에서 사실상 매입원가로 기능할
가능성이 높다는 것이 **이번에 새로 연결한 근거 있는 해석**이지만,
API가 이 필드를 문자 그대로 "공급가"라고 명명하지 않았고, 실제 발주
시점의 최종 청구액이 `option_price` 그대로인지 `disc_price`로 조정
되는지는 여전히 **확정되지 않았다** — 그래서 "공급가"라는 표현 대신
"매입원가로 추정되는 값"으로 구분해서 쓴다.

### 3-2. 상품 기본가·옵션 추가금·옵션별 최종 단가·배송비·조건부 추가비용

`GET seller/product/{code}` 응답 스키마를 전부 대조한 결과, **최상위
`result`에 별도의 "상품 기본가" 필드가 없다** — 가격 정보는 오직
`options[]` 배열 안에만 있고, 옵션마다 완전히 독립된 최종 단가
(`option_price`)를 갖는다. 즉 이 상품(과 이 API 구조)에는 "기본가 +
옵션 추가금" 모델이 존재하지 않는다 — **옵션별 절대 단가**만 있다.

|---|---|---|
| 상품 기본가 | 해당 없음(필드 자체가 없음) | 스키마에 없다는 것을 확인, 추측하지 않음 |
| 옵션별 최종 단가 | 아래 3-4 표 | `option_price` 그대로, 옵션마다 독립 |
| 배송비(기본) | 3,000원 | 실제 응답(19차), `extends_info.send_price` |
| 배송비(제주, 조건부 추가) | 6,000원 | 실제 응답(19차), `extends_info.jeju_send_price` — 기본과 합산인지 대체인지는 API 필드만으로 확정 불가 |
| 배송비(도서산간, 조건부 추가) | 8,000원 | 실제 응답(19차), `extends_info.etc_send_price` — 위와 동일 |

| 반품비(조건부) | 왕복 6,000원(제주 10,000/도서산간 16,000) | 공개 화면 기준(2026-09-20 조사) — API의 `return_comment` 원문은 이번 응답에서 캡처하지 못함(아래 3-3) |

## ⑥ 판매가 제안

### 6-1. 기존 마진·비용 기준 확인 결과

`purchase_task_policy_settings`(company_id=1)를 재확인한 결과
`min_net_profit=0`, `min_margin_rate=0`(둘 다 미설정 기본값) —
**확정된 목표 마진율·최소 순이익 정책이 없다.** 참고할 수 있는
유일한 과거 값은 `PurchaseOrderApproval#1`의 스냅샷(2026-09-14,
만료·재사용 금지)뿐이며, 그 안의 `margin_rate_snapshot≈35.5%`도
정책이 아니라 그 시점 한 번의 계산 결과다. `PurchaseTask#1`의
`coupang_sale_amount=15,000`/`coupang_fee_amount=1,620`(수수료율
약 10.8%)도 이 매입 작업이 처음 만들어진 계기가 된 **원래 쿠팡 주문
건의 관측값**일 뿐, 이 카테고리의 확정 수수료율이 아니다(D3 문서의
"쿠팡 수수료율 미조사"가 여전히 유효).

### 6-2. 계산식과 가정(전부 명시, 확정 아님)

```
판매가(P) = 원가(C) / (1 - 목표마진율(m) - 채널수수료율(f))
원가(C) = 옵션 단가(§3-4) + 기본 배송비(3,000원)
```

**가정(예시 계산용, 사용자 확정 전까지 유효하지 않음)**: 목표마진율
`m = 30%`(원 대비 가산율이 아니라 판매가 대비 마진율 — 참고용 관측
`35.5%`보다 보수적으로 낮춰 예시함), 채널수수료율 `f = 10.8%`(위 관측
값, 이 카테고리 확정 아님).

| 옵션 | 원가(매입원가+배송비, 원) | 예시 판매가(원, 반올림) |
|---|---|---|
| 샴푸 200ml 본품 | 7,150+3,000=10,150 | 10,150/(1-0.30-0.108) ≈ **17,145** |
| 샴푸 500ml 리필 | 11,000+3,000=14,000 | 14,000/0.592 ≈ **23,649** |
| 바디워시 200ml 본품 | 5,050+3,000=8,050 | 8,050/0.592 ≈ **13,598** |
| 바디워시 500ml 리필 | 7,850+3,000=10,850 | 10,850/0.592 ≈ **18,328** |

세금·반품비·광고비는 위 계산에 포함하지 않았다(확정 비용이 아니므로
숨기거나 순이익에 반영하지 않음) — 반품비는 발생 시 왕복 6,000원
(제주 10,000/도서산간 16,000)이 별도로 추가된다는 사실만 남긴다.
**이 표는 사용자가 실제 목표 마진율·확인된 쿠팡 수수료율을 정하면
그대로 재계산 가능한 제안일 뿐, 원본 어디에도 저장하지 않았다** —
온채널·쿠팡 원본 가격 설정도 변경하지 않았다.
