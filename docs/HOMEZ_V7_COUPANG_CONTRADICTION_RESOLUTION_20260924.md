## ④ 21차 검증 범위 재정리 — "파일 2개"가 아니라 실제 소비 경로로 확인

21차가 추가한 필드(옵션 레벨 `disc_price`/`recom_cus_price`, 상품
레벨 `status`/`return_policy_detail`/`image_url`/`tax_exempt`/
`minor_sale_prohibited`/`notice_info_raw`)를 실제로 **읽는 코드가
`app/` 전체에 있는지 정밀 검색**했다(단순히 "파일 2개만 고쳤으니
안전하다"고 주장하지 않고 직접 증명):

```
grep '\.disc_price|\.recom_cus_price|\.discount_price\b|
     \.recommended_customer_price|\.return_policy_detail|
     \.tax_exempt\b|\.minor_sale_prohibited|\.notice_info_raw' app/
→ 매치 6줄 전부 app/domains/purchase_task/channel_adapter.py 자기 자신
  (21차가 직접 작성한 대입문) — 그 외 소비처 0곳
```

추가로 `ProductAttributeMatchService.supplier_values_from_channel_lookup()`
(속성비교에 `ProductLookupResult`를 연결하는 유일한 변환 함수)의
실제 코드를 다시 읽어 `result.title`과 6개 `ChannelAttributeValue`
필드(제조사/원산지/모델명/포장수량/규격/인증정보)만 읽는다는 것을
재확인했다 — **21차가 추가한 필드는 이 함수가 전혀 건드리지 않는다.**
`asdict(...)`나 다른 직렬화 호출로 이 두 dataclass를 통째로 바깥에
노출하는 코드도 없다(grep 0건).

**결론**: 21차 변경의 실제 영향 범위는 "onchannel_client.py의
`get_product()` 파싱 결과"와 "channel_adapter.py의 `lookup_product()`
반환값"으로 **완전히 닫혀 있다** — 이 두 지점 밖으로 새는 경로가
없다. 91건(신규 8건이 정확히 이 두 지점을 각각 정상/누락/null/
잘못된 타입으로 덮음, 기존 83건이 회귀)은 **이 변경의 실제 영향
범위 전체와 정확히 일치한다** — 추가 집중 테스트도, 전체 회귀
확대도 필요하지 않다고 결론짓는다(공용 계약·직렬화·가격 해석·
속성비교 경로 전부 grep으로 직접 확인, 추측이 아님).

**중단된 21차 전체 회귀(`unittest discover`)**: 여전히 **결과
미확정**으로 유지한다 — 21차 문서에 이미 정직하게 기록했고, 위
grep 증거로 볼 때 재실행이 필요하다고 판단하지 않는다. **가드 로그의
차단 이벤트 0건은 "이번 조사에서 주입한 fake 경로가 실제로 실행됐고
그 과정에서 가드가 아무것도 막지 않았다"는 뜻일 뿐, 그 자체가
"모든 실 자원에 전혀 접촉하지 않았다"는 절대 증명은 아니다** — 가드가
포괄하지 못하는 경로가 이론상 있을 수 있음을 인정하고 표현을
정정한다.
