| 매입원가(추정 근거) | `option_price` = 5,050원 | **확인됨**(API 원문, 3회 관측 일치) — "공급가"라는 명칭 필드는 없고 seller=HOMEZ 역할 해석에 근거한 추정임은 20차와 동일 |
| 기본 배송비 | 3,000원 | 확인됨(API 원문) |
| `disc_price`(최종 준수가) 6,500원 | **원가 계산에 사용하지 않음** | 의미 미확인 — 위 §A 신규 관측대로 "할인 원가"가 아니라 "최저 판매가 기준"일 가능성이 더 높다고 판단해, 할인된 원가로 취급하지 않는다(할인 적용조건 미확인 상태에서 원가를 낮춰 잡지 않는다는 원칙 그대로) |
| 목표마진율(`m`) | 30%(예시 가정) | **미확정** — `purchase_task_policy_settings`는 여전히 0/0(정책 없음), 20~22차와 동일 |
| 채널수수료율(`f`) | 10.8%(예시 가정) | **미확정** — `PurchaseTask#1`의 과거 관측값일 뿐 이 카테고리 확정 수수료율 아님 |

### 예시 판매가(옵션 3945580 한정, 확정 아님)

```
원가(추정) = 5,050 + 3,000(배송비) = 8,050원
예시 판매가 = 8,050 / (1 - 0.30 - 0.108) = 8,050 / 0.592 ≈ 13,598원
```

**참고 대조(확정 아님)**: `disc_price`(6,500원)가 만약 최저 판매가
기준이라는 추정이 맞다면, 위 예시 판매가(13,598원)는 이미 그 기준을
크게 상회해 문제가 되지 않는다 — 다만 이는 아직 확인되지 않은
가정에 대한 참고일 뿐, 이 계산 자체가 확정 판매가라는 뜻은 아니다.
세금·반품비·광고비는 포함하지 않았다(반품 발생 시 왕복 6,000원 별도).
원본 온채널·쿠팡 가격 설정은 변경하지 않았다.

### NAME 차이 — 범위 재확인(확대 해석 금지)

22차 결론(HOMEZ 후보명 = 옵션 3945580 표시명과 정확히 일치, 콤보
리스팅 중 하나를 대표) 그대로 유지한다. **이 일치는 "이름"에만
해당한다** — 구성(포장 단위)·용량이 완전히 동일하다는 근거로
확대하지 않는다: 구성수량은 여전히 추정값이고(§B 문의 대기), 용량은
200ml로 이름·가격 응답 양쪽에서 일관되나 별도 공식 "용량" 필드로
확정된 것은 아니다(`gosi_info.prd_weight`가 4옵션을 한꺼번에 나열할
뿐 옵션별로 분리돼 있지 않음).

### 속성비교 `BLOCKED` — 근거 있는 해결 제안(원본 미반영)

`resolve_run()`을 실행하지 않았다. 대신 이번에 새로 확보한 근거를
기준으로 사람이 검토할 제안값만 아래에 남긴다:

| 필드 | 제안값 | 근거 | 신뢰도 |
|---|---|---|---|
| MANUFACTURER | 유레카코스 | `gosi_info.make_import` 원문("화장품 제조업자 및 화장품 책임판매업자") | 상(원문에 "제조업자" 명시 포함) |
| ORIGIN_COUNTRY | 대한민국 | `gosi_info.make_con` 원문 | 상 |
| NAME | (사업 판단 필요, 제안 보류) | 옵션 3945580 표시명과 일치하나 상품 레벨 제목("샴푸/바디워시")과는 다름 | 사람 판단 필요 — 제안 보류 유지 |
| OPTIONS/QUANTITY/SIZE | 여전히 근거 부족(구성수량 미확정) | §B 회신 대기 | 하 — 제안 보류 |

MANUFACTURER·ORIGIN_COUNTRY는 이번에 신뢰도가 높아졌지만, "근거
있는 해결 제안만 작성하고 원본 해제는 하지 않는다"는 지시에 따라
`resolve_run()` 실행은 별도 승인 대상으로 남긴다.

## ⑤ 실행 관리

- A와 B는 서로 독립적으로 각 1회씩만 실행했다(중복 호출·중복 발송 없음).
- 문의 회신을 기다리는 동안 진행 가능한 작업(등록 초안·가격 계산)을
  이번 라운드 안에서 함께 완료했다(§③·§④).
- 이번 라운드는 코드 변경이 없어 전체 회귀를 실행하지 않았다(22차의
  "코드 변경 없으면 회귀 불필요" 판단 기준 재사용).
- 실제 외부 호출: 온채널 GET 1회(§A) + 이메일 발송 1회(§B) = 총 2건.
  로컬 DB 변경 범위: `purchase_channel_connections#4`(verified_at 등
  갱신) + `product_attribute_comparison_runs`/`items`(신규 run#2 및
  8개 항목 생성) — 그 외 테이블은 변경 없음(재확인함).
- 두 호출 모두 결과가 명확했다(A: 성공 응답 파싱 완료, B: 정상 발송
  응답 수신) — 실패나 불명확한 결과가 없어 재실행 여부를 판단할
  상황 자체가 발생하지 않았다.

## Git

이번 라운드가 만든 파일은 이 문서 1개와 `docs/HOMEZ_PROJECT_STATE.md`
갱신뿐이다(코드 변경 없음). 조사용 스크립트·응답 JSON은 프로젝트
디렉터리가 아닌 세션 스크래치 디렉터리에만 남겨 Git에 포함하지
않았다. 계정 아이디는 이 문서 전체에서 `sin9**`로 마스킹해 표기했다
(실제 발송한 메일 본문에는 온채널이 계정을 식별할 수 있도록 평문으로
포함했으나, 그것과 이 기록 문서는 별개다 — 비밀번호·API 키·고객
개인정보·원문 로그는 전혀 포함하지 않았다).
자신이 시작한 임시 작업(스크립트 실행)은 완료 후 별도 프로세스를
남기지 않았다(`python.exe` 0개로 종료 확인).
