**두 값이 완전히 일치한다 — 가이드 5편 제작 전체 기간 동안 실제
운영 DB에 대한 쓰기가 단 한 번도 없었다.** 파일 크기(1,327,104
bytes)와 수정 시각도 이 세션에서 새로 변경된 흔적이 없다. 이 작업
전체는 별도 임시 SQLite 파일(`guide_demo.db`, 스크래치패드 디렉터리)
에서만 이루어졌다.

## 2. 민감정보 노출 정적 검사

### 2-1. 문서 텍스트 검사

`docs/guides/` 전체에서 데모 비밀번호 리터럴(`DemoGuide2026!`)을
검색한 결과 **0건** — 데모 계정 비밀번호가 어떤 문서에도 텍스트로
남지 않았다(스크래치패드 스크립트에만 존재하며, 스크래치패드는
저장소 밖 임시 작업 디렉터리다).

가상 데모 이메일 도메인(`homez-guide-demo.com`)은 가이드 2 관련
문서 3곳에 의도적으로 언급되어 있다 — 실제 이메일이 아니라 이 가이드
전용으로 만든 가상 도메인임을 밝히는 설명 목적이며, 실제 개인정보가
아니다.

### 2-2. 스크린샷 이미지 검사 (수동 시각 검토, 25장 전수)

- 초대 코드 화면(`04_invitations_and_requests.png`) — 캡처 시점에
  "발급된 초대 코드가 없습니다" 상태였으므로 실제 코드 값 자체가
  노출되지 않았다. (코드가 실제로 발급된 상태를 캡처하지 않은 것은
  의도적 선택이었다.)
- 복구 코드 화면(`02_account_security_full.png`) — 복구 코드
  생성/공개 영역은 캡처되지 않았다(코드 생성 버튼만 보이고, 실제
  생성 실행은 하지 않음).
- 판매채널 연동 화면(`01_store_connection.png`) — Credential
  입력 필드는 비어 있는 상태로만 캡처, 실제 값 입력 없음.
- 로그인/오류 화면 — 비밀번호 입력창은 항상 빈 상태 또는 마스킹된
  점(●) 문자만 표시(브라우저 기본 password input 동작).
- 사용자 관리 표(`04_invitations_and_requests.png`) — 이메일은 전부
  `*.homez-guide-demo.com` 가상 도메인, 실명 없음(전부 "데모
  매니저" 등 역할 기반 표시 이름).
- CDP 기반 캡처 방식 특성상 브라우저 주소창·OS 작업 표시줄·알림
  영역이 스크린샷에 전혀 포함되지 않는다(뷰포트 콘텐츠만 캡처) —
  개인 폴더 경로 노출 위험이 구조적으로 없다.

**결론: 25장의 스크린샷 중 실제 비밀/토큰/코드 값이 노출된 것은
0건이다.**

### 2-3. 스토리보드/자막 검사

모든 스토리보드 문서에 "초대 코드/복구 코드는 모자이크 처리한다"는
제작 규칙을 명시했다(가이드 2, 5 스토리보드). 실제 영상이 아직
제작되지 않았으므로 이 규칙은 향후 실제 녹화 시 반드시 지켜야 할
사전 요구사항으로 문서화된 상태다.

## 3. 데모 환경 격리 확인

- 데모 서버는 `DATABASE_URL`을 임시 파일로 강제 지정한 뒤에만
  `app.main`을 import하도록 작성되었다(`guide_demo_seed_and_launch.py`).
- 데모 회사/계정/상품은 전부 가상(`가상 홈즈 데모 상점`, `(가상 데모
  상품) 접이식 미니 선풍기` 등 명시적 라벨 포함).
- 실제 쿠팡/네이버 API, 실제 AI 이미지 생성 API, 실제 이메일/SMS
  발송은 이 작업 전체에서 단 한 번도 호출되지 않았다.
